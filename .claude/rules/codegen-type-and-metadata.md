# Codegen: Type System and Metadata

### Type registry cross-check + alias resolution before lookup; new primitives wired into every reflection site

User-name registries (`record_types_`, `enum_types_`, `generic_enum_templates_`, `type_aliases_`) share one user-facing namespace. Every `emitStmt(<Decl>Stmt &)` must reject same-kind duplicates AND call `rejectIfTypeNameTakenByOtherKind()` for cross-kind collisions. `union_type_info_` is an anonymous cache (key = flattened type string), NOT a user-name registry. Always route a user-supplied name through `resolveTypeAlias()` before registry lookup or string equality (`"MyStr" == "str"` false-negative breaks `emitWeakUpgrade` header offset and `validateTypeBounds` alias bound check); preserve the user's original in `codegenError` messages. `weakInnerTypeName` only strips `"weak "` — alias-resolve before comparing inner to `"str"`. New primitives must be wired into `reverseResolveType`, `inferExprType` / `inferExprTypeName`, `inferTypeArgs`, `resolveType`, format strings, `low_level_type_name`, `wrapInAny` / `unwrapFromAny` slot tag tables.

### Canonicalization that may collapse type category must be guarded at every call site

Any normalization step that may change a type's category (union → scalar, variadic → single, tuple → element, alias → target) must add an explicit early-return for the collapsed case. `flattenUnionWithAliases("A | int")` where `type A = int` collapses to `"int"`; downstream `wrapInUnion` indexes `union_type_info_` by the original category and dereferences `end()`. Audit every caller before merging.

### `propagateTypeMeta` is single-value; composites decompose at the caller; tuple sigs use `source_type_name` as boundary channel

`propagateTypeMeta(name, val)` rebuilds `TypeMeta::*` slots on a single SSA value. Tuples (`(T1, T2, …)`) and future composites split at the caller via `splitTypeArgs` (strip outer parens, recurse per element); do NOT add a `tuple_elem_type_names: vector<string>` slot. For `Option<T>`, accept both `Option<T>` prefix and `T?` suffix (`OptionalType::toString()` emits the suffix form). When a tuple is loaded from `List<(K, V)>`, stamp `getOrCreateMeta(val).source_type_name = "(K, V)"`; the FieldAccessExpr numeric-index arm reads it, calls `splitTupleSig`, propagates the matching component name onto the extracted field. `source_type_name` is the lossless channel for type names that `propagateTypeMeta` cannot carry (also used by `Result<T, E>` / `Option<T>` precedent). **TupleExpr literal codegen must also stamp `source_type_name` (`emitExprVariant(TupleExpr)` in `codegen_expr_literal.cpp`)**: anonymous LLVM `StructType` collapses str / List / Map / closure / etc. to `ptr`, so any downstream consumer that needs to distinguish per-element types (e.g. `verifyCalledWith` recording-side `(int, str)` discrimination via `mockArgEqual` kind=10 in #1706) must read `source_type_name` rather than reverse-resolving the LLVM struct. Build the sig from element types/values (`i64Ty_` → `"int"`, `f64Ty_` → `"float"`, `i1`/`i8` → `"bool"`, `ptr + isStringValue` → `"str"`, else `buildTypeNameFromMeta`); stamp only when every element name is recoverable.

### Metadata rebuilds: every load / extract / PHI / branch-merge needs explicit propagation; same-element helpers pair `setTypeMeta` with `propagateMeta`

`ValueMetadata` is keyed by `llvm::Value*`. `CreateLoad(elemTy, GEP(data, i))`, `CreateExtractValue(opt/result, idx)`, BinOp results, and PHI-merged values are fresh SSA with no metadata; helpers that dispatch on metadata (`getListElementType`, `isStringValue`, `valueToString`, compound-op type dispatch) silently misclassify. Snapshot the inner type name from outer container metadata (`buildTypeNameFromMeta`) into a local `std::string` BEFORE calling `propagateTypeMeta` (the helper may rehash and invalidate `getMeta` results). Guard with `!innerName.empty() && innerName != "str"`. Sites needing this: `valueToString` element loops, ADT field-load (must go through per-type `getOrCreateADTToStringFn` cached BEFORE body emission, else codegen-time recursion on self-referential ADTs), compound-op loaded slots, outer `emitResultBranch` PHIs (capture Ok-incoming + `propagateMeta(okIncoming, mergedResult)` after the outer branch), `Option<Coll>` / `Result<Coll, E>` / `Result<_, Coll>` extracted inner. Same-element-type collection helpers (`slice`, `take`, `appended`, `distinct`, `filter`, `sort`, `merge`, set ops) call BOTH `setTypeMeta(TypeMeta::ListElem, newHeader, elemTy)` AND `propagateMeta(src, newHeader)` (rehash-safe; copies source-level names + `*_fn_type_info` + `nested_list_elem` + resource kinds). Element-changing helpers (`flatten`, `enumerate`, `zip`, `map`) construct `list_elem_type_name = "(T1, T2)"` manually.

### `wrapInUnion` disambiguates same-LLVM-type variants by metadata, not LLVM type equality

Under opaque pointers, `List<int>` / `Map` / `Set` / `str` / closure all resolve to `ptr`. Resolve in three passes: (1) reconstruct full source-level name via `buildTypeNameFromMeta(val)` and exact-match against `componentNames`; (2) coarse kind match via `isListTypeName` / `isMapTypeName` / `isSetTypeName` / `isFunctionTypeName` against metadata fields; (3) LLVM-type equality fallback. Picking the first LLVM-matching variant produces `Map` wrapped with tag=0 (List) and corrupts dispatch.

### Numeric coercion: `/` always float, `//` / `%` integer-error-on-zero, narrowing via `emitCheckedFPToInt`, mix-check uses "int" sentinel

`/` always returns `float` and follows IEEE 754 (zero divisor → ±inf, `0/0` → NaN); never add an integer zero-division guard. `//` and `%` (and low-level native-width `/` / `%`) are integer and error on zero. Float printing uses `std::to_chars` overload 3 (shortest round-trip), appends `".0"` when no decimal point/exponent and not `nan`/`inf`. Implicit `int↔float` coercion is annotation-driven and limited to assignment-like sites (var decl, reassign, compound assign, return) — NOT function args or if-expr branch unification. Gate with `!isLowLevelTypeName(typeName)`; low-level types (`i64` / `f32` / etc.) still require explicit `as` casts. Never call `CreateFPToSI` / `CreateFPToUI` directly — use `emitCheckedFPToInt(val, targetTy, typeName, bbPrefix, siteLabel)` which inserts a NaN / ±inf / range guard before narrowing (LLVM `fptosi` returns poison on those). Signed boundary is `[−2^(W-1), 2^(W-1))`; do NOT use symmetric `fabs(x) >= 2^(W-1)` which spuriously rejects `INT64_MIN`. `low_level_type_name` mix-check between operands must map empty → `"int"` sentinel before comparing — else `1 + getFromMap(m, k)` silently mixes int with `1i64`.

### Diagnose type / control-flow mismatches at the frontend, never at LLVM verify

Check type / control-flow invariants in C++ and call `codegenError(...)` BEFORE emitting invalid IR. Smells: `ConstantInt::get(v->getType(), ...)` without an `isIntegerTy()` guard (produced cryptic `icmp ne ptr, i0 0`); terminator-emitting calls (`CreateUnreachable` / `CreateRet` / `CreateBr`) not followed by a new block + `SetInsertPoint` (produced "Terminator found in middle of basic block"); runtime-call arg-type mismatches without `isJsonValue` ptr check. Never let LLVM verification be the user-visible error surface.

### List/Set literal stamps for enum / Result / Option / pointer-backed named types; Set mirrors List denylist

`emitExprVariant(ListExpr)` runs `inferCollectionTypeName` only inside `if (elemTy == ptrTy_)`. Enum (i64), ADT (struct), `Result<T, E>` (struct), `Option<T>` (struct) elements are non-pointer — stamp `list_elem_type_name` explicitly outside the ptr guard. For `Result` / `Option`, recover inner via `buildTypeNameFromMeta(vals[0])` (reads the metadata `propagateMeta` attached at `buildOkValue` / `buildSomeValue`); fall back to `reverseResolveTypeName(innerTy)` for primitives. For `List<T>` annotations, preserve every non-primitive inner name except `str` (which keeps the `list_elem_is_str` side-channel) — denylist primitives (`int` / `float` / `bool`); allow named pointer-backed types like `JsonValue` and stdlib resources so `xs[i]` rebuilds metadata. `Set<X>` annotation propagation must mirror this denylist; the single-var for-loop path is the canonical Set-first / List-fallback template, multi-var must use the same `headerTy` switch (`setHeaderTy_` vs `listHeaderTy_`).

### `inferCollectionTypeName` List branch prefers stored `list_elem_type_name` over lossy `reverseResolveTypeName`

`reverseResolveTypeName` is lossy: `ptrTy_` → `"str"` (so `List<List<int>>` middle list with stored `"List<int>"` becomes `"List<str>"`), unnamed `StructType` → fall-through to `"any"` (so `List<List<(int,int)>>` becomes `"List<any>"`). Check `meta->list_elem_type_name` BEFORE falling back; return `""` for unnamed `StructType` (tuples) so callers derive the name from the source annotation; do NOT return `""` for `ptrTy_` unconditionally (plain `List<str>` sets no `list_elem_type_name` so returning empty would break nested-list display).

### Function / lambda return inference: structural unification, lockstep helpers, declared param type NAMES, dynamic metadata in dedicated slots

Generic function inference must walk `TypeNode` structurally (`BasicType` / `GenericType` / `TupleType` / `FnType` / `OptionalType`) and unify each variable against `inferExprTypeName`'s shaped string — string-matching `toString()` against the bare type-param set silently produces no binding for `List<T>`/etc. `inferReturnType` (returns `llvm::Type*`) and `inferReturnTypeName` (returns shaped Ry name) must be maintained in lockstep — block-bodied lambdas must populate `returnTypeName` in addition to the LLVM type (else `propagateTypeMeta` gates on `!returnTypeName.empty()` and silently drops collection metadata). The same populate rule applies to **bare fn-reference paths** (`VariableExpr` resolving to an `OverloadEntry`): every `FnTypeInfo` synthesized from `entry` must assign `info.returnTypeName = entry.returnTypeName;` alongside `paramTypes` / `paramTypeNames` / `returnType`. Discovered in #1715 — `verifyCalledWith`'s structural signature compare reads `FnTypeInfo::returnTypeName`; an empty string compares unequal to any declared return type and would false-reject every bare fn-ref verify call. `inferExprTypeName(VariableExpr)` must consult alloca metadata FIRST via `getTypeMeta(TypeMeta::ListElem|MapKey|MapValue|SetElem, alloca)`; fall back to `reverseResolveTypeName(getAllocatedType())` only for structs / primitives (NOT the alloca's pointer type, which collapses to `"str"`). Lambda return-name inference must build a `paramTypeNameMap` (name → `resolveTypeAlias(p.type->toString())`) parallel to `paramTypeMap` and thread it through the same three helpers; consult `paramTypeNameMap` BEFORE the `inferExprType` fallback. Helper-function returns store dynamic metadata (`thread_result`, `task_result`, `fn_type_info`) in dedicated per-function slots, NOT by full-copying `ValueMetadata` onto `llvm::Function` — multi-return functions would overwrite single-valued slots and replay the wrong snapshot at every call site. Reject inconsistent dynamic metadata across return branches at compile time.

### Empty collection literal early-return paths must propagate closure / nested-type metadata

`codegen_stmt.cpp` has special early-return paths for empty literals (`a: Set<fn> = {}`, `a: List<fn> = []`) that allocate the header and return BEFORE the general `if (newTy == ptrTy_)` metadata-propagation block. Each such path must explicitly set `setTypeMeta(TypeMeta::SetElem / ListElem / MapKey / MapValue, ptr, elemTy)` AND `getOrCreateMeta(ptr).{set/list/map_*}_elem_type_name` (nested collection inner) AND `*_fn_type_info` (closure inner). Without these, downstream guards (e.g., `set_elem_fn_type_info` equality rejection in `codegen_expr.cpp`) silently don't fire and `Set<fn> == Set<fn>` compiles without error.

### `any` collection / record wrap dispatches by metadata, not LLVM type; element-type erased on wrap

**Source**: #1697 (2026-05-18, feat — collections); #1797 (2026-05-18, feat — records)
**Tags**: codegen, any, metadata-erasure, collection, record, type-dispatch, descriptor

**Context**: Issue #1697 extended `any` to hold `List` / `Map` / `Set` headers in `data[8]` (tags 5/6/7). #1797 added record support (tag 8) via heap-boxing; the box stores a descriptor word in front of the record struct so dynamic type identity survives `any` erasure across function boundaries. Under opaque pointers, `List<int>`, `Map<str,int>`, `Set<bool>`, plain `str`, and the record box's data ptr all collapse to `ptrTy_` — `getAnyTypeTag(val->getType())` cannot pick the right tag from the LLVM type alone, and the collection's element type / record's struct identity cannot be encoded in the 1-byte tag at all.

**Rule**: Treat the `any` slot as element-type-erased / struct-identity-erased. Wrap-side dispatch reads `getMeta(val)` (collections) or `findRecordInfoForType(val->getType())` (records) to pick the right tag; unwrap-side dispatch trusts the static type annotation (`targetTypeName`) supplied by the caller, but a **descriptor-pointer-equality check at unwrap time** is the dynamic safety net for records.

**How to apply**:
- Use `getAnyTypeTagForValue(val)` (NOT `getAnyTypeTag(val->getType())`) when the input may be a collection. The `ForValue` variant inspects `getMeta(val)->{list_elem,map_key,map_value,set_elem}` for `ptrTy_` inputs and returns `RyAnyTag::{List,Map,Set}`; only when no collection metadata is present does it fall back to type-based dispatch (which still returns `Str` for `ptrTy_`). The record arm of `wrapInAny` runs **before** this metadata check, so a struct-typed value is heap-boxed and tagged `Record=8` regardless of what `getMeta` would have inferred.
- `unwrapFromAny(anyVal, targetTy, targetTypeName)` requires the source-level target type name when `targetTy == ptrTy_`. It calls `resolveTypeAlias(targetTypeName)` and probes `isListTypeName` / `isMapTypeName` / `isSetTypeName` to pick the expected tag; empty / "str" / non-collection names keep the legacy `Str` tag behavior. **When `targetTy` is a `StructType` and `findRecordInfoForType(targetTy)` succeeds**, a parallel branch routes through a **runtime descriptor chain walk**: load the descriptor pointer from the box at offset +0, call `__ry_record_is_subtype_desc(actualDesc, expectedDesc)` which walks `RyRecordDescriptor::parent_desc` (returns 1 when `expectedDesc` is `actualDesc` itself or any ancestor in the chain) (#1802). On chain match: GEP the record struct at +8 using the **target type's** struct layout (Parent struct is a prefix of Child by Ry's inheritance ABI; all Ry fields are `alignof ≤ 8` so the +8 offset is invariant across Parent/Child layouts) + field-wise retain via `emitRecordArcFieldsRetain(recordVal, ParentStructTy)` (touches only Parent fields; Child-only fields stay owned by the box dtor). On miss: trap via `emitRuntimeError`. Callers in `codegen_stmt.cpp` (var-decl, assign, reassign), `codegen_fn.cpp` (return), `codegen_lambda.cpp` (return), and `codegen_call_dispatch.cpp` (arg coercion) MUST thread the declared type name through — for records, use `findRecordTypeName(structTy)` when no caller-visible annotation exists. Without this, `let xs: List<int> = anyVal` would mismatch the runtime tag check against `Str=3`, or `let p: Point = anyVal` would skip descriptor verification entirely.
- `wrapInAny` allow-list now includes collections and records: the rejection is `isNonStrPointer(val) && !isCollection && !isRecord`, where `isCollection` is computed from container metadata and `isRecord` from `findRecordInfoForType`. Enums / fn-pointers / resources remain rejected. **Do NOT widen `canAnyHoldType(ty)`** — it still returns true only for `{i64, f64, i1, ptr}` and is used by sites that drive the static "can this fit in any?" question; collection AND record eligibility is dynamic-metadata-driven and lives in `wrapInAny` itself. Record dispatch at the call / return / decl sites is the *separate* `llvm::isa<StructType>(targetTy) && findRecordInfoForType(...)` branch, parallel to (not replacing) the `canAnyHoldType` branch.
- Element-type erasure is the user-visible spec, documented in `docs/reference/types.md`. For collections, `any == any` deep equality is best-effort (List uses 8-byte slot byte-equality, Map/Set fall back to pointer identity); `to_string` returns opaque markers (`<List>` / `<Map>` / `<Set>`); arithmetic / order comparisons surface "operator X not supported" at runtime. **For records**, the descriptor word recovers full type identity: `any == any` is exact field-wise deep equality (descriptor pointer compare + dispatch to per-type eq fn — distinct record types are always unequal); `to_string` reads the descriptor's `type_name` and emits `<TypeName>` (e.g. `<Point>` rather than a generic `<Record>`). **Cross-type unwrap** (`let p: Parent = anyHoldingChild`) is intentionally out of scope in v0.0.25 and traps at runtime — subtype coercion on the typed path is unchanged. The complementary ARC-side rule for retain / release lives in [[codegen-arc-cow]].

### Collection element-access any-widening; `Set<any>` needs `emitAnyBinaryOp`; post-hoc Result coercion

Every site reading / writing a collection element slot (Map / List / Set index-assign, `add`, `append!` / `appended`, `insert`, `in` / `not in`) applies the canonical 3-branch widening: `wrapInAny(val)` if `isAnyType(elemTy)`, `unwrapFromAny(val, elemTy)` if `isAnyType(val->getType()) && canAnyHoldType(elemTy)`, else `codegenError("type mismatch")`. `tryEmitSubtypeCoerce` runs first for List index-assign. `anyTy_` is `{i64 tag, [8 x i8] data}`; LLVM `icmp eq` rejects the array data — for `Set<any>` / `Map<any>` element comparison, replace `emitComparisonOp("==", ...)` with `emitAnyBinaryOp("==", ...)` (calls `__ry_any_eq`) and hoist scratch allocas OUT of any inline linear-scan loop. Result/Option type coercion is post-hoc in `emitVarDecl` (`coerceResultType`), NOT threaded into Ok/Err constructors. Compute `okNeedsRuntimeBranch` / `errNeedsRuntimeBranch` BEFORE the early bailout; bail only when both slots differ AND neither can be `anyTy_`-unwrapped. Both differ AND both can be unwrapped → emit a runtime disc branch (disc=1 → Ok, disc=0 → Err) PHI-merged. Single-slot mismatch: only accept when `tryGetStaticResultDisc(val, &staticDisc)` returns true (walks `InsertValueInst` chain, recurses into PHI incomings); runtime-disc sources (call results, loads, mixed Ok/Err PHI) must return `nullptr` else silent miscompile zero-fills the active payload. Placeholder types (`Result<Unit,E>` / `Result<i8,E>` / `Result<u8,E>` all lower to `{i1, i8, E}`) are NOT a safe signal — disc value is the only reliable discriminant. `buildOkValue` / `buildErrValue` / `buildSomeValue` call `tryRetainArcSource(inner)` internally when `inner->getType() == ptrTy_` (do not double-retain at callers).
