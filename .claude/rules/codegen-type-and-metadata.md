# Codegen: Type System and Metadata

### Type registry cross-check + alias resolution before lookup; new primitives wired into every reflection site

User-name registries (`record_types_`, `enum_types_`, `generic_enum_templates_`, `type_aliases_`) share one user-facing namespace. Every `emitStmt(<Decl>Stmt &)` must reject same-kind duplicates AND call `rejectIfTypeNameTakenByOtherKind()` for cross-kind collisions. `union_type_info_` is an anonymous cache (key = flattened type string), NOT a user-name registry. Always route a user-supplied name through `resolveTypeAlias()` before registry lookup or string equality (`"MyStr" == "str"` false-negative breaks `emitWeakUpgrade` header offset and `validateTypeBounds` alias bound check); preserve the user's original in `codegenError` messages. `weakInnerTypeName` only strips `"weak "` — alias-resolve before comparing inner to `"str"`. New primitives must be wired into `reverseResolveType`, `inferExprType` / `inferExprTypeName`, `inferTypeArgs`, `resolveType`, format strings, `low_level_type_name`, `wrapInAny` / `unwrapFromAny` slot tag tables.

### Canonicalization that may collapse type category must be guarded at every call site

Any normalization step that may change a type's category (union → scalar, variadic → single, tuple → element, alias → target) must add an explicit early-return for the collapsed case. `flattenUnionWithAliases("A | int")` where `type A = int` collapses to `"int"`; downstream `wrapInUnion` indexes `union_type_info_` by the original category and dereferences `end()`. Audit every caller before merging.

### `propagateTypeMeta` is single-value; composites decompose at the caller; tuple sigs use `source_type_name` as boundary channel

`propagateTypeMeta(name, val)` rebuilds `TypeMeta::*` slots on a single SSA value. Tuples (`(T1, T2, …)`) and future composites split at the caller via `splitTypeArgs` (strip outer parens, recurse per element); do NOT add a `tuple_elem_type_names: vector<string>` slot. For `Option<T>`, accept both `Option<T>` prefix and `T?` suffix (`OptionalType::toString()` emits the suffix form). When a tuple is loaded from `List<(K, V)>`, stamp `getOrCreateMeta(val).source_type_name = "(K, V)"`; the FieldAccessExpr numeric-index arm reads it, calls `splitTupleSig`, propagates the matching component name onto the extracted field. `source_type_name` is the lossless channel for type names that `propagateTypeMeta` cannot carry (also used by `Result<T, E>` / `Option<T>` precedent). **TupleExpr literal codegen must also stamp `source_type_name` (`emitExprVariant(TupleExpr)` in `codegen_expr_literal.cpp`)**: anonymous LLVM `StructType` collapses str / List / Map / closure / etc. to `ptr`, so any downstream consumer that needs to distinguish per-element types (e.g. `verifyCalledWith` recording-side `(int, str)` discrimination via `mockArgEqual` kind=10 in #1706) must read `source_type_name` rather than reverse-resolving the LLVM struct. Build the sig from element types/values (`i64Ty_` → `"int"`, `f64Ty_` → `"float"`, `i1`/`i8` → `"bool"`, `ptr + isStrLike` → `"str"`, else `buildTypeNameFromMeta`); stamp only when every element name is recoverable.

### Metadata rebuilds: every load / extract / PHI / branch-merge needs explicit propagation; same-element helpers pair `setTypeMeta` with `propagateMeta`

`ValueMetadata` is keyed by `llvm::Value*`. `CreateLoad(elemTy, GEP(data, i))`, `CreateExtractValue(opt/result, idx)`, BinOp results, and PHI-merged values are fresh SSA with no metadata; helpers that dispatch on metadata (`getListElementType`, `isStrLike`, `valueToString`, compound-op type dispatch) silently misclassify. Snapshot the inner type name from outer container metadata (`buildTypeNameFromMeta`) into a local `std::string` BEFORE calling `propagateTypeMeta` (the helper may rehash and invalidate `getMeta` results). Guard with `!innerName.empty() && innerName != "str"`. Sites needing this: `valueToString` element loops, ADT field-load (must go through per-type `getOrCreateADTToStringFn` cached BEFORE body emission, else codegen-time recursion on self-referential ADTs), compound-op loaded slots, outer `emitResultBranch` PHIs (capture Ok-incoming + `propagateMeta(okIncoming, mergedResult)` after the outer branch), `Option<Coll>` / `Result<Coll, E>` / `Result<_, Coll>` extracted inner. Same-element-type collection helpers (`slice`, `take`, `appended`, `distinct`, `filter`, `sort`, `merge`, set ops) call BOTH `setTypeMeta(TypeMeta::ListElem, newHeader, elemTy)` AND `propagateMeta(src, newHeader)` (rehash-safe; copies source-level names + `*_fn_type_info` + `nested_list_elem` + resource kinds). Element-changing helpers (`flatten`, `enumerate`, `zip`, `map`) construct `list_elem_type_name = "(T1, T2)"` manually.

**Higher-order combinator loops** (`filter` / `map` / `reduce` / `fold` / `any` / `all` / `tap` in `src/codegen_call_higher_order.cpp`) load each element via `CreateLoad(elemTy, GEP(data, i), ...)`; the resulting SSA carries no metadata. Snapshot `list_elem_type_name` from the source container into a local `std::string` **before** the loop body and call `propagateTypeMeta(snap, elem)` immediately after each load, guarded by `elem->getType() == ptrTy_ && !snap.empty() && snap != "str"`. Order matters at `reduce_first` and any other seed-loading site that calls `wrapInAny`: the propagate must run **before** the conditional `wrapInAny`, otherwise `getAnyTypeTagForValue` falls back to type-based tag selection and a `ptrTy_` collection element is tagged `Str=3` (then `__ry_any_eq` and `unwrapFromAny` route through the wrong branch). The same discipline applies to `emitCollOp_get` Map arm — snapshot `map_value_type_name` and `map_value_fn_type_info` from the receiver, stamp on the loaded `get*_val` via a `stampLoadedMapValue` lambda symmetric to the List branch's `stampLoadedElem`, then call `propagateMeta(someVal, phi)` / `propagateMeta(foundVal, phi)` after the merge PHI so the inner type name survives the Option/value boundary. Do NOT call `propagateTypeMeta("str", elem)` to flag str container elements — the helper does not set `str_elem` and would re-introduce the `-24` / `-16` offset confusion described in [[codegen-arc-cow]]. The iterator path (`for elem in iter(xs):`) is tracked separately as a follow-up. (#2247)

### `wrapInUnion` disambiguates same-LLVM-type variants by metadata, not LLVM type equality

Under opaque pointers, `List<int>` / `Map` / `Set` / `str` / closure all resolve to `ptr`. Resolve in three passes: (1) reconstruct full source-level name via `buildTypeNameFromMeta(val)` and exact-match against `componentNames`; (2) coarse kind match via `isListTypeName` / `isMapTypeName` / `isSetTypeName` / `isFunctionTypeName` against metadata fields; (3) LLVM-type equality fallback. Picking the first LLVM-matching variant produces `Map` wrapped with tag=0 (List) and corrupts dispatch.

### Numeric coercion: `/` always float, `//` / `%` integer-error-on-zero, narrowing via `emitCheckedFPToInt`, mix-check uses "int" sentinel

`/` always returns `float` and follows IEEE 754 (zero divisor → ±inf, `0/0` → NaN); never add an integer zero-division guard. `//` and `%` (and low-level native-width `/` / `%`) are integer and error on zero. Float printing uses `std::to_chars` overload 3 (shortest round-trip), appends `".0"` when no decimal point/exponent and not `nan`/`inf`. Implicit `int↔float` coercion is annotation-driven and limited to assignment-like sites (var decl, reassign, compound assign, return) — NOT function args or if-expr branch unification. Gate with `!isLowLevelTypeName(typeName)`; low-level types (`i64` / `f32` / etc.) still require explicit `as` casts. Never call `CreateFPToSI` / `CreateFPToUI` directly — use `emitCheckedFPToInt(val, targetTy, typeName, bbPrefix, siteLabel)` which inserts a NaN / ±inf / range guard before narrowing (LLVM `fptosi` returns poison on those). Signed boundary is `[−2^(W-1), 2^(W-1))`; do NOT use symmetric `fabs(x) >= 2^(W-1)` which spuriously rejects `INT64_MIN`. `low_level_type_name` mix-check between operands must map empty → `"int"` sentinel before comparing — else `1 + getFromMap(m, k)` silently mixes int with `1i64`.

### Diagnose type / control-flow mismatches at the frontend, never at LLVM verify

Check type / control-flow invariants in C++ and call `codegenError(...)` BEFORE emitting invalid IR. Smells: `ConstantInt::get(v->getType(), ...)` without an `isIntegerTy()` guard (produced cryptic `icmp ne ptr, i0 0`); terminator-emitting calls (`CreateUnreachable` / `CreateRet` / `CreateBr`) not followed by a new block + `SetInsertPoint` (produced "Terminator found in middle of basic block"); runtime-call arg-type mismatches without a resource-kind ptr check (e.g. `findResourceKind(val)` for `TcpStream` / `Lock` / etc. argument validation). Never let LLVM verification be the user-visible error surface.

### List/Set literal stamps for enum / Result / Option / pointer-backed named types; Set mirrors List denylist

`emitExprVariant(ListExpr)` runs `inferCollectionTypeName` only inside `if (elemTy == ptrTy_)`. Enum (i64), ADT (struct), `Result<T, E>` (struct), `Option<T>` (struct) elements are non-pointer — stamp `list_elem_type_name` explicitly outside the ptr guard. For `Result` / `Option`, recover inner via `buildTypeNameFromMeta(vals[0])` (reads the metadata `propagateMeta` attached at `buildOkValue` / `buildSomeValue`); fall back to `reverseResolveTypeName(innerTy)` for primitives. For `List<T>` annotations, preserve every non-primitive inner name except `str` (which keeps the `list_elem_is_str` side-channel) — denylist primitives (`int` / `float` / `bool`); allow named pointer-backed types like stdlib resources (`TcpStream`, `Lock`, etc.) so `xs[i]` rebuilds metadata. `Set<X>` annotation propagation must mirror this denylist; the single-var for-loop path is the canonical Set-first / List-fallback template, multi-var must use the same `headerTy` switch (`setHeaderTy_` vs `listHeaderTy_`).

### `inferCollectionTypeName` List branch prefers stored `list_elem_type_name` over lossy `reverseResolveTypeName`

`reverseResolveTypeName` is lossy: `ptrTy_` → `"str"` (so `List<List<int>>` middle list with stored `"List<int>"` becomes `"List<str>"`), unnamed `StructType` → fall-through to `"any"` (so `List<List<(int,int)>>` becomes `"List<any>"`). Check `meta->list_elem_type_name` BEFORE falling back; return `""` for unnamed `StructType` (tuples) so callers derive the name from the source annotation; do NOT return `""` for `ptrTy_` unconditionally (plain `List<str>` sets no `list_elem_type_name` so returning empty would break nested-list display).

### Function / lambda return inference: structural unification, lockstep helpers, declared param type NAMES, dynamic metadata in dedicated slots

Generic function inference must walk `TypeNode` structurally (`BasicType` / `GenericType` / `TupleType` / `FnType` / `OptionalType`) and unify each variable against `inferExprTypeName`'s shaped string — string-matching `toString()` against the bare type-param set silently produces no binding for `List<T>`/etc. `inferReturnType` (returns `llvm::Type*`) and `inferReturnTypeName` (returns shaped Ry name) must be maintained in lockstep — block-bodied lambdas must populate `returnTypeName` in addition to the LLVM type (else `propagateTypeMeta` gates on `!returnTypeName.empty()` and silently drops collection metadata). The same populate rule applies to **bare fn-reference paths** (`VariableExpr` resolving to an `OverloadEntry`): every `FnTypeInfo` synthesized from `entry` must assign `info.returnTypeName = entry.returnTypeName;` alongside `paramTypes` / `paramTypeNames` / `returnType`. Discovered in #1715 — `verifyCalledWith`'s structural signature compare reads `FnTypeInfo::returnTypeName`; an empty string compares unequal to any declared return type and would false-reject every bare fn-ref verify call. `inferExprTypeName(VariableExpr)` must consult alloca metadata FIRST via `getTypeMeta(TypeMeta::ListElem|MapKey|MapValue|SetElem, alloca)`; fall back to `reverseResolveTypeName(getAllocatedType())` only for structs / primitives (NOT the alloca's pointer type, which collapses to `"str"`). Lambda return-name inference must build a `paramTypeNameMap` (name → `resolveTypeAlias(p.type->toString())`) parallel to `paramTypeMap` and thread it through the same three helpers; consult `paramTypeNameMap` BEFORE the `inferExprType` fallback. Helper-function returns store dynamic metadata (`thread_result`, `task_result`, `fn_type_info`) in dedicated per-function slots, NOT by full-copying `ValueMetadata` onto `llvm::Function` — multi-return functions would overwrite single-valued slots and replay the wrong snapshot at every call site. Reject inconsistent dynamic metadata across return branches at compile time.

### Empty collection literal early-return paths must propagate closure / nested-type metadata

`codegen_stmt.cpp` has special early-return paths for empty literals (`a: Set<fn> = {}`, `a: List<fn> = []`) that allocate the header and return BEFORE the general `if (newTy == ptrTy_)` metadata-propagation block. Each such path must explicitly set `setTypeMeta(TypeMeta::SetElem / ListElem / MapKey / MapValue, ptr, elemTy)` AND `getOrCreateMeta(ptr).{set/list/map_*}_elem_type_name` (nested collection inner) AND `*_fn_type_info` (closure inner). Without these, downstream guards (e.g., `set_elem_fn_type_info` equality rejection in `codegen_expr.cpp`) silently don't fire and `Set<fn> == Set<fn>` compiles without error.

### `any` collection / record / enum wrap dispatches by metadata, not LLVM type; element-type erased on wrap

**Source**: #1697 (2026-05-18, feat — collections); #1797 (2026-05-18, feat — records); #1798 (2026-05-19, feat — enums)
**Tags**: codegen, any, metadata-erasure, collection, record, enum, type-dispatch, descriptor

**Context**: Issue #1697 extended `any` to hold `List` / `Map` / `Set` headers in `data[8]` (tags 5/6/7). #1797 added record support (tag 8) via heap-boxing; the box stores a descriptor word in front of the record struct so dynamic type identity survives `any` erasure across function boundaries. #1798 added enum support (tag 9) via the same heap-box pattern — organic `enum` declarations and built-in `Option<T>` / `Result<T, E>` all flow through `Enum=9` (including simple enums whose payload is a bare `i64` discriminant, so the source-level enum identity survives the round trip rather than collapsing to `Int=0`). Under opaque pointers, `List<int>`, `Map<str,int>`, `Set<bool>`, plain `str`, and the record / enum boxes' data ptrs all collapse to `ptrTy_` — `getAnyTypeTag(val->getType())` cannot pick the right tag from the LLVM type alone, and the collection's element type / record's struct identity / enum's full generic parameterization cannot be encoded in the 1-byte tag at all.

**Rule**: Treat the `any` slot as element-type-erased / struct-identity-erased. Wrap-side dispatch reads `getMeta(val)` (collections), `findRecordInfoForType(val->getType())` (records), or `findEnumLikeTypeNameForBoxing(val)` (enums — order: organic ADT via `findAdtEnumName` → `Option<T>` / `Result<T, E>` via the `reverse_option_types_` / `reverse_result_types_` maps → simple enum via `meta->enum_value_type` for `i64` inputs) to pick the right tag; unwrap-side dispatch trusts the static type annotation (`targetTypeName`) supplied by the caller, but a **descriptor-pointer-equality check at unwrap time** is the dynamic safety net for records and enums.

**How to apply**:
- Use `getAnyTypeTagForValue(val)` (NOT `getAnyTypeTag(val->getType())`) when the input may be a collection. The `ForValue` variant inspects `getMeta(val)->{list_elem,map_key,map_value,set_elem}` for `ptrTy_` inputs and returns `RyAnyTag::{List,Map,Set}`; only when no collection metadata is present does it fall back to type-based dispatch (which still returns `Str` for `ptrTy_`). The record arm of `wrapInAny` runs **before** this metadata check, so a struct-typed value is heap-boxed and tagged `Record=8` regardless of what `getMeta` would have inferred.
- `unwrapFromAny(anyVal, targetTy, targetTypeName)` requires the source-level target type name when `targetTy == ptrTy_`. It calls `resolveTypeAlias(targetTypeName)` and probes `isListTypeName` / `isMapTypeName` / `isSetTypeName` to pick the expected tag; empty / "str" / non-collection names keep the legacy `Str` tag behavior. **When `targetTy` is a `StructType` and `findRecordInfoForType(targetTy)` succeeds**, a parallel branch routes through a **runtime descriptor chain walk**: load the descriptor pointer from the box at offset +0, call `__ry_record_is_subtype_desc(actualDesc, expectedDesc)` which walks `RyRecordDescriptor::parent_desc` (returns 1 when `expectedDesc` is `actualDesc` itself or any ancestor in the chain) (#1802). On chain match: GEP the record struct at +8 using the **target type's** struct layout (Parent struct is a prefix of Child by Ry's inheritance layout; all Ry fields are `alignof ≤ 8` so the +8 offset is invariant across Parent/Child layouts) + field-wise retain via `emitRecordArcFieldsRetain(recordVal, ParentStructTy)` (touches only Parent fields; Child-only fields stay owned by the box dtor). On miss: trap via `emitRuntimeError`. Callers in `codegen_stmt.cpp` (var-decl, assign, reassign), `codegen_fn.cpp` (return), `codegen_lambda.cpp` (return), and `codegen_call_dispatch.cpp` (arg coercion) MUST thread the declared type name through — for records, use `findRecordTypeName(structTy)` when no caller-visible annotation exists. Without this, `let xs: List<int> = anyVal` would mismatch the runtime tag check against `Str=3`, or `let p: Point = anyVal` would skip descriptor verification entirely.
- `wrapInAny` allow-list now includes collections, records, and enums: the rejection is `isNonStrPointer(val) && !isCollection && !isRecord && !isEnum`, where `isCollection` is computed from container metadata, `isRecord` from `findRecordInfoForType`, and `isEnum` from `findEnumLikeTypeNameForBoxing` returning a non-empty name. Fn-pointers and resources remain rejected. **Do NOT widen `canAnyHoldType(ty)`** — it still returns true only for `{i64, f64, i1, ptr}` and is used by sites that drive the static "can this fit in any?" question; collection / record / enum eligibility is dynamic-metadata-driven and lives in `wrapInAny` itself. Record and enum dispatch at the call / return / decl sites are *separate* StructType (or i64 for simple enum) branches parallel to (not replacing) the `canAnyHoldType` branch.
- Element-type erasure is the user-visible spec, documented in `docs/reference/types.md`. For collections, `any == any` deep equality is best-effort (List uses 8-byte slot byte-equality, Map/Set fall back to pointer identity); `to_string` returns opaque markers (`<List>` / `<Map>` / `<Set>`); arithmetic / order comparisons surface "operator X not supported" at runtime. **For records**, the descriptor word recovers full type identity: `any == any` is exact field-wise deep equality (descriptor pointer compare + dispatch to per-type eq fn — distinct record types are always unequal); `to_string` reads the descriptor's `type_name` and emits `<TypeName>` (e.g. `<Point>` rather than a generic `<Record>`). **For enums**, the same descriptor pattern applies: `any == any` matches descriptor pointers first, then dispatches to a per-enum equality fn that switches on the discriminant and compares per-variant payloads; `to_string` emits `<TypeName>` (e.g. `<Color>`, `<Option<int>>`, `<Result<int, str>>`). **Cross-type unwrap** is out of scope for records (`let p: Parent = anyHoldingChild` traps at runtime in v0.0.25 — subtype coercion on the typed path is unchanged) and is **structurally absent for enums** (Ry enums have no inheritance, so the descriptor has no `parent_desc` chain to walk). The complementary ARC-side rule for retain / release lives in [[codegen-arc-cow]].

### `Option<T>` / `Result<T, E>` alloca decls must stamp `source_type_name` so wrapInAny recovers the full generic parameterization across LoadInst

**Source**: #1798 (2026-05-19, feat)
**Tags**: codegen, any, enum, option, result, source-type-name, generic, alloca, load, descriptor-cache-key

**Context**: When a `Result<T, E>` / `Option<T>` value is stored into an alloca and later loaded for `wrapInAny`, the loaded SSA value is a fresh struct (`{i1, T}` / `{i1, T, E}`) with no metadata. `findEnumLikeTypeNameForBoxing` cannot synthesize the full source-level name (`"Result<List<int>, str>"`) from the LLVM struct alone — under opaque pointers the ARC-managed inner slots collapse to `ptr`, and `reverseResolveTypeName(ptrTy_)` returns `"str"`. The fallback path then keyed the per-enum descriptor cache as `"Result<str, str>"`, while the unwrap site queried `"Result<List<int>, str>"`. Descriptor-pointer equality failed at runtime with `any enum type mismatch (expected Result<List<int>, str>, got a different enum type)` even though the same value had just been wrapped.

**Rule**: At every alloca decl site for `Option<T>` / `Result<T, E>` typed locals, stamp `getOrCreateMeta(ptr).source_type_name = <source-level annotation>` immediately after `propagateMeta(val, ptr)`. The complementary read-side helper inside `findEnumLikeTypeNameForBoxing` (a `resolveSourceTypeName` lambda) walks `LoadInst → getPointerOperand() → meta->source_type_name` to recover the full name across the load boundary. Without this, the descriptor cache keys diverge between wrap and unwrap sites and every Option/Result with an ARC-managed inner type fails to round-trip through `any`.

**How to apply**:
- Var-decl site (`emitVarDecl` in `src/codegen_stmt.cpp` after the `propagateMeta(val, ptr)` call for Option/Result): `if ((isOptionType(newTy) || isResultType(newTy)) && annot && !annot->empty()) getOrCreateMeta(ptr).source_type_name = *annot;`
- Read-side in `findEnumLikeTypeNameForBoxing` (`src/codegen_arc.cpp`): define a `resolveSourceTypeName` lambda that returns `getMeta(val)->source_type_name` if non-empty, else `getMeta(cast<LoadInst>(val).getPointerOperand())->source_type_name` if `val` is a `LoadInst`. Use it in both the Option<T> and Result<V, E> branches before the lossy `reverseResolveTypeName` fallback.
- Simple enums (i64 payload) use the analogous `meta->enum_value_type` stamp at the enum-variant-construction site, not `source_type_name` — the value type is what flows through the metadata chain naturally for i64-sized enums.
- This pattern generalizes: whenever a per-type descriptor cache is keyed by a source-level type name that must survive load/store, `source_type_name` is the lossless channel. Tuples and ADT enums use the same channel for the same reason (existing precedent: `(K, V)` from `items()` / `enumerate()`).

### Collection element-access any-widening; `Set<any>` needs `emitAnyBinaryOp`; post-hoc Result coercion

Every site reading / writing a collection element slot (Map / List / Set index-assign, `add`, `append!` / `appended`, `insert`, `in` / `not in`) applies the canonical 3-branch widening: `wrapInAny(val)` if `isAnyType(elemTy)`, `unwrapFromAny(val, elemTy)` if `isAnyType(val->getType()) && canAnyHoldType(elemTy)`, else `codegenError("type mismatch")`. `tryEmitSubtypeCoerce` runs first for List index-assign. `anyTy_` is `{i64 tag, [8 x i8] data}`; LLVM `icmp eq` rejects the array data — for `Set<any>` / `Map<any>` element comparison, replace `emitComparisonOp("==", ...)` with `emitAnyBinaryOp("==", ...)` (calls `__ry_any_eq`) and hoist scratch allocas OUT of any inline linear-scan loop. Result/Option type coercion is post-hoc in `emitVarDecl` (`coerceResultType`), NOT threaded into Ok/Err constructors. Compute `okNeedsRuntimeBranch` / `errNeedsRuntimeBranch` BEFORE the early bailout; bail only when both slots differ AND neither can be `anyTy_`-unwrapped. Both differ AND both can be unwrapped → emit a runtime disc branch (disc=1 → Ok, disc=0 → Err) PHI-merged. Single-slot mismatch: only accept when `tryGetStaticResultDisc(val, &staticDisc)` returns true (walks `InsertValueInst` chain, recurses into PHI incomings); runtime-disc sources (call results, loads, mixed Ok/Err PHI) must return `nullptr` else silent miscompile zero-fills the active payload. Placeholder types (`Result<Unit,E>` / `Result<i8,E>` / `Result<u8,E>` all lower to `{i1, i8, E}`) are NOT a safe signal — disc value is the only reliable discriminant. `buildOkValue` / `buildErrValue` / `buildSomeValue` call `tryRetainArcSource(inner)` internally when `inner->getType() == ptrTy_` (do not double-retain at callers).

**#1808 amendment**: `coerceResultType` accepts an optional third arg `const std::string &dstResTypeName = ""` carrying the destination's source-level Result type name (e.g. `"Result<MyEnum, str>"`, `"Result<Option<int>, str>"`). The Ok / Err slot path is extended with a parallel `canRuntimeUnwrapAsEnum(dstTy, dstTypeName)` predicate — true when `(dstTy == i64Ty_ && isSimpleEnumTypeName(dstTypeName))` OR `(dstTy is StructType && (isOptionType(st) || isResultType(st) || !findAdtEnumName(st).empty()))` — so the `okNeedsRuntimeBranch` / `errNeedsRuntimeBranch` flags fire for enum destinations too. **Do NOT widen `canAnyHoldType`** — it must stay primitive-only; the enum branch is dedicated and parallel, mirroring the per-site emitter pattern from #1797 / #1798. Slot type names are extracted from `dstResTypeName` directly via `CodeGen::splitTypeArgs` + `CodeGen::trimTypeNameSpaces` after stripping the `"Result<"` / `">"` envelope (no header change required — keeps the helper file-scope in `codegen_match.cpp`); empty / malformed → graceful degradation (enum-struct slot still opens the runtime branch via LLVM type alone; simple-enum i64 slot stays closed). All five call sites (`emitVarDecl`, function-local reassign, module-global reassign, two `mockReturnValueOnce` emitters) thread the type name. For reassign sites, use `getMeta(ptr)->source_type_name` directly — `buildTypeNameFromMeta` does NOT read `source_type_name` on Result allocas and would return empty. The static-disc-first path priority (try `tryGetStaticResultDisc` BEFORE the runtime-branch bailout) handles the common `Ok(any-holding-enum)` case where source `Result<any, Error>` mismatches target on both slots but only the active Ok slot needs to be enum-coercible (inactive Err slot is zero-fill).

### `any` → typed collection unwrap at `emitVarDecl` needs a `source_type_name` gate; `"any"` is ambiguous, not a concrete mismatch

**Source**: #1883 (2026-05-26, fix)
**Tags**: codegen, any, var-decl, source_type_name, typed-collection, json-load, segfault

**Context**: `json.load(text)` returns `Result<any, Error>` whose `Ok(v)` arm binds `v: any` with no collection element metadata — `propagateTypeMeta("any", varAlloca)` in `codegen_match.cpp` does not transfer `list_elem_type_name` / `map_key_type_name` etc. The `canAnyHoldType(annotTy)` cascade in `emitVarDecl` then routed `xs: List<str> = v` into `unwrapFromAny(val, ptrTy_, "List<str>")` without verifying that `v` actually held a `List<str>`. The `#1698` whitelist inside `unwrapFromAny` was gated on `fromGenericSubstitution` only, so literal annotations bypassed it. Result: `List<str>` / `List<float>` segfaulted (8-byte typed stride walked off the end of the 16-byte `RyAny` payload); `List<int>` silently corrupted (read `RyAny` tag bytes as payload). Same hazard for `Map<_, T>` / `Set<T>`.

**Rule**: At the `canAnyHoldType(annotTy) && annotTy == ptrTy_` branch in `emitVarDecl` (`src/codegen_stmt.cpp`), when the annotation resolves to a typed collection (`List<T>` / `Set<T>` / `Map<K, V>` where the element type is not `any`), gate the unwrap on a 3-stage `source_type_name` lookup (mirrors the `resolveSourceTypeName` lambda in `codegen_arc.cpp:1737-1746`):

1. `getMeta(val)->source_type_name`
2. `getMeta(LoadInst.getPointerOperand())->source_type_name`
3. `arc_any_managed_vars_[srcAlloca]` (the load-bearing stage for the legitimate roundtrip `xs(List<int>) → a: any → ys: List<int>` — `registerAnyManagedVar` stamps the source name on the alloca but `propagateTypeMeta("any")` is a no-op, so the getMeta side is empty)

Three outcomes:
- `sourceName == "any"`: **defer to runtime tag check** (treat as ambiguous, not as concrete mismatch). The motivating shipped case is a function whose return type is `any` (e.g. `fn identityAny(v: any) -> any: return v` → `ys: List<int> = identityAny(xs)`); the wrapped value MAY be the right collection at runtime, and rejecting it breaks `tests/spec/any.test.ry` `shouldPreserveListThroughAnyRoundtripInFn`.
- `sourceName.empty()` OR `resolveTypeAlias(sourceName) != resolvedColl`: `codegenError` with a `load[T]` hint (renamed from `loadAs[T]` in #1887). Empty is the `case Ok(v):` hazard; mismatch is `a: any = List<int>; ys: List<str> = a`.
- Otherwise (concrete match): forward to `unwrapFromAny` as before.

**Why a frontend gate and not a runtime check**: `ListHeader` layout (`include/ry/runtime/core/list.hpp:16-23`) has no stride / element-type field — the runtime has no way to detect the mismatch without an out-of-band side table. The metadata-channel gate is the only place we know the source-level type. `List<any>` / `Set<any>` / `Map<str, any>` annotations stay unconditional (payload stride matches destination, payload is `RyAny[N]`).

**Do NOT widen `canAnyHoldType(ty)`** to incorporate this check. The collection eligibility is dynamic-metadata-driven (per the rule in §57's "Do NOT widen `canAnyHoldType`" callout); the gate lives at the call site in `emitVarDecl`, parallel to the existing primitive-only `canAnyHoldType` branch.

**Scope and residual hazards**: The fix only covers the var-decl coercion path. Same hazard exists in (a) the reassignment paths (`xs = v` after `xs: List<str>` is declared — `codegen_stmt.cpp` lines ~1370, ~1664), (b) function argument / return coercion, and (c) function-boundary `any` round-trip with concrete-mismatched element strides (`fn → any → List<wrong>` — the `"any"` ambiguity gate intentionally lets the wrap through, then unwrapFromAny's runtime tag check can still pass for List vs List even when the element type differs because the tag is just `List`). The Case-C residual is the cost of keeping the shipped `identityAny`-style roundtrip working; future tightening would require either (a) a runtime element-type field in `ListHeader` (layout break) or (b) threading element metadata across function boundaries via `source_type_name` on the return value.

### `tryUnwrapFromAny` is the Result-returning sibling of `unwrapFromAny`; emitResultBranch loses metadata so callers re-stamp via propagateTypeMeta

**Source**: #1852 (2026-05-24, feat)
**Tags**: codegen, any, json, load, loadAs, result, propagateTypeMeta, error-message-prefix, recursive-unwrap

**Context**: `json.load[T](text)` (named `json.loadAs[T](text)` until #1887 renamed it) originally invoked the panic-version `unwrapFromAny` via the implicit conversion at `v: T = a` — every tag/descriptor mismatch (record missing field, list-of-record element wrong type, `Option<T>` with non-null inner mismatch) terminated the JIT with `_Exit(1)` instead of returning `Err(Error)`. #1852 introduced `tryUnwrapFromAny(anyVal, targetTy, targetTypeName) -> Result<T, Error>` as a parallel Result-returning sibling. The four typed targets (flat / nested record, `List<Record>` / `Map<str, Record>`, `Option<Record>`) flow through a recursive `tryUnwrapFromAny` call chain that prefixes each err message with `load<TargetType>: ...` so the user-visible message identifies the failure site (e.g. `load<Outer>: field 'inner': load<Inner>: field 'age' missing`). The error-message prefix was `loadAs<...>: ...` until #1887 flipped it to `load<...>: ...` to track the API rename.

**Rule**: Use the **sibling pattern** when a per-type unwrap helper needs to switch from panic to Result-based propagation: keep the panic version intact for sites that semantically cannot fail (assignment-time coercion, static-typed locals where the type checker guarantees the shape), and add a `tryUnwrapXxxFromAny` sibling that returns `Result<T, Error>` for sites that must propagate. Do NOT retrofit `unwrapFromAny` to take a "trap on mismatch" flag — `_Exit` paths and Result paths have structurally different error-message shapes (the trap version uses `emitRuntimeError`'s fprintf; the Result version uses a `cachedGlobalString` + `__ry_string_make_uninit` prefix-concat to build a heap string the user can pattern-match) and conflating them in one function obscures both.

**How to apply**:
- Sibling helpers go in `src/codegen_any.cpp` next to the panic versions. Public dispatcher (`tryUnwrapFromAny`) routes to `tryUnwrapRecordFromAny` / `tryUnwrapListFromAny` / `tryUnwrapMapFromAny` / `tryUnwrapOptionFromAny` by the same target-type predicates (`findRecordInfoForType`, `isListTypeName`, `isMapTypeName`, `isOptionType`) used by the panic dispatcher. For the structurally-simple cases (primitives, `List<any>`, `Map<str, any>`, single-tag check) `tryUnwrapFromAny` reuses `emitResultBranch(isErr, resTy, buildOk, buildErr)` from `codegen_call_dispatch.cpp` — but `emitResultBranch` builds the result via a PHI on two SSA values, which under opaque pointers **erases all `getMeta()` metadata**. The dispatcher in `src/codegen_call_json.cpp` (`emitJsonLoad`, named `emitJsonLoadAs` until #1887) re-stamps after the call: `cg.propagateTypeMeta("Result<" + typeArg + ", Error>", result);`. Without this re-stamp, `case load[List<Person>](text): Ok(xs):` reaches `xs` with empty `list_elem_type_name` and downstream `xs[0].name` field access fails to find the record metadata.
- Error message prefix is **per-helper-arm**, not threaded through one global helper. Each `tryUnwrapXxxFromAny` builds its own `"load<Label>: ..."` prefix where `Label = targetTypeName.empty() ? "?" : targetTypeName` (prefix was `loadAs<...>` until #1887 flipped it to `load<...>`), and when forwarding an inner err message prepends the outer prefix via the canonical runtime-string-concat pattern (`cachedGlobalString(prefix)` + `emitStringByteLen(innerMsg)` + `__ry_string_make_uninit(totalLen)` + two `getStdlibMemcpy()` calls + `emitArcRelease(emitStrGetHeaderFromData(innerMsg))` to release the inner). This builds a heap-allocated str whose nested wording (`load<Outer>: field 'inner': load<Inner>: field 'age' missing`) survives the Result PHI because `ptrTy_` slots are opaque to the PHI's metadata loss.
- For `Option<T>` specifically, the dispatch is 3-way (NOT 2-way like `emitResultBranch`): `tag == Unit → Ok(None)` / `tag != Unit → recurse via tryUnwrapFromAny(anyVal, innerTy) → inner Ok wrap in Some(...) → inner Err prepend "expected null or " prefix`. Build three independent BBs (`none`, `inner_ok`, `inner_err`) and merge with one 3-incoming PHI on `resTy`. The error wording `load<Option<X>>: expected null or load<X>: ...` deliberately satisfies the test's `toContain("null") + toContain("JSON object")` simultaneous assertion when the source is a primitive (e.g. `42` with `Option<Record>` target).
- `buildSomeValue(inner, optTy)` calls `tryRetainArcSource(inner)` internally when `inner` is `ptrTy_` — the recursive `tryUnwrapFromAny` already owns one refcount on the extracted Ok value, so the `Some(...)` arm does NOT double-retain (the existing tryRetainArcSource is the single retain the wrapper owes the caller). The same applies to `buildOkValue(rec)` on record / collection results: the field-by-field `InsertValue` build owns the refcount once per ARC-bearing field.
- The complementary `share/std/json/json.ry` change is a one-line `v: T = a` → `v: T = a?` won't work (the `?` operator requires the LHS Result type to match the function's return Result type). Instead, the Ry-side `load<T>` does NOT need to change — `emitJsonLoad` in `codegen_call_json.cpp` directly emits the `tryUnwrapFromAny` call as part of the `load[T]` codegen and PHI-merges the parse-Err / unwrap-Err / unwrap-Ok paths into a single `Result<T, Error>` SSA value.

### `Map<any, V>` is out of scope for the literal `any`-hint path; key-side must keep the strict same-type gate

**Source**: #1884 (2026-05-27, feat — `Map<K, any>` / `List<any>` / `Set<any>` literal annotation propagation)
**Tags**: codegen, any, map, literal, hint, rehash, hash-table, scope, strict-type-gate

**Context**: #1884 added a `LiteralAnyHintGuard` RAII helper so that `m: Map<str, any> = {"a": 1, "b": "two", "c": true}` per-element-wraps via `wrapInAny` and skips the strict same-LLVM-type gate in `emitExprVariant(MapExpr / ListExpr / SetExpr)`. The hint structure has separate `map_key_any` / `map_value_any` flags, but **only the value side is wired**. The temptation is to extend the same wrap-skip to `Map<any, V>` for symmetry; this is unsafe.

**Rule**: In both `computeLiteralAnyHintFromAnnot` and `computeLiteralAnyHintFromMeta` (the var-decl / function-local reassign + module-global reassign paths feed through these), force `hint.map_key_any = false` even when the annotation literally says `Map<any, V>`. Both helpers must agree — if only one keeps the gate closed, the reassign path leaks the unsafe wrap on its own. The map literal emitter then falls through to the strict same-LLVM-type key check, which is the user-visible error surface (`map keys must all have the same type`).

**Why**:

- The hash-table rehash dispatch (`__ry_ht_rehash_i64` / `__ry_ht_rehash_f64` / `__ry_ht_rehash_str`) has no 16-byte struct (`anyTy_`) variant. Picking any of the three would write keys at the wrong stride or hash bytes that overlap the tag.
- The runtime lookup path (`emitMapKeyLookup`) has a linear-scan fallback for `StructType` keys via `__ry_any_eq`, so a populated `Map<any, V>` *would* be lookup-safe in isolation — but the literal-time bucket write hashes the key into a bucket that the lookup linear-scan would have to ignore entirely. There is no current code path that can produce a self-consistent `Map<any, V>` at literal-construction time.
- The ARC story is also unaddressed for `anyTy_` keys carrying str / List / Map / Set / record / enum payloads (the default map dtor releases the LLVM-typed key slot, not the anyTy_ heap-box descriptor underneath).

**How to apply**:

- In `src/codegen_expr_literal.cpp` (`computeLiteralAnyHintFromAnnot`, `computeLiteralAnyHintFromMeta`), when the annotation matches `Map<K, V>` with `splitTypeArgs` returning 2 args, set `hint.map_value_any = (trimTypeNameSpaces(args[1]) == "any")` and **leave `hint.map_key_any` at its default `false`** — do NOT mirror the check on `args[0]`.
- Negative tests live in `tests/test_codegen_stmt.cpp` (e.g. `MapKeyTypeMismatchUnderAnyAnnotationRejected`) and verify that `Map<any, V> = {1: "a", "two": "b"}` still produces the strict same-type error. If a future PR lifts this restriction, it must add (a) an `__ry_ht_rehash_any` runtime variant, (b) a bucket-write path that hashes through `__ry_any_hash`, and (c) a per-key ARC release path that dispatches on the inner tag.
