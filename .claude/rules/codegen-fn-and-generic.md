# Codegen Functions, Generics, and Higher-Order

### inferExprType / inferExprTypeName visitors must handle every expression node, including IfExpr/IfBlockExpr and ADT constructors

`inferExprType` and `inferExprTypeName` (`src/codegen_lambda.cpp`) determine an expression-body lambda's return type. Both must have explicit `if constexpr` cases for every AST node that can appear as the outermost expression — any unhandled node falls through to `i64Ty_` (= `int`) silently, baking the wrong return type into the function signature. Required cases: `IfExpr` / `IfBlockExpr`, plus `Ok` / `Err` / `Some` / `None` / `Error` / `None()` in `CallExpr`. For Result/Option IfExpr branch merge, use `preferConcrete(a, b)`: i8 placeholder loses to anything; `anyTy_` (unannotated param) loses to a concrete type but wins over i8. The Ok/Err/Some/None emitters (`codegen_call.cpp`) must `unwrapFromAny(inner, expectedSlotTy)` when the value is `anyTy_` and the slot is concrete & primitive — otherwise the emitted struct slot type differs from the sibling branch and `validateBranchTypes` fails. `canAnyHoldType(errorTy_)` is false, so `Err(Error(...))` is unaffected.

### None has three syntactic forms — isNoneLiteral must match all three

`None` (bareword `VariableExpr`), `none` (`NoneExpr`), and `None()` (zero-arg `CallExpr`) are semantically identical Option literals. `isNoneLiteral` in `codegen_type.cpp` must recognize all three, otherwise the annotation-aware short-circuit at `emitVarDecl` / local-reassign / module-global-reassign sites is bypassed for `None()` and the emitter falls back to `fn_->getReturnType()` — wrong in let-decl / reassignment where the enclosing function's return type is unrelated. `CallExpr` is stored as `std::unique_ptr` in the `ExprNode` variant; use `std::get_if<std::unique_ptr<CallExpr>>`.

### Option None inner-type hint channel: option_none_hint_inner_ vs option_decl_annotation_inner_

`None()` / `none` in branch-merge / lambda-call-arg / record-constructor-field positions needs an inner-type hint, otherwise it defaults to `Option<i8>` or `Option<i64>`. Two RAII-guarded class-state fields: `option_none_hint_inner_` is the arm hint read directly by `None()` / `NoneExpr` emitters (nullptr = no hint); `option_decl_annotation_inner_` carries declaration-context annotation inner and is used only as fallback in IfExpr / IfBlockExpr — must NOT flow into argument positions, which take their hint from the callee's `FnTypeInfo::paramTypes[i]` or the field's struct element type. CaseExpr (pattern match) installs the hint from the scrutinee's Option inner because pattern-bound vars are not in scope at pre-scan time. `isNoneLiteral` short-circuit at the three annotation-aware sites must remain the FIRST check (faster, no hint state needed for trivial `x: Option<int> = None()`).

### instantiateGenericEnum must keep variantOrder in sync with variants

The generic-enum instantiation path duplicated most of `EnumInfo` setup but missed populating `info.variantOrder`. Any code reading `variantOrder` (e.g. payload-aware ADT equality) silently iterates zero elements for generic enums and falls through to the tag-only fast path, returning wrong results. When adding new `EnumInfo` fields, update both the non-generic path (`codegen_stmt_misc.cpp`) and the generic path (`codegen_fn_generic.cpp`) together.

### Generic enum types in type positions need substituteTypeParamsInName plus ensureEnumInstantiated

`resolveType("MyOpt<T>")` during generic-fn instantiation needs two independent mechanisms: (1) substitute type-param names inside `<...>` recursively (bare name, `weak X`, `X?`, `Base<Args...>`) using `type_param_scope_`, then re-call `resolveType` with the rewritten name; (2) call `ensureEnumInstantiated(typeName)` before the final `unknown type` error so any type position lazily instantiates. Both layers are required — fixing only one leaves half the issue. Surface-name strings (`paramTypeNames`, `exposedReturnTypeName`) used for metadata-driven dispatch must also flow through `substituteTypeParamsInName`. For bare template names without `<...>`, emit a dedicated diagnostic ("generic enum 'X' used without type arguments; write X<T>...") echoing the template's actual first type-parameter name, not a hardcoded `T`.

### Lambda / function return paths need bidirectional any ↔ narrow coercion

Whenever a return site has a `wrapInAny` (narrow → any) branch, audit the same site for the inverse `unwrapFromAny` (any → narrow) case — both directions are required. Untyped lambda params default to `any`, so `(a, b) -> int => a + b` evaluates `a + b` via `emitAnyBinaryOp` (returns `any`) but the annotation says `int`. Without `unwrapFromAny`, this errors with "expected 'int', found 'any'". Apply at both expression-body (`codegen_lambda.cpp`) and block-body (`codegen_fn.cpp`) return sites: `if (isAnyType(val->getType()) && !isAnyType(retTy) && canAnyHoldType(retTy)) val = unwrapFromAny(val, retTy);`. `canAnyHoldType` limits to primitives so non-primitive return mismatches still produce a compile error.

### Higher-order untyped lambdas: accumulator anyTy_ alloca needs wrapInAny on seed

`anyTy_` is a 16-byte struct `{i64 tag, [8 x i8] data}`. `CreateStore(narrowVal, anyTyAlloca)` writes only 8 bytes of value width, leaving `data` uninitialized; the tag holds the raw value and the dispatch routes on garbage. Before `CreateStore(v, accSlot)` where `accSlot` is `anyTy_`, coerce with `wrapInAny(v)` (or `coerceCallArgs`-style widening). When fixing one higher-order fn (`reduce`), audit all siblings (`fold`, `scan`). Use MSan, not ASan, to detect this regression.

### Seed-less reductions on possibly-empty lists must return Option, not panic

`reduce(list, fn)` (no seed), `min`, `max`, and similar must return `Option<T>` and emit `buildNoneValue` on the empty branch / `buildSomeValue` on the populated branch with a PHI at merge — model on `first` / `last`. Reductions that take a seed (`fold`) are exempt — the seed makes the empty case well-defined, plain `T` return is right. When two near-identical builtins differ only in a parameter (`reduce(list, fn)` vs `fold(list, init, fn)`), detect Python/JS-style miscalls at the specific arg count and emit a targeted error naming the sibling (precedent: ad-hoc hints in `codegen_call_user.cpp:17`).

### @native dispatch: exact-match Pass 1 before widening Pass 2

All three `@native` dispatch sites (`emitTableDrivenNativeCall` fixed-arity, variadic, `emitGenericNativeCall`) run a two-pass overload resolution: Pass 1 exact type match (unchanged behavior), Pass 2 (only if Pass 1 empty) accepts widening via `isWideningConversion` / `emitWideningConversion`. Order matters: `pow(2, 3)` must dispatch to `(int, int) -> int` rather than silently promoting to `(float, float) -> float`. Reuse the public helpers; do not reimplement `SIToFP` inline. Custom emitters replicate this locally — append the widening branch AFTER both exact branches so precedence is preserved by branch ordering (`emitMathFloorCeilRound`, `emitMathLog`, `emitMathPow` are canonical examples).

**User-defined generic fns follow the same two-pass shape (#1874).** `CodeGen::resolveGenericOverload` (`src/codegen_fn_generic.cpp`) iterates `generic_fn_templates_[baseName]` twice through `tryInferTypeArgsForTemplate`: Pass 1 with `allowWidening=false` (concrete leaves must equal the inferred `inferExprTypeName` value), then — only when Pass 1 yields zero matches — Pass 2 with `allowWidening=true` which delegates to the static helper `isNameWidening` (mirrors `isWideningConversion` at the type-name level: `u8 -> int`, `u8 -> float`, `int -> float`). Widening is honored only at top-level BasicType concrete leaves; recursive calls into GenericType / TupleType / FnType / OptionalType inner positions always disable the flag so `List<int>` does NOT accept `List<u8>`. Each pass collects every match; exactly one wins, two-or-more raises `codegenError("ambiguous overload ...")` (Pass 2's message distinguishes "after widening"), and zero matches across both passes raises `codegenError("no matching overload ...")` when multiple templates are declared. The single-template legacy path is preserved: with exactly one declared template, the no-match branch re-runs `tryInferTypeArgsForTemplate` with `emitErrorOnUnbound=true` to keep the original "could not infer type parameter '...'" diagnostic. Call-site widening (`SIToFP` etc.) is automatic because `resolveOverload` in `src/codegen_call_user.cpp` already calls `isWideningConversion` / `emitWideningConversion` against the selected template's params — no separate widening-conversion step is required after `resolveGenericOverload` returns. **Duplicate-declaration rejection** happens at registration time in `registerGenericFnTemplate`: each `GenericFnTemplate` is compared against existing entries via `buildParamFingerprint` (type-variable names normalized to positional `__T0`, `__T1`...) and an exact arity + fingerprint match raises `codegenError("duplicate generic function declaration ...")`. `mangleGenericFnName` reuses the same fingerprint as a suffix on each monomorphized symbol so two distinct templates that resolve to the same surface type-args (e.g. `first<T>(xs: List<T>)` and `first<T>(s: Set<T>)` both at `T=int`) compile to distinct IR functions and cache independently in `generic_fn_instantiated_`.

### IndexExpr first index is scalar only — RangeExpr routes to emitListSlice

`lst[a..b]` parses as `IndexExpr{indices:[RangeExpr{a,b}]}`. Without a guard, `RangeExpr` materializes a `List<i64>` ARC header (`ptr`) that flows into the bounds-check helper (`codegen::lowering::lowerBoundsCheck` → `codegen::emission::emitBoundsCheck`) / GEP and produces `ICmp ptr vs i64` verifier errors. Before the index-emit loop, detect single-index RangeExpr, reject str / map receivers, emit start/end as i64 directly, apply `emitNegativeIndexWrap` to each bound, set `endExcl = end + 1`, then call `emitListSlice`. Semantics: `lst[a..b]` is inclusive on both ends, negative bounds wrap, out-of-bounds clamp. `emitListSlice` invariant is "caller pre-wraps, I clamp" — applies to both call sites (`emitCollOp_slice` and the range-index route). For string substring, `wrapBase` must be `__ry_utf8_len_n(s, byteLen)`, not byte length.

### Self-referential enum inline fields produce a dedicated diagnostic recommending List / Map / Set / Task / Channel indirection

`emitStmt(EnumStmt &)` walks each variant field's `TypeNode` AST recursively. Self-reference is reported when the enum's own name appears in any of: bare identifier, generic application's base, optional inner, tuple/array element, union component, or arbitrary non-indirection generic. Indirection wrappers that stop the descent (payload is boxed, layout is finite): `List<_>`, `Map<_,_>`, `Set<_>`, `Task<_>`, `Channel<_>`, `weak T`, `fn(...)`. The recommendation message points to List/Map/Set/Task/Channel only (excludes `weak` and `fn(...)` — unusual choices for data storage). Run this pre-pass before saving the generic-enum template so `generic_enum_templates_` never holds a self-referential template that would crash at instantiation.

### Lambda return-type inference must consult @native signatures and use source-level type names; propagate full captured-var metadata

`inferExprType` / `inferExprTypeName` for `CallExpr` must check `native_fn_sigs_` + `native_lib_index_` when `findFunction()` misses — many stdlib calls (`lockNew`, resource-returning fns, `Result<any, Error>` returns like `json.load`) are registered only as `@native`. When narrowing overloads, compare `inferExprTypeName(arg)` against `sig.params[i].typeName` (source-level Ry names), NOT `argTypes[i] == resolveType(sig.params[i].typeName)` — under opaque pointers, `str` / `List` / `Map` / `Set` all resolve to `ptr` and the LLVM-type comparison declares every overload ambiguous. For captured variables in lambda / nested-fn bodies, save the outer alloca in `CaptureAnalysisResult::capturedSrcAllocas` and call `propagateMeta(srcAlloca, newAlloca)` after the captured-param `CreateStore` — copies collection types, type-name strings, `fn_type_info`, resource kinds, ARC-managed flags in one shot. Without this, dispatch inside the body misroutes (e.g. `length(xs)` → str runtime). At higher-order Result/lambda boundaries, restore metadata after `CreateExtractValue` (drops `ValueMetadata`): mirror the `?` operator path in combinators by `propagateMeta(wrapper, payload)` before passing into the callback. In `emitLambdaCall`, always stamp the call result from `FnTypeInfo.returnTypeName` (and `returnFnTypeInfo` for fn-typed returns).

### @native first-class materialization: synthesize a thunk that re-enters the call dispatcher

To make a `@native` stdlib fn usable as a first-class value (`let f = toInt`), `emitExprVariant<VariableExpr>` calls `materializeNativeThunk(name)` immediately after the user-fn lookup miss and before the `undefined variable` error. The helper collects `NativeFnSignature` candidates by bare name and `<package>::name` suffix, rejects multi-overload names with "ambiguous reference, wrap in a lambda", and emits an internal LLVM Function `__ry_native_thunk_<name>` whose body is a synthetic `CallExpr{callee=name, args=VariableExpr{p.name}}` routed back through `emitExpr` (reuses Pattern A/B/generic + `@native("libname")` dlopen with no duplication). `FnScope` is mandatory around body emission to save/clear/restore `fn_` / `current_function_` / `IRBuilder` state — without it, the synthetic CallExpr's IR lands in the caller's BB. Cache the thunk in `native_thunk_cache_[name]` BEFORE body emission so self-referential resolution returns the same Function instead of recursing infinitely. Set `getOrCreateMeta(thunk).fn_type_info = info` with `info.paramTypeNames` populated from `sig.params[i].typeName`. The thunk's signature mirrors `sig.params` 1:1 (default-omission shortcut works only on direct CallExpr). User-defined fns continue to shadow `@native` because the thunk path activates only on user-fn lookup miss.
