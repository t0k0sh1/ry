### Added

- `try:` block expression — an effect-block that creates a propagation scope for the `?` operator below the function level. Inside the block, `?` escapes to the block's merge point (not to the enclosing function), and the tail expression is implicitly wrapped in `Ok(...)` / `Some(...)`. The Result / Option discriminant and the `Err` type are resolved from either the enclosing fn return type (`return try: ...`) or a `let` LHS annotation (`let x: Result<T, E> = try: ...`). Inline form (`try: <expr>`) and block form (`try:` + indented body + tail) are both supported. Nested `try:` blocks always dispatch to the innermost; `using` composes cleanly inside `try:` (close runs on every exit path, including `?` escape). Mixing Result and Option `?` operators within a single block is a compile error. The existing function-level `?` semantics are preserved verbatim when no enclosing `try:` exists. See [RFC: effect-block](docs/rfcs/effect-block.md) and the [`?` operator reference](docs/reference/operators.md#try-block-expression-effect-block). (#1702)
