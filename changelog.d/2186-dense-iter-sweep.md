### refactor(codegen): migrate dense iterator next-fn bodies via crates/emit primitives (#2186)

A/A2 follow-on (#2098 / #2099) sweep that closes the dense-iterator cluster (`iter(List)` / `iter(Set)` / `iter(Map)`) on the boundary trajectory pilots A and A2 opened. No new capability — the next-fn body shape is identical to `take` / `filter` / `map`. Two new generic primitives extend the #2099 aggregate-access pair into a symmetric set: `ry_emit_undef` (`LLVMGetUndef`, the seed of `undef → insertvalue 0 → insertvalue 1` aggregate-build) and `ry_emit_insert_value` (`LLVMBuildInsertValue`, the symmetric partner of `ry_emit_extract_value`). `emitDenseIterator` (the shared `List` / `Set` lambda) and the `Map` iterator's next-fn body in `src/codegen_call_iterator.cpp` carry no `builder_.Create*`; `filter` / `map` function declarations move onto `emitCreateFunction` to match `take`'s surface. The outer state-setup (`malloc` + StructGEP stores + header alloc — `ValueMetadata` crossing) stays C++-side and is tracked under #2100. ASLR-normalized `--emit-llvm-ir` diff bit-exact empty over List/Set/Map probes with `__iter_list_next` / `__iter_set_next` / `__iter_map_next` / `tuple_k` / `tuple_kv` markers coverage-gated.
