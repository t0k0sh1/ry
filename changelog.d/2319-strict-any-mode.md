### Added

- `strict-any` opt-in mode that enables stricter `any` semantics ahead of those becoming the default. Activated by the `RY_STRICT_ANY=1` environment variable or the `--strict-any` CLI flag (which `setenv`-s the same variable so subprocesses spawned by `ry test` inherit it). Diagnostics produced by the mode are tagged `[strict-any/<rule>]` for grep-friendly filtering. The first rule shipped is `any-arithmetic`: direct binary `+`/`-`/`*`/`/`/`%`/`//`/`**` and unary `-` on an `any`-typed operand is rejected with a hint to annotate the operand type or use `asType[T](...)` to recover a concrete value first. Comparisons (`==`, `!=`, `<`, `<=`, `>`, `>=`) remain permitted because they always yield a concrete `bool`. Follow-up issues #2316 / #2317 / #2321 / #2323 plug additional rules into the same `[strict-any/<rule>]` seam; #2322 will eventually flip strict-any to the default. (#2319)
