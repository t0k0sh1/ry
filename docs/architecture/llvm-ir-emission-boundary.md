# LLVM IR Emission Boundary

This document identifies the candidate shared-library boundary inside the codegen layer. It is the design reference for issue #1949 (extract the LLVM IR emission layer as a separate shared library) and #1950 (reimplement that shared library in Rust). Issue #1820 (v0.0.26 stage 2) prepares the surface by extracting layer-independent helpers and documenting the access patterns described here.

## What this boundary is

The "LLVM IR emission layer" is the subset of `CodeGen` that owns LLVM types and the `IRBuilder<>`. Today this is intertwined with type registries, ARC bookkeeping, stdlib dispatch, and module-namespace state inside a single monolithic class (`include/ry/codegen.hpp`). The goal of #1949 is to extract the LLVM-touching surface into its own `.so`/`.dylib` exposing a stable `extern "C"` boundary, so that #1950 can reimplement it in Rust without rewriting the rest of the compiler.

## Constraint: LLVM types must not cross the boundary

In the final design, the following LLVM-owned types **must not appear** in the shared-library boundary:

- `llvm::Value*` / `llvm::Constant*` / any `llvm::*` derivative
- `llvm::Module&` and `llvm::LLVMContext&`
- `llvm::IRBuilder<>` and its template instantiations
- `llvm::Function*` / `llvm::BasicBlock*` / `llvm::Type*`

These types are LLVM-version-coupled and cannot be reasonably exposed through a stable boundary. The boundary instead exchanges opaque handles (or value IDs) that the LLVM side resolves internally. Concretely: anywhere the current C++ code passes an `llvm::Value*` between a custom stdlib emitter and a `CodeGen` helper, that exchange must be redesigned to use a plain integer handle, a small POD struct, or a callback that lives entirely on the LLVM side.

## Access categories observed in custom stdlib emitters

The 16 `src/codegen_call_*.cpp` dispatcher files are the primary consumers of `CodeGen` internals. Their access patterns fall into five categories:

1. **LLVM context handles**: `builder_`, `mod_`, `ctx_`, `fn_`. These are the raw LLVM state — they cannot cross the boundary as-is. Custom emitters that take a `CodeGen&` and read these directly must be reshaped to receive an `EmitterContext` wrapper instead.
2. **Primitive type accessors**: `i64Ty_`, `ptrTy_`, `anyTy_`, `errorTy_`, `i8Ty_`, `f64Ty_`, etc. These are `llvm::Type*` and share the same constraint as category 1 — wrap behind opaque type-id handles in the boundary.
3. **Runtime wrapper helpers**: `getRuntimeFn`, `wrapPtrAsResult`, `wrapStatusAsResult`, `emitResultBranch`, `buildErrorFromRuntime`. **This category is the most narrowed existing boundary candidate** — all five helpers are already centralized in `src/codegen_call_dispatch.cpp`, and they encapsulate the canonical "call a runtime symbol, wrap the result as `Result<T, Error>`" pattern. They are the natural starting point for the shared-library extraction in #1949: a thin wrapper layer that exchanges opaque value handles and dispatches to the LLVM-owning side.
4. **Metadata API**: `propagateTypeMeta`, `setTypeMeta`, `emitExpr`. These mutate or query the `ValueMetadata` keyed by `llvm::Value*`. Crossing the boundary requires the metadata store to live on the LLVM side and be addressed through the same opaque handles as category 1.
5. **Predicate and error helpers**: `isStringValue`, `isFile`, `codegenError`, `requireArgs`, `propagateTypeMeta`. These mix value inspection (LLVM-coupled) with diagnostic reporting (layer-independent). Diagnostics can move to the caller side; value-inspection predicates must stay LLVM-side.

## Narrowing direction (not implemented in #1820)

The concrete narrowing — replacing direct `CodeGen&` parameters in custom emitters with a smaller `EmitterContext` interface — is **not** in scope for issue #1820. The acceptance criterion is satisfied here by documentation: emitter access is currently broad, the narrowing plan is to introduce a context struct exposing only the surface above, and the implementation is left to a follow-up issue gated on #1949's boundary design.

The recommended sequence is:

1. (this issue, #1820) Document the surface; extract layer-independent string/type-name helpers out of `CodeGen` so they no longer cross the boundary.
2. (#1949) Define the shared-library boundary starting from category 3 (the most narrowed surface today) and progressively wrap the other categories. Extract the LLVM-owning side into `libemit.so`/`.dylib`.
3. (#1950) Reimplement `libemit` in Rust behind the same boundary.

## Stage 2-A landed (#1949 scaffolding)

> **Historical record — superseded by Rust cutover (#1993) and C++ shim removal (#2229).** References below to `src/codegen_emission_*.cpp`, `src/codegen_lowering_*.cpp`, `include/ry/codegen/lowered_*.hpp`, and the `ry::codegen::{emission,lowering,lowered}` namespaces describe the then-current shim layer that #2229 deleted. The current implementation is in `crates/emit/src/` (see "Stage 2-C complete (#1993 — cutover to Rust)" below); caller-side C++ in `codegen_*.cpp` calls `ry_emit_*` directly.

The first #1949 PR is intentionally scaffolding-only — it stands up the shared-library boundary without migrating every category-3 helper:

- **Shared library target**: `emit` is built as `add_library(SHARED ...)` in the root `CMakeLists.txt`. It produces `lib/libemit.{dylib,so}`; LLVM is not linked into it (its symbols resolve from the main process via `-undefined dynamic_lookup` on macOS and `-rdynamic` on Linux, mirroring the `add_ry_native_lib()` pattern). Unlike the JIT-loaded stdlib native libs the `ry` / `ry_tests` executables and the `add_ry_fuzz_target` harnesses link it explicitly because `ry_lib`'s shim layer references its symbols at compile time.
- **boundary header**: `include/ry/llvm_emit/api.h`. Defines `RyValueId` / `RyFuncId` / `RyTypeId` as `uint32_t` opaque handles, `RyEmitCtx` as an opaque struct, and a `RyEmitCallbacks` slot for the helpers that have not crossed the boundary yet. The header is the LLVM-type-exclusion contract: no `llvm::Value*` / `llvm::Module&` / `llvm::IRBuilder<>` / `llvm::Function*` / `llvm::BasicBlock*` / `llvm::Type*` appears in any public signature. Module / IRBuilder / context / function pointers are passed as transitional `void*` until categories 1 and 2 cross the boundary in a successor PR.
- **Helpers crossing the boundary in 2-A**: three entry points — two of the five category-3 helpers plus the BoundsCheck pilot.
  - `ry_emit_get_runtime_fn` — backs `CodeGen::getRuntimeFn` (category 3).
  - `ry_emit_build_error_from_runtime` — backs `CodeGen::buildErrorFromRuntime` (category 3). Takes `errorTy_` as a transitional `void*` parameter to preserve the named-`StructType` pointer identity that `isResultType` and friends rely on.
  - `ry_emit_bounds_check` — backs the BoundsCheck pilot from #1961. Not a category-3 helper; it is the first lowered-op surface that crosses the boundary. Calls into `CodeGen::emitNegativeIndexWrap` and `CodeGen::emitBoundsError` through the `RyEmitCallbacks` slot (this is replaced in Stage 2-B by proper boundary functions).
- **Category-3 helpers deferred** (still `CodeGen` methods, untouched call sites): `wrapPtrAsResult`, `wrapStatusAsResult`, and `emitResultBranch` — the remaining three of five. Their bodies pull in `getResultType` (a pointer-identity-sensitive `result_types_` cache) and `buildOkValue` / `buildErrValue` (which call `propagateMeta` + `tryRetainArcSource`). Migrating them via callbacks would widen the boundary surface beyond the scaffolding scope; they migrate together with the `ResultBranch` lowered op in Stage 2-B (#1964).
- **BoundsCheck shape**: the lowered op type in `include/ry/codegen/lowered_bounds_check.hpp` still holds `llvm::Value*` members, per the two-stage boundary policy — the lowering↔emission split is an internal C++ boundary where LLVM types are allowed; only the boundary surface is opaque. `src/codegen_emission_bounds_check.cpp` interns the op's `idx` / `len` into handles immediately before each boundary call.
- **EmitCtx lifecycle**: one ctx is created in `CodeGen::CodeGen` and destroyed in `CodeGen::~CodeGen`. There is no current-function slot: BB-creating boundary ops derive the parent function from the builder's insert block (`ctx->builder->GetInsertBlock()->getParent()`), so the former `ry_emit_ctx_set_function` setter and its cached field were removed in #2083. The handle table is a `std::vector<llvm::Value*>` indexed by `RyValueId`; handle 0 is the sentinel for "invalid / null".

## Stage 2-B landed (#1964 — category-3 migration complete)

> **Historical record — superseded by Rust cutover (#1993) and C++ shim removal (#2229).**

The second #1949-track PR finishes the category-3 helper migration and removes the transitional `RyEmitCallbacks` slot:

- **Three new emission entry points**: `ry_emit_result_branch`, `ry_emit_negative_index_wrap`, `ry_emit_bounds_error` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. All three are self-contained: `ry_emit_bounds_error` resolves its own `stdout` / `stderr` / `_Exit` / `fprintf` callees through `getOrInsertGlobal` / `getOrInsertFunction` on the LLVM `Module*`, and deduplicates format-string globals inside `RyEmitCtx::bounds_msg_cache` rather than calling back into CodeGen's `cachedGlobalString`.
- **ResultBranch lowered op**: `include/ry/codegen/lowered_result_branch.hpp` mirrors the BoundsCheck shape (`lowered::ResultBranchOp` struct + `lowering::lowerResultBranch` + `emission::emitResultBranch`). The lowering side has no constant-fold path today (ok/err builders are runtime lambdas), but the structure is kept symmetric so a future fold can be added without reshuffling callers. The emission side translates `llvm::function_ref<>` closures into the C-function-pointer + `user_ctx` boundary shape via a small trampoline in `src/codegen_emission_result_branch.cpp`.
- **`emitResultBranch` shim**: `CodeGen::emitResultBranch` survives as a thin shim that calls `codegen::lowering::lowerResultBranch` + `codegen::emission::emitResultBranch`. This keeps the ~14 existing `function_ref`-style call sites (including the three-level nest in `emitHttpRequest`, the `emitResultBranchWithMeta` in `codegen_call_io.cpp`, and Option/Result-monad helpers) working without per-caller edits. `wrapPtrAsResult` / `wrapStatusAsResult` likewise stay on the CodeGen side as thin convenience wrappers over `emitResultBranch`.
- **`getResultType` stays in CodeGen**: the `result_types_` cache and its `reverse_result_types_` reverse map are consumed by ARC release (`codegen_arc.cpp`) and Any wrapping (`codegen_any.cpp`) for type introspection. Migrating those reverse-direction consumers requires a category-2 (primitive type accessor) migration that is out of Stage 2-B scope. `resTy` crosses the boundary as `void*`, mirroring `errorTy_` in `ry_emit_build_error_from_runtime`.
- **`RyEmitCallbacks` removed**: `ry_emit_bounds_check` now invokes `ry_emit_negative_index_wrap` and `ry_emit_bounds_error` directly inside the shared library. The `RyEmitCallbacks` typedef, `ry_emit_ctx_set_callbacks`, and the corresponding registration in `CodeGen::CodeGen()` are all gone. The handle table inside `RyEmitCtx` is unchanged.

After Stage 2-B, the only remaining transitional shapes are the `void*` parameters for module / builder / context / function / `StructType*` — those become typed opaque handles when categories 1 and 2 cross the boundary in Stage 2-C.

Stage 2-C will: (1) migrate the remaining lowered IR ops (`RuntimeCall`, `AnyWrap` / `Unwrap`, `CollectionMutate`, `ArcRetain` / `Release`, `CowEnsureUnique`, `ControlFlow`), (2) start crossing category 1 / 2 so the transitional `void*` parameters can become typed opaque handles. The first 2-C step (#1967) migrated `OptionWrap` via two new emission entry points (`ry_emit_option_wrap_some` / `ry_emit_option_wrap_none`); unlike BoundsCheck / ResultBranch, OptionWrap creates no basic blocks and therefore does not require `ry_emit_ctx_set_function`. The Ry-semantic side effects of the `Some` arm (`propagateMeta` + `tryRetainArcSource`, #999) stay on the CodeGen-side shim so the emission TU remains a pure `intern → boundary → resolve` transit. `getOptionType`'s `StructType` cache stays in CodeGen for the same reason as `getResultType` (`reverse_option_types_` is consumed by ARC release and Any wrapping); `optTy` crosses the boundary as `void*`. The codegen-layering graduation document remains unwritten until the remaining 2-C ops migrate and the boundary is observable end-to-end.

## Stage 2-C in progress (#1968 — ARC retain/release migrated; #1969 — RuntimeCall consolidated; #1970 — CowEnsureUnique migrated)

> **Historical record — superseded by Rust cutover (#1993) and C++ shim removal (#2229).**

The first Stage 2-C op migration moves ARC retain/release across the boundary. ARC ops are the highest-fanout lowered op surface (`emitArcRetain` has 30+ call sites and `emitArcRelease` has 25+, reached indirectly through `@parallel for`, lambda capture, CoW clone, record/tuple field retain, and tagged-union release paths), so migrating them first establishes the boundary shape that the remaining Stage 2-C ops (`RuntimeCall`, `AnyWrap`, `CollectionMutate`, `CowEnsureUnique`, etc.) will reuse:

- **Two new emission entry points**: `ry_emit_arc_retain` and `ry_emit_arc_release` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. Both are self-contained: the implementation rebuilds the anonymous `{i64 strong_count, i64 weak_count}` ARC header struct locally (no `void *arc_header_ty_ptr` parameter needs to cross the boundary because opaque pointers make the offset-0 GEP version-independent), resolves `__ry_gc_track` / `__ry_gc_untrack` / `free` callees through `getOrInsertFunction` on the `Module*`, and emits `__ry_arc_counter_address`-keyed `atomicrmw add` for the live-count balance counter — all without calling back into `CodeGen`.
- **Atomic flag crosses the boundary**: `ry_emit_arc_retain` / `ry_emit_arc_release` take an `int atomic` parameter (`RyArcAtomic` enum: `RY_ARC_NONATOMIC = 0`, `RY_ARC_ATOMIC = 1`). The `@parallel for` SeqCst contract (`parallel_for_depth_ > 0` → `atomicrmw SeqCst`) is preserved because the caller-side `isArcAtomic()` decision is made before the boundary call and propagated as a primitive.
- **Destructor crosses as a C function pointer**: `ry_emit_arc_release` takes `void *destructor_callee` rather than `llvm::FunctionCallee`. The lowering layer (`src/codegen_lowering_arc.cpp`) extracts `Value*` via `FunctionCallee::getCallee()` so the LLVM-typed `(FunctionType*, Value*)` pair does not need to cross the boundary; the emission side rebuilds the `void(*)(void*)` `FunctionType` locally. `gcVisitFn` likewise crosses as `void *gc_visit_fn` (nullable — null suppresses the `arc.gc_track` BB entirely).
- **ArcRetain / ArcRelease lowered ops**: `include/ry/codegen/lowered_arc.hpp` mirrors the BoundsCheck / ResultBranch shape (`lowered::ArcRetainOp` + `lowered::ArcReleaseOp` structs, `lowering::lowerArcRetain` / `lowerArcRelease` passthrough lowering, `emission::emitArcRetain` / `emitArcRelease` boundary dispatch). The lowering layer has no constant-fold path (ARC ops are always emitted at runtime), but the symmetric structure is kept so a future "skip retain when ref is already strong-immortal at compile time" fold can be added without reshuffling callers.
- **`CodeGen::emitArcRetain` / `emitArcRelease` shims**: both survive as thin shims that call `codegen::lowering::lowerArc*` + `codegen::emission::emitArc*`. The 55+ existing call sites (record field retain, tuple element CoW retain, `@parallel for` thunk teardown, lambda capture release, weak upgrade fast path, ARC tagged-union release, etc.) are not touched. `used_native_libraries_.insert("gc")` migrates from inline in `emitArcRelease` to once in `codegen_emission_arc.cpp` — the runtime requires `libry_gc` whenever `__ry_gc_track` / `__ry_gc_untrack` appear, and that decision is now driven by the emission layer.
- **`arc_owned_values_` side-effect intentionally not mirrored**: pre-migration `emitArcRelease` called `emitArcGetDataPtr` to compute the destructor argument, which had the side effect of inserting the resulting `Value*` into `arc_owned_values_`. The dataPtr is consumed only by the destructor call on the next IR line and is dead thereafter, so the side effect was benign at the release site. The boundary version uses a plain `GEP(i8, headerPtr, ARC_HEADER_SIZE)` with no side-table registration — verified semantically equivalent by the existing destructor-touching spec tests (List / Map / Set with str elements, `Result<List<int>, str>` Err binding, `@parallel for` worker ARC retain/release loops).
- **`arcHeaderTy_` named → anonymous**: pre-migration codegen used a named `%ArcHeader = type { i64, i64 }` struct. The boundary version creates an anonymous `StructType::get(*ctx, {i64, i64})` per call. Under opaque pointers all GEPs degenerate to `getelementptr i8, ptr ..., i64 N`, so the named-vs-anonymous difference is invisible in the emitted IR except for the absence of the `%ArcHeader = type {...}` declaration line. FileCheck CHECK patterns reference only BB labels (`arc.retain`, `arc.retain.done`, `arc.release.body`, `arc.release`, `arc.free`, `arc.skip_free`, `arc.gc_track`, `arc.done`) — not the named struct — so the goldens stay bit-exact.

## Stage 2-C in progress (#1969 — RuntimeCall consolidated, ResultBranch preemptive fix)

> **Historical record — superseded by Rust cutover (#1993) and C++ shim removal (#2229).**

The third Stage 2-C op migration consolidates every `__ry_*` runtime symbol resolution across the boundary. RuntimeCall is the highest-volume Stage 2-C surface — ~130 `mod_->getOrInsertFunction("__ry_…", fnTy) + builder_.CreateCall(...)` pairs scattered across 17 codegen translation units (largest: `codegen_test.cpp` 46, `codegen_call_io.cpp` 39, `codegen_call_string.cpp` 12) — and its consolidation completes the "no direct `__ry_*` symbol resolution from codegen" invariant Stage 2-C is built around:

- **New emission entry point**: `ry_emit_runtime_call` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. The implementation rebuilds the `FunctionType` from `ret_ty_ptr` + `arg_ty_ptrs[0..arg_ty_count]` (all transitional `void*` until categories 1/2 cross the boundary), resolves the symbol through `getOrInsertFunction`, and emits a single `CreateCall` against it with the supplied `RyValueId` argument handles. Void-returning calls get an empty SSA name automatically (LLVM forbids naming `void` results); non-void calls honour the `name_hint` parameter.
- **RuntimeCall lowered op**: `include/ry/codegen/lowered_runtime_call.hpp` mirrors the BoundsCheck / ResultBranch / OptionWrap / ARC shape (`lowered::RuntimeCallOp` struct + `lowering::lowerRuntimeCall` passthrough + `emission::emitRuntimeCall` boundary shim). The op type intentionally keeps `ret_ty` / `arg_tys` as bare `llvm::Type *` (category 2 not yet migrated, mirroring `errorTy_` / `resTy` on the boundary side). No constant-fold path: runtime calls are by definition runtime.
- **Bulk call-site migration via `getRuntimeFn`**: `CodeGen::getRuntimeFn` (`src/codegen.cpp:115`) is a boundary-aware thin wrapper over `ry_emit_get_runtime_fn` since Stage 2-A (#1949). The ~130 scattered call sites are uniformly rewritten from `auto fnTy = llvm::FunctionType::get(retTy, argTys, false); auto fn = mod_->getOrInsertFunction("__ry_…", fnTy);` to `auto fn = getRuntimeFn("__ry_…", retTy, {argTys});` — a one-line consolidation that routes every symbol resolution through the boundary without touching the subsequent `builder_.CreateCall(...)` (which stays on the caller side). The `emission::emitRuntimeCall` helper is available for future call-site migrations that want to route a full call (callee resolution + `CreateCall`) through the boundary in one shot.
- **`used_native_libraries_.insert("<mod>")` audit during migration**: where call-site migration touched stdlib dispatchers (`dispatchIO`, etc.), the library insert was verified to be at the dispatcher's top per the `.claude/rules/codegen-stdlib-dispatcher.md` rule (#1856). `dispatchIO` already conformed and was unchanged.
- **Variadic out of scope**: `__ry_print_printf` and `__ry_sprint_printf` in `codegen_call_user.cpp` use `isVarArg=true` and are incompatible with `getRuntimeFn`'s fixed `isVarArg=false`. A variadic-aware boundary variant or extension is deferred to a follow-up; the two sites remain on the legacy `getOrInsertFunction` path.
- **`ry_emit_result_branch` preemptive fix**: while in `src/llvm_emit/impl.cpp` for the RuntimeCall boundary implementation, `ry_emit_result_branch` was updated to derive the parent function for new basic blocks from `ctx->builder->GetInsertBlock()->getParent()` instead of `ctx->function`. This mirrors the `ry_emit_arc_retain` / `ry_emit_arc_release` fix in #1968 and forestalls the same cross-function reference hazard when result-branch helpers are invoked inside destructor / lambda / thunk bodies (where `cg.fn_` tracks the outer function while the IRBuilder has been retargeted to a nested function). Pre-existing call sites had not triggered the hazard because they happened to update `cg.fn_` before invoking, but RuntimeCall migration enlarges the caller surface.

## Stage 2-C in progress (#1970 — CowEnsureUnique migrated)

> **Historical record — superseded by Rust cutover (#1993) and C++ shim removal (#2229).**

The fourth Stage 2-C op migration (#1970) moves CoW (Copy-on-Write) uniqueness check across the boundary. CoW is the most structurally complex op migrated so far — a single call expands into atomic strong-count load + ICmp + CondBr + per-kind (List / Map / Set) deep copy with malloc + memcpy of the data buffer + optional per-element retain loop + optional per-key retain loop (Map) + `arc_release` of the old data ptr + slot store + PHI joining the no-clone and clone branches:

- **One new emission entry point**: `ry_emit_cow_ensure_unique` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. The function takes a single descriptor pointer (`RyCowEnsureUniqueDesc *`) carrying 12 primitive / opaque fields: `data_ptr_id` / `slot_ptr_id` (handles), `kind` (RyCowKind enum: `RY_COW_LIST=0` / `RY_COW_MAP=1` / `RY_COW_SET=2`), `atomic` (RyArcAtomic), `elem_size` / `key_size` / `val_size` (DataLayout-derived primitive sizes), `do_elem_retain` / `elem_is_str` / `do_key_retain` / `key_is_str` flags, and `destructor_callee` as a C `void *`. The single-descriptor shape keeps the C boundary extension surface narrow even though the op has many parameters; future ops with multiple kind-dependent fields are expected to adopt the same shape.
- **CowEnsureUnique lowered op**: `include/ry/codegen/lowered_cow.hpp` mirrors the ArcRetain / Release shape (`lowered::CowEnsureUniqueOp` struct, `lowering::lowerCowEnsureUnique` passthrough lowering, `emission::emitCowEnsureUnique` boundary dispatch with the LLVM `Value*` → `RyValueId` intern step). The lowering layer collects per-kind element / key / value sizes from `mod_->getDataLayout()` and the per-collection element type metadata before the descriptor is filled in by the CodeGen-side shim.
- **`CodeGen::emitCowCheckSlot` shim**: survives as a ~60-line shim that walks `arc_str_managed_vars_` / `arc_field_record_vars_` to set the `do_elem_retain` / `do_key_retain` flags, looks up element / key / value types via `getListElementType` / `getMapKeyType` / `getMapValueType` / `getSetElementType`, computes sizes via `dl.getTypeAllocSize`, resolves `getOrCreateCollectionDestructor`, calls the lower-then-emit pair, and runs `propagateMeta` / `propagateMetaWide` on the result. `CodeGen::emitCowCheck` (which wraps `emitCowCheckSlot` with the `arc_backed_vars_` / `arc_str_managed_vars_` guard) is untouched.
- **`emitCowDeepCopyList` / `emitCowDeepCopyMap` / `emitCowDeepCopySet` removed**: these three CodeGen-private helpers (one per collection kind) had no callers outside `emitCowCheckSlot`, so they dissolve into the boundary implementation's per-kind switch. The per-kind layout is reproduced as anonymous `StructType::get(*ctx, {...})` calls inside the boundary: List `{i64 strong, i64 weak, ptr data}`, Map `{i64 strong, i64 weak, ptr keys, ptr values, i64 cap, ptr present}`, Set `{i64 strong, i64 weak, ptr elems, i64 cap, ptr present}`. These mirror the named struct shapes still created in `src/codegen.cpp`'s collection constructors — a sync comment in `src/llvm_emit/impl.cpp` flags the dependency.
- **`emitCowRetainArcElements` stays in CodeGen**: this helper is called from 8 non-CoW sites (`codegen_expr.cpp`, `codegen_call.cpp`, `codegen_call_collection.cpp`) that retain ARC element buffers without going through the CoW path (`append!`, `insert!`, `concat`, `merge`, `slice`, …). Migrating it would either widen the boundary surface for a per-element retain loop or require those call sites to construct CoW descriptors they do not need. The boundary implementation re-derives the same loop shape internally by calling `ry_emit_arc_retain` per element.
- **Internal boundary cross-calls**: `ry_emit_cow_ensure_unique` invokes `ry_emit_arc_retain` (per element / per key in the retain loops) and `ry_emit_arc_release` (for the old data pointer before the slot store) directly inside the shared library. This is the first boundary helper that composes other boundary helpers — the pattern validates that the boundary surface is composable, not just leaf-level.
- **Atomic strong-count load preserves Acquire pairing**: the "is this the sole owner?" check at the top of the CoW path uses `emitAtomicI64Load(strongCountAddr, AtomicOrdering::Acquire)` when `desc->atomic == RY_ARC_ATOMIC`, preserving the pairing with the `atomicrmw SeqCst` updates emitted by `ry_emit_arc_retain` / `ry_emit_arc_release` so TSan stays clean on the `@parallel for` ARC path.
- **`arc_owned_values_` re-insert dropped**: the pre-migration `emitCowCheckSlot` called `arc_owned_values_.insert(newDataPtr)` after the clone branch. The set is rebuilt on every subsequent `emitArcGetDataPtr` call, and every downstream consumer goes through `emitArcGetDataPtr` before reading the data pointer, so the side-table insert was redundant. The boundary version omits it; the existing destructor-touching spec tests (List / Map / Set with str / nested-collection elements, `Result<List<int>, str>` Err binding, `@parallel for` worker ARC retain/release loops) confirm equivalence.

## Stage 2-C in progress (#1972 — AnyWrap/Unwrap migrated)

> **Historical record — superseded by Rust cutover (#1993) and C++ shim removal (#2229).**

The fifth Stage 2-C op migration (#1972) moves the `Any` wrap/unwrap op group across the boundary. `Any` is the most semantically complex op group migrated so far — `wrapInAny` covers six payload kinds (primitive Int/Float/Bool, Str heap header, collection List/Map/Set headers, organic Record via per-type heap box, simple-enum i64 / ADT-enum / Option / Result via per-enum heap box, function-pointer/resource rejection), `unwrapFromAny` covers three target kinds (Standard scalar/Str/collection, F64Promote with int→float coercion, Record with runtime descriptor-chain subtype walk via `__ry_record_is_subtype_desc`), and `tryUnwrapFromAny` adds the typed `Option<…>` / `Record` / `List<T>` / `Set<T>` / `Map<str, V>` sub-emission paths that build `Result<T, Error>` outputs rather than trapping on mismatch:

- **Three new emission entry points**: `ry_emit_any_wrap`, `ry_emit_any_unwrap`, `ry_emit_any_try_unwrap` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. Three top-level entries (rather than a single dispatched op) match the public CodeGen surface and let each boundary helper keep its own `RyAnyWrapKind` (`NonBox=0` / `RecordBox=1` / `EnumBox=2`) / `RyAnyUnwrapKind` (`Standard=0` / `F64Promote=1` / `Record=2`) / `RyAnyTryUnwrapKind` (`Standard=0` / `F64Promote=1`) enum.
- **AnyWrap / AnyUnwrap / AnyTryUnwrap lowered ops**: `include/ry/codegen/lowered_any.hpp` mirrors the CollectionMutate shape (three `lowered::AnyWrapOp` / `AnyUnwrapOp` / `AnyTryUnwrapOp` structs, `lowering::lowerAnyWrap` / `lowerAnyUnwrap` / `lowerAnyTryUnwrap` passthrough lowering, `emission::emitAnyWrap` / `emitAnyUnwrap` / `emitAnyTryUnwrap` boundary dispatch). No constant-fold path: `Any` boxing always materializes a runtime tag + payload pair.

## Weak ARC migration via atomic primitives (#2190, pilot E (ii))

## boundary struct-layout verification (#1995)

`#[repr(C)]` on the Rust side guarantees a C-compatible layout, but it does **not** by itself guarantee that the Rust structs match the C++ structs in `include/ry/llvm_emit/api.h` byte-for-byte: field order, padding, and `enum` underlying-type interpretation can each drift incidentally when the two declarations are maintained by hand. Because the Rust reimplementation of `emit` (#1950 / #1993) passes these descriptors across the FFI boundary by pointer, any such drift is a silent miscompile. The verification mechanism below is the safety net that turns that class of drift into a build failure.

### Method A — paired compile-time assertions

The check is implemented as two halves that assert against the **same** constants:

- **C++ side** — `tests/test_abi_layout.cpp`: `static_assert(sizeof(...) == N)`, `static_assert(alignof(...) == N)`, and `static_assert(offsetof(..., field) == N)`. The TU includes only `api.h` + `<cstddef>` (no LLVM headers) and is compiled into `ry_tests` on every normal build.
- **Rust side** — `crates/emit/src/abi.rs` (the layout assertions, moved out of `lib.rs` in the #2025 split and relocated into `abi` by #2057): `const _: () = assert!(std::mem::size_of::<T>() == N)` / `align_of` / `offset_of!`. These `const _` items are const-evaluated even under `cargo check`, so CI's `lint` job exercises them via `cargo check --workspace --all-targets` (workspace scope since #2344) without building the full cdylib.

Method A was chosen over a runtime layout-probe boundary helper (e.g. `size_t ry_layout_probe(uint32_t)`) deliberately: a probe would add a new `extern "C"` symbol to the emission boundary, which collides with the parent issue's "do not extend the production emission `extern "C"` boundary surface" constraint, and it would require linking the Rust cdylib (`RY_LLVM_EMIT_IMPL_RUST=ON`) before the C++ side could call it — making "always run in CI" harder. Method A adds no boundary surface and fails fast at build / check time.

### Verification model and its residual gap

Method A locks **each language side independently** to a reviewed constant. Its guarantees:

- Incidental drift on **either** side (a reordered field, new padding, a changed type width) makes that side's `sizeof` / `offsetof` disagree with `N`, breaking that side's build. This is the realistic threat model when hand-porting the 28 function bodies in #1993 Sub-issue 3 — e.g. editing a Rust typedef is caught against the C++-derived constant.
- It does **not** compare the C++ layout against the Rust layout directly. A deliberate edit to `api.h` that also updates the C++ constant but forgets the Rust struct would leave both sides individually green while the real layouts diverge. That residual is covered by process, not mechanism: `api.h` is the locked boundary ground truth, and any change to it must update the byte-for-byte Rust mirror. Closing the gap mechanically (cbindgen / a shared source-of-truth / a runtime probe) is intentionally **not** done here — it would contradict Method A's "add no boundary surface" premise and over-engineer against the realistic drift direction.

The canonical constants below are the human-readable source of truth that a reviewer cross-checks both sides against.

## Sub-issue 3 landed (#1997 — 28 `ry_emit_*` bodies ported to Rust; shared-libLLVM link model)

`crates/emit/src/lib.rs` now implements all 28 `extern "C"` bodies via the LLVM C API (llvm-sys), byte-for-byte equivalent to `src/llvm_emit/impl.cpp` (verified: filecheck-15 identical under both backends; `ry test -p` 203/0 and `ry_tests` 2524 green with `RY_LLVM_EMIT_IMPL_RUST=ON`). The C++ impl and the flag remain (removed in Sub-issue 5). The handle ↔ `llvm-sys` cast is a plain pointer cast (`p as LLVMTypeRef`), mirroring impl.cpp's `reinterpret_cast`; the 28 functions preserve the internal call graph (`bounds_check` → `negative_index_wrap` + `bounds_error`; `cow_ensure_unique` → `arc_retain`/`arc_release`; `any_wrap` → `arc_retain`) and the three correctness rules (named↔anonymous struct sync, ARC `weak_count` Acquire-load, builder-derived parent function).

**Load-bearing build requirement — ON builds need a SHARED libLLVM.** This was a latent defect in the #1949/#1950 scaffolding, exposed only here because Sub-issue 3 is the first time the Rust side builds real IR. Linking the Rust cdylib against the static LLVM component archives gives it its own LLVM copy, distinct from the one `ry` statically links — two copies whose `APFloat` `fltSemantics` singletons live at different addresses. When the Rust side calls `ConstantFP::get` on an `LLVMContext` created by the C++ side, the `FPConstants` DenseMap empty-key check (`isEqual(bucket, EmptyKey)`) compares against the *other* copy's singleton and never matches, so `LookupBucketFor` spins forever (any float constant — e.g. json `Result<float,…>` / NaN / INF). Integer / pointer / struct paths don't depend on a per-copy singleton, so they emit byte-identical IR and pass. The fix builds BOTH sides against ONE shared `libLLVM`:

- `crates/emit/Cargo.toml`: `llvm-sys` `force-dynamic` feature → links `libLLVM.dylib` instead of static archives.
- `CMakeLists.txt`: `set(LLVM_LIBS LLVM)` under `RY_LLVM_EMIT_IMPL_RUST` → `ry` links shared `libLLVM` instead of static component libs.

**Consequence — every ON environment must ship a shared libLLVM.** CI satisfies this (`docker/ci.Dockerfile` builds LLVM with `LLVM_BUILD_LLVM_DYLIB=ON`); Homebrew `llvm@21` ships `lib/libLLVM.dylib`. The documented dev prefix `/usr/local/llvm` is **static-only** and does NOT — `cmake --preset rust-emit` (LLVM_DIR → Homebrew) is the local ON build. The OFF (C++ default) path is unaffected: it links the C++ impl into `ry`'s single LLVM (no second copy) and continues to use `/usr/local/llvm` static via `--preset default`.

- **Toolchain.** A Rust 1.83+ toolchain is required for any local build outside the Docker image (the `ry-ci` image bakes Rust in). The cdylib's internal memory is outside the C++ sanitizer instrumentation scope — see `.claude/rules/jit-teardown-suppression.md`.

### Module layout (#2025)

`crates/emit/src/lib.rs` was a single 2906-line file after the cutover; #2025 split it into per-responsibility modules. This is a **pure code move** — the emitted IR is byte-for-byte identical (verified by the filecheck goldens and an `--emit-llvm-ir` diff; the only per-run variation is the ASLR-randomized `__ry_arc_counter_address` constant, which the goldens already mask). `lib.rs` is now the crate root: the `#![allow(...)]` FFI carve-outs, the `mod` declarations, and a `pub use ffi::*` re-export (which keeps boundary-only items such as `RyBasicBlockId` / `RY_BOUNDS_ARRAY` reachable instead of dead code now that they live in a private module). The implementation lives in:

- `ffi.rs` — the locked C type contract: opaque handle types, scalar / enum typedefs, the four `Ry*Desc` descriptor structs, and the `#[repr(C)]` layout assertions.
- `support.rs` — shared internal helpers (`EmitCtx`, intern / resolve, opaque-handle casts, LLVM type constructors, name builders, module-global lookup, layout constants, the inline runtime-error / ARC-alloc helpers).
- one module per lowered-op category, each owning its `ry_emit_*` bodies: `lifecycle`, `bounds` (bounds-check / negative-index-wrap / bounds-error), `result` (build-error-from-runtime / result-branch), `option`, `arc`, `runtime_call` (generic runtime-call + runtime-fn lookup), `collection`, `cow`, `any`, `control_flow`.

The `#[no_mangle] extern "C"` boundary functions are exported from the cdylib regardless of which (private) module they live in. The three correctness rules (named ↔ anonymous struct sync, ARC `weak_count` Acquire-load, builder-derived parent function) and the internal call graph are preserved verbatim by the move. Follow-up #2026 covers the non-structural cleanup (helper dedup, Rust idiom, internal constant renames).

The same PR (#2028) also added defensive input-validation guards to `ry_emit_build_error_from_runtime`, `ry_emit_result_branch`, and `ry_emit_get_runtime_fn` — NULL handles and NULL `RyBuildValueFn` callbacks now return the sentinel (`0` / `null`) instead of dereferencing a bad handle or `unwrap`-panicking across the extern "C" boundary, mirroring the pre-existing guards in `ry_emit_runtime_call`. The CodeGen caller never passes NULL (it always supplies live handles and the `trampolineOk` / `trampolineErr` function pointers), so this is additive hardening: happy-path IR is unchanged and the filecheck goldens are byte-identical. The guard branches reachable through a supported boundary call are covered by `tests/test_emit_abi_guards.cpp`; see `.claude/rules/tests-cpp-conventions.md` for the test-vs-document split. (#2080 later extended this same guard contract to every remaining entry point — see "Boundary input-validation unified across all entry points" below.)

### Layer structure (#2057 — abi / ffi / core; arc pilot)

Building on the #2025 file split, #2057 establishes a three-layer structure inside `crates/emit/src/` and migrates **arc** as the pilot vertical slice. Like #2025 this is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a probe that exercises arc retain/release, the Any retain-guards, list-grow, CoW, Map/Set, and a runtime call; the only per-run variation is the ASLR-randomized `__ry_arc_counter_address`, normalized before diffing). The api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean) and the boundary symbols stay exported.

The layers and their one-way dependency `abi → core`:

- **`abi`** (was `ffi.rs`) — the C/C++ emission boundary, i.e. the *actual* foreign-function interface: the `#[no_mangle] extern "C"` entry points, the `#[repr(C)]` descriptors and opaque `Ry*` handle types, the layout assertions, and the plumbing that exists *because C++ calls in* — the `cx` reify (opaque handle → `EmitCtx`, confined since #2081 to the private `ctx_access` submodule and reached only via the scoped `with_ctx` / validated `checked_cx`), `intern` / `resolve` (the u32-id ↔ value bridge), the opaque-handle casts, and `cstr_bytes`.
- **`core`** (was `support.rs`) — the abi-independent IR generation engine: the concrete `EmitCtx`, the Rust-native `ValueRef` (a typed `LLVMValueRef` newtype) and `Atomicity` enum, the basic-IR type constructors, name builders, module-global lookup, layout constants, and the libc / runtime-error / ARC-alloc emitters. **`core` must not reference `abi`** (`core⇏abi`) — the title invariant. For the pilot this is enforced by convention (grep `core.rs` / `arc.rs` for `crate::abi` → empty); it becomes Cargo-enforced once the physical crate split (below) lands, because `abi` will be a separate cdylib crate that `core`'s rlib simply does not depend on. `EmitCtx` keeps its `values` intern table for now (a plain `Vec<LLVMValueRef>` with no abi type, so `core` still compiles abi-free); extracting it into an abi-side wrapper is deferred to the crate-split phase.
- **`ffi`** — the Rust-native public surface: a thin re-export of `core`'s `EmitCtx` / `ValueRef` / `Atomicity`, and the convergence point where the C++ path (via `abi`) and the Rust-direct path meet. For the pilot it is nearly empty; the layer earns its keep once an external Rust consumer and the crate split arrive. **The name `ffi` is provisional and arguably inverted** (the real foreign-function interface is `abi`); a holistic naming pass is deferred to #2022.

**arc as the pilot.** `arc_retain` / `arc_release` are now `pub(crate)` methods on `core::EmitCtx` taking the Rust-native `ValueRef` / `Atomicity` (and `Option<ValueRef>` for the nullable destructor / gc-visit callees). The C++ path enters through the `abi` `ry_emit_arc_*` externs, which resolve the u32 header id and translate the C `c_int` atomic flag (preserving the `== RY_ARC_ATOMIC`, else-non-atomic semantics exactly) before calling the method. The Rust-direct path — the Any retain-guard in `any.rs` — calls `c.arc_retain(ValueRef(hdr), Atomicity::NonAtomic)` straight, **skipping the abi id bridge** (the former `intern` → `arc_retain_impl` → `resolve` round-trip is gone; removing the redundant `intern` is IR-neutral because the id was consumed only by the immediate resolve and ids never appear in the emitted IR). The builder-derived parent-function rule and the `weak_count` Acquire-load rule are preserved verbatim.

Out of scope (deferred): extracting `values` from `EmitCtx`; the physical crate split (cdylib `abi` + rlib `ffi` + `core`); the `opt` / `profile` peer layers; and migrating the other ops (`any`, `cow`, `collection`, …) — each is a separate issue, so they remain import-re-pointed legacy modules for now.

### Layer structure follow-on (#2059 — control_flow / option / lifecycle; the `abi/` directory split)

#2059 extends the #2057 pilot to the three handle-centric ops and turns the per-op extern layout into a directory. Like #2057 it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a probe exercising an `if`-expression PHI, a `while` loop, `Some` / `None`, and a CoW list mutation; the ASLR-randomized `__ry_arc_counter_address` is normalized before diffing), the api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean), and the boundary symbols stay exported.

- **The `abi/` directory.** `crates/emit/src/abi.rs` stays the module root holding only the shared boundary primitives; each migrated op's `#[no_mangle]` externs move into a child file `crates/emit/src/abi/<op>.rs` (`arc`, `control_flow`, `option`, `lifecycle`), declared `mod <op>;` from `abi.rs`. The already-merged arc pilot's externs relocated here too, so `abi.rs` is now purely shared. `cow.rs` still calls `ry_emit_arc_retain` / `_release` by name (its own migration is #2062), so `abi.rs` keeps a `pub use arc::*` to resolve that through `crate::abi::*`; every other migrated op has no in-crate name-caller, so its child module is a plain `mod <op>;` (the cdylib exports the `#[no_mangle]` symbols regardless of module path).
- **core-role op modules.** `crates/emit/src/{control_flow,option}.rs` became `impl EmitCtx` blocks using only `core` (like `arc.rs`), so the `core⇏abi` invariant now covers `{core, arc, control_flow, option}.rs` — grep them for `use crate::abi` → empty (the lone `crate::abi` token in `core.rs` is the doc comment naming the invariant). The methods take the Rust-native handles and **return the raw `ValueRef` / `BasicBlockRef` without interning**: `intern` / `resolve` are abi-side, so the extern shell does the u32-id bridge on the way in and out. That forced split is exactly what keeps the engine method abi-free.
- **Minimal handle vocabulary.** `core` gains exactly the three newtypes the migrated ops need — `BasicBlockRef` / `FunctionRef` / `TypeRef`, next to `ValueRef`. `FuncTypeRef` and the module / builder / context handles are intentionally **not** added: an unused newtype trips the `cargo clippy -- -D warnings` dead-code gate, and the next op-migration issue adds whichever it needs. SSA-name params stay `*const c_char` to match the existing `core` convention (`emit_malloc` etc.) rather than `&CStr`.
- **lifecycle is IR-free.** Its only core part is the `EmitCtx` constructor, so `EmitCtx::new` (taking the raw `LLVM*Ref` handles) landed in `core.rs` next to the struct and `src/lifecycle.rs` was removed; the four externs are boundary plumbing in `abi/lifecycle.rs`. Behaviour is preserved verbatim, including the absence of a NULL-ctx guard on the non-`destroy` entries — hardening (as added for arc in #2058) is a separate follow-up, not part of a pure relocation. (That follow-up landed in #2080: `ctx_set_function` / `intern` / `resolve` gained a `ctx.is_null()` guard; `ctx_set_function` was then removed in #2083 as unused, leaving `intern` / `resolve`.)

The op-migration pattern the remaining sub-issues (#2060–#2063: `bounds` / `result` / `runtime_call` / `collection` / `cow` / `any`) reuse — the `abi/` split, the extern↔method shape, the `core⇏abi` grep, the IR-bit-exact recipe, and the behaviour-preservation rules — is recorded in the #2059 design comment. Out of scope here (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers, and `ffi` re-exporting the new handle newtypes (no Rust-direct consumer yet).

### Layer structure follow-on (#2060 — bounds / result / runtime_call; callback / arg-buffer / error-global ops)

#2060 reuses the #2059 pattern for the three mid-size ops that carry a callback, a variable-length arg buffer, and a shared error-message global. Like its predecessors it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a probe exercising a `List<int>` index (List-kind bounds), a fixed `i32[4]` index (Array-kind bounds), `convert.int` (the `result_branch` + `build_error_from_runtime` Result path), `print` / `len` runtime calls, and `list.sort` (the `__ry_timsort` `get_runtime_fn` path), each marker coverage-gated in the baseline before the ASLR-normalized diff, plus all 15 filecheck fixtures byte-identical), the api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean), and the boundary symbols stay exported. The guards added in #2028 stay abi-side, so `tests/test_emit_abi_guards.cpp` is unchanged.

- **bounds.** The three functions become `EmitCtx` methods. `bounds_check` calls `self.negative_index_wrap` / `self.bounds_error` directly — the former `intern` → extern → `resolve` id round-trip is gone (IR-neutral; ids never appear in the emitted IR). `abi.rs` keeps a `pub use bounds::*` because legacy `collection.rs` still calls `ry_emit_negative_index_wrap` / `_bounds_error` through `crate::abi::*` (its migration is #2061), mirroring the arc↔cow arrangement. `cstr_bytes` moved from `abi.rs` to `core.rs` (a pure `CStr` primitive, re-exported from `abi` for `any.rs`): bounds is the first migrated op to build prefix-derived SSA names in `core`, so it is the first to need it there. The new `BoundsKind { List, Array }` enum replaces the `c_int` kind at the engine boundary (the abi shell maps `RY_BOUNDS_LIST` → `List`, else `Array`).
- **result (asymmetric split).** `build_error_from_runtime` is a clean core method + thin shell. `result_branch` deliberately keeps its full orchestration in `abi/result.rs` with `RyBuildValueFn` staying `Option<fn>`. Two independent reasons forbid moving it into a `&mut self` core method: its ok/err builders return interned `RyValueId`s that only `resolve` (abi-side) can turn back into values; and wrapping the callback to pass into a `&mut self` method would re-enter `cx(ctx)` and create a second `&mut EmitCtx` aliasing the receiver across the extern call (UB under Stacked/Tree Borrows). So `result` is the one op whose core-role module (`result.rs`) holds only part of the op. `abi.rs` declares `mod result;` with no `pub use` (no in-crate name-caller). (**#2069 later resolves this asymmetry** — a closure-delegating free function moves the IR into `core` without a `&mut self` borrow; see the #2069 follow-on below.)
- **runtime_call.** `runtime_call` takes the Rust-native typed slices `&[TypeRef]` / `&[ValueRef]`; the abi shell owns the boundary validation (NULL / count-mismatch / per-element NULL → sentinel), the `from_raw_parts` borrow, and the id-resolve / type-translate into those slices. `get_runtime_fn` takes the new `FuncTypeRef` newtype (boundary-symmetric with `RyFuncTypeRef`, used here so it is not dead code) and returns a `FunctionRef` that the shell hands back **un-interned** — the one migrated entry point that returns a raw `RyValueRef` rather than a `RyValueId`.

This leaves `collection` / `cow` / `any` as the only legacy modules; their migration is #2061–#2063. **Reusable trap for those**: a migrating op must relocate any abi-side helper it still uses (as bounds did with `cstr_bytes`) down into `core` alongside its methods — the core-role module compiles abi-free, so it cannot reach back into `abi` for a shared primitive. Out of scope here (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers, and `ffi` re-exporting the new `FuncTypeRef` / `BoundsKind` (no Rust-direct consumer yet).

### Layer structure follow-on (#2061 — collection; append / insert / removeAt / slice)

Sub-issue #2061 migrates `collection`, the largest scalar / handle op group (four externs, the shared list-grow, and the `slice` out-params). Like its predecessors it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a single probe exercising `append!` (grow → `cap_gt4` / `app.grow`), `insert` (shift → `ins.move`, the grow-name asymmetry → `ins_doubled`), `removeAt` (`rmat_val` / `rmat.ok`), and `slice` (`sl_count` / `sl_diff`), each marker coverage-gated in the baseline before the ASLR-normalized diff, plus all 15 filecheck fixtures byte-identical), the api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean), and the boundary symbols stay exported.

- **All four become `EmitCtx` methods.** `insert` / `remove_at` call `self.negative_index_wrap` / `self.bounds_error` directly — the former `intern` → extern → `resolve` id round-trip is gone (IR-neutral; ids never appear in the emitted IR), the same collapse #2060 did in `bounds_check`. No new newtype is needed (the methods use the existing `ValueRef` / `TypeRef`), and no helper relocation is needed (every primitive `collection` uses — `emit_malloc` / `emit_memcpy` / `emit_memmove` / `load_list_header` / `emit_list_grow` — already lives in `core`, so the #2060 `cstr_bytes` trap does not bite). `abi.rs` declares `mod collection;` with no `pub use` (no in-crate name-caller). The `emit_list_grow` `cap > 4` name asymmetry (named `cap_gt4` in append, unnamed in insert) is preserved verbatim; the deeper method nesting changes only source layout (rustfmt wraps the long `.as_ptr()` lines), not the emitted SSA names.
- **`slice` is the crate's first multi-value engine return.** The method returns a named `SliceParts { count, new_data }` struct (in `core.rs`, next to `ValueRef`) rather than a bare `(ValueRef, ValueRef)`, so the two same-typed handles cannot be silently transposed where the abi shell interns each into its `*mut RyValueId` out-param. The extern keeps its api.h-locked out-param signature — the tuple-vs-struct choice is purely the internal engine return.
- **`pub use bounds::*` removed.** `collection` was the last in-crate caller of the `bounds` externs (`ry_emit_negative_index_wrap` / `_bounds_error`); now that it calls them as engine methods, the re-export #2060 kept in `abi.rs` for exactly this caller is dropped (`mod bounds;` only). The `#[no_mangle]` bounds symbols stay exported for C++ — this completes the "drop the re-export once the last in-crate caller migrates" pattern (mirroring arc↔cow).

This leaves `cow` / `any` as the only legacy modules; their migration is #2062–#2063. No new NULL guards were added (a behaviour-preserving relocation; `collection` takes only resolved handles, so the callback / deref-string rationale that justified `result.rs`'s guards does not apply — hardening stays a separate follow-up). (#2080 added that hardening — `checked_cx` + `resolve_value` + type-handle and out-param guards.) Out of scope here (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers, and `ffi` re-exporting the new handle types (no Rust-direct consumer yet).

### Layer structure follow-on (#2062 — cow; the descriptor-passing pattern)

Sub-issue #2062 migrates `cow` (`ry_emit_cow_ensure_unique`), the first **descriptor-taking** op to cross the boundary, and so it establishes the descriptor-passing pattern that #2063's `any` reuses for its three descriptors. Like its predecessors it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a probe that shares-then-mutates a `List<str>` (elem retain loop → `cow.elem_loop`), a `Map<str, str>` (value retain → `cow.elem_loop` on field 3 **and** key retain → `cow.key_loop` on field 2), and a `Set<str>` (elem retain → `cow.elem_loop`), each marker coverage-gated in the baseline before the ASLR-normalized diff, plus all 15 filecheck fixtures byte-identical), the api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean), and the boundary symbols stay exported.

- **Descriptor passing: C struct → Rust-native struct.** The abi shell (`abi/cow.rs`) maps the 12-field C `RyCowEnsureUniqueDesc` into a Rust-native `CowEnsureUnique` and calls `self.cow_ensure_unique(&d)`. Field expansion (12 positional args, ⑤'s `any` reaches 14) was rejected — it overshoots the `clippy::too_many_arguments` threshold and does not scale. The split of the two new types mirrors the cross-op-vocab-vs-op-bundle distinction: the `CowKind` enum goes in `core.rs` next to `BoundsKind` (a reusable scalar vocabulary the boundary maps `c_int` into), while the `CowEnsureUnique` **bundle** lives in `cow.rs` co-located with its sole consumer (the method) — keeping `core.rs` lean as `any` adds three more descriptor structs. The shell does every C→core conversion (kind→`CowKind` validated, `atomic`→`Atomicity`, the four flags→`bool`, the two ids→`ValueRef` via `resolve`, `destructor_callee`→`Option<ValueRef>`) and holds every guard (null ctx/desc/handles, invalid kind) returning 0 at the boundary, so the engine method takes only validated core vocabulary and its `CowKind` match is exhaustive — the legacy body's two `_ => return 0` dead arms are gone. **`any` inherits this struct-in-its-own-module placement.**
- **Direct arc calls.** `cow_ensure_unique` and its `cow_retain_loop` helper become `EmitCtx` methods; the element/key retains call `self.arc_retain` and the old-header release calls `self.arc_release` directly — the former `intern` → extern → `resolve` id round-trip (3 sites: the retain loop invoked for elem + key, plus the release) is gone (IR-neutral; ids never appear in the emitted IR), the same collapse #2060/#2061 did in `bounds`/`collection`. No helper relocation is needed (every primitive `cow` uses — `emit_malloc` / `emit_memcpy` / `emit_atomic_i64_load` / `emit_arc_counter_delta` / `cname3` / `arc_header_type` — already lives in `core`, so the #2060 `cstr_bytes` trap does not bite). `cow_retain_loop` keeps its `#[allow(clippy::too_many_arguments)]` (`self` + 8 args; bundling the cached LLVM types is the asymmetry its comment rejects). The builder-derived-parent rule is preserved across the `&mut self` conversion.
- **`pub use arc::*` removed.** `cow` was the last in-crate caller of the `arc` externs (`ry_emit_arc_retain` / `_release`); now that it calls them as engine methods, the re-export #2059 kept in `abi.rs` for exactly this caller is dropped (`mod arc;` only). The `#[no_mangle]` arc symbols stay exported for C++ — completing the "drop the re-export once the last in-crate caller migrates" pattern (the same cleanup #2061 did for `pub use bounds::*`). No in-crate module now calls another op's externs by name.

This leaves `any` as the only legacy module; its migration is #2063, which reuses this descriptor-passing pattern (struct mapping at the shell, exhaustive core match) for `RyAnyWrapDesc` / `RyAnyUnwrapDesc` / `RyAnyTryUnwrapDesc`. No new NULL guards were added (a behaviour-preserving relocation; the existing guards moved abi-side unchanged — hardening stays a separate follow-up). (#2080 retrofitted `any` / `cow` onto the shared `checked_cx` + `resolve_value` helpers as part of the boundary-wide unification.) Out of scope here (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers, and `ffi` re-exporting the new `CowKind` (no Rust-direct consumer yet).

### Layer structure follow-on (#2063 — any; the series finale)

Sub-issue #2063 migrates `any` (`ry_emit_any_wrap` / `_unwrap` / `_try_unwrap`), the **largest** and **last** legacy op — three externs over three descriptors (`RyAnyWrapDesc` / `RyAnyUnwrapDesc` / `RyAnyTryUnwrapDesc`), reusing the #2062 descriptor-passing pattern. Like every predecessor it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a single probe exercising all eight kind-paths — wrap NonBox (`any.bool.zext`) / RecordBox (`any.rec.fields.slot`) / EnumBox (`any.enum.payload.slot`), unwrap Standard (`any.tag.check`) / F64Promote (`any.int2float`) / Record (`any.rec.tag_ok`), try_unwrap Standard (`tryany.tag.eq`) / F64Promote (`tryany.fp.is_accept`) — plus both retain guards (`arc_hdr_from_data` and `str_hdr_from_data`), each marker coverage-gated in the baseline before the ASLR-normalized diff, and all 15 filecheck fixtures byte-identical), the api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean), and the boundary symbols stay exported.

- **Three descriptors, three kind enums.** Each extern maps its C descriptor into a Rust-native `AnyWrap` / `AnyUnwrap` / `AnyTryUnwrap` (co-located in `any.rs` with the methods, the #2062 bundle placement) and the `c_int` kind into a dedicated `AnyWrapKind` / `AnyUnwrapKind` / `AnyTryUnwrapKind` enum in `core.rs` next to `CowKind` / `BoundsKind`. The kind mapping folds the legacy `kind > N` reject into its `None → 0` arm, so each engine method's kind match is exhaustive. The message / global-name fields stay `*const c_char` (the #2059 name convention), so the descriptor structs are Copy / lifetime-free and the method calls `cstr_bytes` at the point of use.
- **Thin shell + fallible core (the new wrinkle).** Unlike `cow`'s flat 2-pointer validation — which let `cow_ensure_unique` be infallible with every guard in the shell — `any`'s guards are *branch-nested* (`box_layout_ty` / `descriptor` for RecordBox/EnumBox wrap, `record_struct_ty` / `expected_desc` for Record-unwrap, `target_ty` for the Standard arms). So the three methods return `Option<ValueRef>`: the shell holds the kind-independent guards (null ctx/desc/handles) + the kind mapping and interns `None → 0`, while the branch-specific guards stay *in the method at their original positions* (`let Some(x) = … else { return None }`, or `d.target_ty?` for the single Standard handle). Keeping them in place is what makes the relocation byte-identical even on error paths — a guard that fired after a `tag = ExtractValue` in the legacy body still emits that (dead) instruction before returning, exactly as before; pushing it shell-side would have changed the error-path IR.
- **`try_unwrap`'s ok/err builders stay inline closures.** They capture only Copy LLVM refs (`b` / `res_ty` / `error_ty` / `i1_ty` / `i64_ty` / `err_msg_str`), never `self`, so — unlike `result_branch`'s re-entrant `RyBuildValueFn` C callbacks (#2060), which alias `cx(ctx)` and force `result` to keep its orchestration abi-side (**until #2069**, which delegates to a borrow-free `core` free function instead of a `&mut self` method — see below) — `any_try_unwrap` migrates fully into the `&mut self` method with the closures living inside it.
- **Retain guard + cleanups.** `emit_any_retain_guard` becomes a private `&mut self` method calling `self.arc_retain` directly (`any` was already converged onto `arc_retain` as a method in #2057, so no extern round-trip remained to collapse). `any` was the last in-crate `use crate::abi` consumer, so `abi.rs` drops its dead `pub(crate) use crate::core::cstr_bytes` re-export (kept only for the legacy `any.rs`); `ffi`'s `EmitCtx` / `ValueRef` / `Atomicity` re-export — whose last incidental consumer was that same legacy `any.rs` — is retained as the documented Rust-native surface (annotated `#[allow(unused_imports)]`) pending #2022.

This completes the #2057 series: every op now has its externs in an `abi/<op>.rs` shell over a core-role `impl EmitCtx`, and **no module outside the `abi/` children references `crate::abi`** (`core⇏abi` holds for all ten core-role modules — `any` / `arc` / `bounds` / `collection` / `control_flow` / `cow` / `option` / `result` / `runtime_call` / `core`). Out of scope (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers, and `ffi` growing a real Rust-direct consumer.

### Layer structure follow-on (#2069 — result_branch; the abi-IR-zero finale + CI gate)

The #2057 series moved every op's externs into an `abi/<op>.rs` shell, but one function still built LLVM IR directly *inside* that shell: `result_branch` (27 of 28 functions delegated all IR to `core`; `result_branch` was the lone holdout). #2060 left it abi-side because its re-entrant `RyBuildValueFn` callbacks would alias `cx(ctx)` under a `&mut self` method (above). #2069 closes that last asymmetry, so `crates/emit/src/abi/**` emits **zero** IR. Like its predecessors it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an `--emit-llvm-ir` diff over a `convert.int` probe exercising the ok/err/merge path — `res.ok` / `res.err` / `res.merge` / `%result` coverage-gated in the baseline before the ASLR-normalized diff, plus all 15 filecheck fixtures byte-identical), the api.h C surface is unchanged (`scripts/check-llvm-emit-abi-header.sh` clean, the `EmitAbiGuardTest` `ResultBranch*` guards still pass), and the boundary symbols stay exported.

- **Closure delegation, not a `&mut self` method.** The IR (BB scaffold + cond-br + merge phi) moves into a `core` free function `emit_result_branch(builder, context, is_err, res_ty, build_ok, build_err)` that takes the two value builders as `&mut dyn FnMut() -> ValueRef` closures plus the **decomposed** `builder` / `context` Copy handles — deliberately **not** `&mut self` and **not** a raw `*mut EmitCtx`. Holding no `&mut EmitCtx` borrow, it invokes the re-entrant builders without aliasing the `cx(ctx)` borrow each closure forms on re-entry. This is the option the #2060 analysis did not take: it keeps the re-entrant callback (so each arm's value is still built inside its BB) while relocating the IR, preserving the **exact live-borrow timeline** of the original abi free function — which was already ASan/TSan-clean, so the relocation is too. The abi shell (`abi/result.rs`) wraps each C `RyBuildValueFn` into a closure that calls the callback **then** resolves the returned id (the two-step body is load-bearing: inlining `resolve(cx(ctx), build_ok(user_ctx))` would hold the `cx(ctx)` borrow across the callback, since args evaluate left-to-right), and interns the returned phi. `result.rs`'s core-role module now holds the **whole** op — the "holds only part" exception #2060 documented is gone. The free function (not a `&mut self` method) keeps the builder-derived-parent rule (#1968): a NULL insert block yields a NULL `ValueRef` that the shell interns to 0, preserving the sentinel behaviour.
- **A CI gate locks the invariant.** A new `scripts/check-emit-abi-no-ir.sh` (wired into the `ci.yml` `lint` job alongside the api.h header lint, and into `run-rust-lint.sh` for local repro) greps `crates/emit/src/abi.rs` + `abi/**` for IR-generation symbols — `LLVMBuild[A-Z]` (the `LLVMBuilderRef` *type* is excluded: its 10th char is a lowercase `e`, so the `[A-Z]` class does not match), `LLVMAppendBasicBlock*` / `LLVMPositionBuilder*` / `LLVMAddIncoming` / `LLVMGetInsertBlock` / `LLVMGetBasicBlockParent` — and the `llvm_sys::core` path (substring, catching both `use` and fully-qualified calls), while allowing `use llvm_sys::prelude` (the legitimate type-cast handles in `abi.rs` / `abi/lifecycle.rs`). Comment lines are stripped first so prose naming an IR symbol does not trip it. This is the same enforcement culture as the api.h header lint and the layout asserts: the abi shell stays mechanical-translation-only as the migrated-op surface grows (#2023), keeping a future pure-Rust library (abi removal) a mechanical sweep rather than a logic port.

With `result_branch` migrated, **every** `crates/emit/src/abi/**` file is IR-free — the abi layer is a pure C-boundary shell, and the gate prevents regression. Out of scope (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers, and `ffi` growing a real Rust-direct consumer.

### Internal header layout drift guard (#2071)

The "Named ↔ anonymous struct sync" steady-state constraint (above) — the cdylib rebuilding CodeGen's `listHeaderTy_` / `mapHeaderTy_` / `setHeaderTy_` / `arcHeaderTy_` so the emitted aggregates match the rest of CodeGen — was, until #2071, protected only by a `// Field order MUST stay in sync` comment in `crates/emit/src/composite/cow.rs` / `crates/emit/src/context.rs`. That is weaker than the boundary-descriptor case: `tests/test_abi_layout.cpp` pins the `Ry*Desc` descriptors (Method A above), but **nothing** pinned the internal headers. A C++ field-order change the Rust mirror failed to follow would compile, pass `test_abi_layout.cpp`, pass the filecheck goldens (which don't emit the CoW Map/Set deep-copy paths — see `.claude/rules/codegen-llvm-ir-conventions.md`), and only corrupt CoW deep-copy at runtime.

#2071 closes this with two mechanical guards. Unlike the #1995 boundary-descriptor residual gap — which deliberately left the C++↔Rust comparison to process, to "add no boundary surface" — here the comparison is done **directly**, because the internal headers had no layout coverage at all:

- **Single source + cross-language parity test.** The header field-kind list is defined once in `crates/emit/src/context.rs` `header_fields`, driving both `build_header_struct` for emission and the test-only `ry_emit_test_header_layout` extern (`crates/emit/src/abi/test_introspect.rs`). `tests/test_header_layout.cpp` reads the canonical `cg.*HeaderTy_` from a real `CodeGen` and asserts field count + per-index type + ABI size against the extern's report, plus a permanent negative test that the comparator rejects a permuted layout. A Rust-only self-check would be insufficient (each side validating its own constants misses a C++-only reorder) — the same "compare directly, don't self-check" lesson as the #1995 note. The extern reads only the pure-data `header_fields` slice, never `build_header_struct`, so `crates/emit/src/abi/test_introspect.rs` stays clear of the `scripts/check-emit-abi-no-ir.sh` gate.
- **Behavioral same-type-swap coverage.** Every header field is 8 bytes (i64 / ptr), so a same-type swap (`len↔cap`, `keys↔vals`, `strong↔weak`) is invisible to any layout/offset check; `tests/spec/cow.test.ry` exercises the deep-copy and reads back lengths **and** values (run under ASan, a `keys↔vals` / `elems↔buckets` swap also trips the str retain loop on a non-pointer field). Harmful same-type swaps are exactly the behaviorally-catchable ones; symmetric swaps round-trip and are benign. ARC's `strong↔weak` is covered by the existing dense ARC behavioral suite rather than a new test.

The single-sourcing is a **pure refactor** — the emitted IR is byte-for-byte identical (`build_header_struct` produces the same literal struct as the previous inline `LLVMStructTypeInContext` calls), so the api.h C surface is unchanged and the boundary descriptors (`RyCowEnsureUniqueDesc`) are untouched.

### Boundary input-validation unified across all entry points (#2080)

The #2028 guards (above) hardened only four entry points (`runtime_call` / `build_error_from_runtime` / `get_runtime_fn` / `result_branch`); a review of the migrated boundary found the rest applied input validation inconsistently. `control_flow` / `collection` / `bounds` / `option` and part of `lifecycle` passed unvetted values straight through to the `core` engine, which forwards them to the LLVM C API — so a NULL ctx, a NULL FFI array (`create_phi`'s parallel incoming buffers, raw-deref'd via `*ptr.add(i)`), a NULL out-param (`list_slice`'s `*out_count` / `*out_new_data`), or an id resolving to a NULL handle (`arc_retain` / `arc_release`'s header) reached undefined behavior immediately. #2080 closes this so **every** production entry point shares one boundary contract: malformed input becomes a sentinel (`0` / NULL) or a no-op rather than crossing into IR emission. This is the deferred "hardening as a separate follow-up" referenced by #2058 (lifecycle), #2061 (collection), and #2062–#2063 (cow / any).

- **Three shared helpers** (`crates/emit/src/abi.rs`) fold the per-op inline guard sequences that #2028's four spelled out: `checked_cx` (ctx + `context` / `module` / `builder` NULL → `None`), `resolve_value` (id → `Option<ValueRef>`, `None` when it resolves to the sentinel — subsuming `any.rs`'s former `opt_value_id`), and `ffi_slice` (the `(ptr, count)` borrow that maps an empty count to an empty slice without touching the pointer and rejects a NULL base for `count > 0`). The previously-validated entry points were retrofitted onto the same helpers so the contract is expressed once; `runtime_call` thereby also gains a `context`-NULL check (it previously checked only module / builder — IR-neutral, since `ctx_create` always stores all three together).
- **`result_branch` keeps its inline guards.** It is the lone re-entrant entry point (its `RyBuildValueFn` ok / err callbacks re-enter the emitter); routing its borrow through `checked_cx`'s `&mut EmitCtx` would risk the cross-FFI aliasing the #2069 note above warns about, so its field extraction stays inline rather than going through `checked_cx`. (#2081 later routed that inline extraction through the scoped `with_ctx` accessor — see "`cx` reify confined" below — but it still does not hold a whole-body `checked_cx` borrow across the callbacks.)
- **The pure-plumbing entries** that emit no IR (`intern` / `resolve`) guard only `ctx.is_null()` — they touch none of the three LLVM handles, so the `checked_cx` three-field check would be over-strict (since #2081 they reify via `with_ctx` after that NULL guard).
- **IR-neutral by construction**: the guards fire only on malformed input and the helpers emit no IR, so happy-path output is unchanged (the `scripts/check-emit-abi-no-ir.sh` gate stays green and the filecheck goldens are byte-identical). The reachable guard branches — ctx-NULL per entry point plus the `create_phi` NULL-array, `list_slice` NULL-out-param, and `arc` NULL-header cases — are locked in `tests/test_emit_abi_guards.cpp`; the inner `c.module` / `context` / `builder == NULL` guards need a corrupted ctx and stay documented-only per `.claude/rules/tests-cpp-conventions.md`.

### `cx` reify confined to a single accessor (#2081)

The reify `cx(p: *mut RyEmitCtx) -> &'a mut EmitCtx` minted a `&mut EmitCtx` whose lifetime `'a` was caller-chosen and unconnected to the source pointer — so two `cx(ctx)` calls produced two aliasing `&mut` the borrow checker could not reject (the `'a` is unconstrained). The re-entrant `result_branch` path was the live hazard: its ok / err callbacks re-reify on each arm, and the non-alias property was held only by a comment about left-to-right argument evaluation (a single `resolve(cx(ctx), build_ok(user_ctx))` would have held the borrow across the callback). #2081 confines the reify without changing the C ABI or any emitted IR — a pure refactor.

- **Single audited reify site.** `cx` moves into a private `ctx_access` submodule of `crates/emit/src/abi.rs` with **no `pub`** (not even `pub(super)`, which would re-expose it to the whole `abi` subtree). The op / `result` / `lifecycle` modules are *siblings* of `ctx_access`, not descendants, so they can no longer name `cx` — a stray `cx(ctx)` is a compile error. The module exports only two accessors: `with_ctx(p, |c| …)` (scoped — the `&mut EmitCtx` is bound to the closure body and cannot escape) and `checked_cx` (the validated whole-body accessor, unchanged).
- **`result_branch` / `lifecycle` reify via `with_ctx`.** `abi/result.rs`'s up-front handle extraction, the two re-entrant closures, and the final phi intern each go through a `with_ctx` whose borrow ends with the closure; the C builder runs *outside* any `with_ctx`, so no borrow spans the callback **by construction** rather than by evaluation-order subtlety. `abi/lifecycle.rs`'s `intern` / `resolve` reify via `with_ctx` after their existing `ctx.is_null()` guard (`with_ctx` itself does not NULL-check). The non-re-entrant op modules keep `checked_cx` unchanged — they are whole-body, never re-enter, and are already encapsulated behind that boundary helper.
- **Confined, not alias-proof.** This is the deliberate scope: `checked_cx` still returns an escaping `&mut`, and nesting two `with_ctx` on one handle (or raw-casting the `&mut` out of the closure) still aliases. The guarantee is "the reify is one greppable site and each borrow scope is lexically visible", which makes the residual alias paths locally auditable — not a type-level impossibility proof. `&mut`-aliasing is a Stacked/Tree Borrows violation that ASan / TSan / an IR diff cannot detect, and Miri cannot run this crate (it calls native libLLVM through `llvm-sys`); the no-borrow-across-callback property is therefore discharged structurally (`core::emit_result_branch` holds no `&mut EmitCtx`), not by a test.
- **`unsafe_op_in_unsafe_fn` evaluated, deferred.** The scoped accessor already shrinks the *alias-relevant* unsafe (the raw reify) to one audited helper — the audit-unit reduction this work targeted. A crate-wide `unsafe_op_in_unsafe_fn` is orthogonal: it would force `unsafe { … }` on every `resolve` / `intern` / FFI cast / `from_raw_parts` across a uniformly-unsafe boundary (noise, not signal for the `cx` risk), and is left to a separate evaluation of its own granularity (crate vs file vs `extern "C"` fn). One narrow consequence did land here: a lexical `unsafe { … }` block reaches into a nested closure (an `unsafe fn`'s implicit body-unsafe does not), so the `with_ctx` closures sit inside an explicit `unsafe` block and carry no inner `unsafe`.
- **IR-neutral by construction.** `with_ctx` / `checked_cx` / `cx` emit no IR and import no `llvm_sys::core` path, so `scripts/check-emit-abi-no-ir.sh` stays green. Verified byte-identical via an ASLR-normalized `--emit-llvm-ir` diff over a probe exercising both Result arms through `.andThen()` / `.map()` (coverage-gated on the `res.ok` / `res.err` / `res.merge` scaffold in the baseline) plus the `result_wrap` filecheck fixture. (`any_try_unwrap` builds its own Result branch inline and does not call `emit_result_branch`, so it is untouched by this change.)

### Scalar primitive op surface (#2072 — [C] = (ii) boundary move)

Every op group above moved a *coarse* lowered op (BoundsCheck, CowEnsureUnique, AnyWrap, …) across the boundary while keeping low-level primitives (arithmetic, integer comparison, Alloca / Load / Store) as a deliberate **C++ carve-out** — the (i) "semantic boundary" hypothesis recorded in `codegen-layering-plan.md` §"Explicit non-inclusion". #2072 records the until-then-unrecorded architecture decision **[C] = (ii) boundary move** (that document is an explicitly revisable working hypothesis, and #2072 was chartered to decide the direction): the emission layer owns *every* `IRBuilder<>::Create*`, so the primitives this carve-out reserved for C++ now cross the boundary too. The decision, its trade-off (physical vs semantic boundary; complete C++/LLVM separation vs a near-1:1 ≤10-op vocabulary), and its installment-#1 scope are recorded additively in `codegen-layering-plan.md`; this is the boundary surface.

- **Eleven fine-grained primitive entries**, each wrapping a single `LLVMBuild*` / `LLVMConstInt`: `ry_emit_alloca` / `_load` / `_store` / `_gep` / `_icmp` / `_and` / `_or` / `_add` / `_sub` / `_select` / `_const_int` (+ a `RyICmpPred` predicate enum). The engine methods live in `crates/emit/src/primitive/ops.rs` (a core-role `impl EmitCtx`, `core⇏abi`), the `#[no_mangle]` shells in `crates/emit/src/abi/primitive.rs`. The shells are pure mechanical translation (resolve ids, map `c_int` predicate → the `core::IcmpPred` vocabulary, intern the result), so `scripts/check-emit-abi-no-ir.sh` stays green; the api.h header lint (`scripts/check-llvm-emit-abi-header.sh`) stays green (no `llvm::*` / `void *` in the new signatures). Unlike the coarse ops there is **no `lowered_*` struct layer** — a primitive has no lowering-side semantic decision (the same reasoning that gave ControlFlow none). Runtime-symbol calls (`__ry_string_make_uninit`, `memcpy`) reuse `ry_emit_runtime_call`; `SetInsertPoint` / `GetInsertBlock` stay direct (builder-state, no IR).
- **First consumers: the five string byte-ops.** `toUpper` / `toLower` / `trim` / `trimStart` / `trimEnd` (and the shared `emitIsWhitespace`) in `src/codegen_call_string.cpp` now emit their inline loop bodies entirely through CodeGen-side wrappers (`emitAlloca` / `emitLoad` / `emitICmpSLT` / `emitConstInt` / …, declared in `include/ry/codegen.hpp`) that hide the intern → `ry_emit_*` → resolve hop — so those functions carry **zero** `builder_.Create*`. Like every predecessor it is a **pure refactor**: the emitted IR is byte-for-byte identical, verified by an ASLR-normalized `--emit-llvm-ir` diff over a probe exercising all five ops, with each op's markers (`upper_buf` / `is_lower_a`, `lower_buf` / `is_upper_a`, `trim_safe_len` / `final_start`, `tstart_rlen`, `tend_final`) coverage-gated in the baseline first (the `#2026` discipline in `.claude/rules/codegen-llvm-ir-conventions.md`).
- **Installment #1, not complete separation.** This establishes the primitive vocabulary and the bit-exact migration discipline on five ops only; CodeGen still threads `llvm::Value*` through the wrappers, orchestrates the loops, and obtains `len` from the shared `emitStringByteLen` (which still emits `Create*`). The full-codebase sweep and the migration of shared helpers are future work. Out of scope (unchanged from #2057): the physical crate split, the `opt` / `profile` peer layers.

### New op migration (#2092 — reduce: sum / min / max)

#2092 migrates the numeric reduce builtins `sum` / `min` / `max` from inline `builder_.Create*` in `src/codegen_call_higher_order.cpp` into the crate — the first **new** op added since the #2059–#2069 series moved the original lowered-op vocabulary across, and the ARC-independent "safest batch" (following the #2072 string-op pilot). Like its predecessors it is a **pure refactor** — the emitted IR is byte-for-byte identical (verified by an ASLR-normalized `--emit-llvm-ir` diff over a coverage-gated probe set: sum list i64/f64/i8, sum variadic i64/f64/i8, min/max list i64/f64 with the empty-list error block, min/max variadic i64/f64 — each shape's marker grep-confirmed in the baseline before the diff), the api.h C surface gains only the four new declarations (`scripts/check-llvm-emit-abi-header.sh` / `scripts/check-emit-abi-no-ir.sh` clean), and the boundary symbols are exported.

- **Op set splits by shape.** `crates/emit/src/composite/reduce.rs` holds four `impl EmitCtx` methods; `crates/emit/src/abi/reduce.rs` holds their resolve / intern shells. The **list forms** (`ry_emit_reduce_sum_list`, `ry_emit_reduce_minmax_list_loop`) emit a whole accumulate loop; the **variadic forms** (`ry_emit_reduce_sum_step`, `ry_emit_reduce_minmax_step`) emit one fold step the C++ loop drives per argument. A single "fold the pre-evaluated array" op would bunch the operand loads ahead of the arithmetic (the inline C++ interleaves `emitExpr(arg[i])` with each accumulate), so the per-step shape is what keeps the IR byte-exact.
- **`minmax_list_loop` is deliberately partial.** The empty-list guard + `emitRuntimeError` stay C++-side because `emitRuntimeError` builds an ARC string global (`cachedGlobalString`), out of scope for the ARC-free batch — porting it would import ARC-string-global machinery through the very batch chartered to have zero ARC entanglement. The C++ side keeps `loadListHeader` + the `mm_empty` check, positions the builder at `mm.ok`, and the boundary emits only the `mm_first` seed + loop. `sum_list` has no empty-list error (sum of `[]` is 0), so it loads the header in Rust and is a whole-op migration. The asymmetry is intentional — the first op split between C++ and Rust for an ARC-dependency reason rather than the re-entrant-callback reason that kept `result_branch` abi-side (#2060).
- **12 boundary-input guards.** `tests/test_emit_abi_guards.cpp` gains the ctx-NULL / resolve-None / NULL-elem-type cases for all four entries (the #2080 contract — every entry returns the sentinel 0 on malformed input).

### Function-creation capability (#2098 — [A] = (ii) boundary move, generic primitives)

Every op above (coarse or primitive) operated *inside* a function the C++ side already had open — `ry_emit_create_basic_block` takes an explicit parent handle, and the parent itself could only be made by C++'s `llvm::Function::Create`. #2098 records the *capability* decision (orthogonal to #2072's *style* decision; see `codegen-layering-plan.md`) to move that function-CREATION mechanism into the emission layer, via **(ii) boundary move with generic primitives** rather than a coarse semantic `ry_emit_iter_take_next` op (which would leak Ry-level iterator semantics and need one bespoke `core` fn per `Function::Create` site). This is distinct from the `RuntimeCall` / `get_runtime_fn` *declaration* path (`getOrInsertFunction` of an external symbol): these create a new *definition* that then receives a body.

- **Five generic primitive entries.** `ry_emit_create_function` (`LLVMAddFunction` + `LLVMSetLinkage` — the `Function::Create` equivalent; returns a raw `RyFunctionRef`, not interned, like `create_basic_block`'s `RyBasicBlockRef`; + a `RyLinkage` enum), `ry_emit_get_param` (`LLVMGetParam`), `ry_emit_struct_gep` (`LLVMBuildStructGEP2` — the compile-time field-index GEP, distinct from `ry_emit_gep`'s single runtime i64 index), `ry_emit_call_indirect` (`LLVMBuildCall2` through a loaded fn-pointer *value*, distinct from `ry_emit_runtime_call`'s name-keyed `getOrInsertFunction`), and `ry_emit_ret` (`LLVMBuildRet` / `LLVMBuildRetVoid`). Engine methods: `create_function` / `get_param` / `call_indirect` in the new `crates/emit/src/primitive/function.rs`, `build_struct_gep` in `primitive/ops.rs`, `build_ret` in `primitive/control_flow.rs` (all core-role `impl EmitCtx`, `core⇏abi`); `#[no_mangle]` shells in `crates/emit/src/abi/function.rs` (+ the `struct_gep` / `ret` shells added to `abi/primitive.rs` / `abi/control_flow.rs`). The shells are pure translation (resolve ids, NULL-check handles, map the `c_int` linkage → `core` `LLVMLinkage`, `ffi_slice` the call args, intern the result), so `scripts/check-emit-abi-no-ir.sh` stays green; the api.h header lint stays green (no `llvm::*` / `void *`). All five are non-semantic and reused across the 33 C++ `Function::Create` sites.
- **First consumer: the `take` iterator's next-fn.** `take(iter, n)` in `src/codegen_call_iterator.cpp` builds its `__iter_take_next.N` function entirely through CodeGen-side wrappers (`emitCreateFunction` / `emitGetParam` / `emitStructGEP` / `emitCallIndirect` / `emitRet`, plus the existing `emitLoad` / `emitICmpSGT` / `emitConstInt` / `emitSub` / `emitStore` / `createBBInFn` / `emitBranchCond` / `buildNoneValue`) — so its function-body emission carries **zero** `builder_.Create*`. `FnScope` / `fn_` / `pushScope` / `popScope` / `SetInsertPoint` stay C++ (codegen symbol-table state / builder position, not IR). A **pure refactor**: byte-for-byte identical IR, verified by an ASLR-normalized `--emit-llvm-ir` diff over a `take(iter([…]), n)` probe with the next-fn markers (`__iter_take_next` / `src_next_fn` / `src_state` / `remaining` / `has_rem` / `new_rem` / `src_opt`) coverage-gated in the baseline first (the `#2026` discipline).
- **Settle ≠ unlock.** This proves the capability on `take`'s next-fn (Part A) only. The iterator's header-alloc + `setTypeMeta(IteratorElem)` + malloc-stack tracking (`ValueMetadata` crossing) stays C++ — #2100's domain; closure / `FnTypeInfo` crossing (`filter` / `map`) is #2099; the `list`/`set`/`map` dense iterators and the remaining 32 `Function::Create` sites are the follow-on sweep.

### ValueMetadata crossing + switch construction (#2100 — [B] = (ii) boundary move, generic primitives)

The representative `str(List<enum>)` (`src/codegen_tostring.cpp`) needs two capabilities the boundary lacked: the per-element type metadata that drives enum variant-name lowering, and `switch` construction itself. #2100 settles both as **(ii) boundary move with generic primitives** (orthogonal to #2072's style axis; see `codegen-layering-plan.md` for the decision record).

- **Type metadata does NOT cross.** `value_metadata_` is keyed by `llvm::Value*`, which cannot cross the boundary. Rather than a `RyToStringDesc` carrying the element type name, the migrated List-loop element load round-trips the boundary (`intern → ry_emit_load → resolve`); the returned SSA value is still a valid `value_metadata_` key on the CodeGen side, so `propagateElemMeta` re-stamps the enum type and the recursive `valueToString` reaches the variant-name switch — all C++-side. This is the same rule `ry_emit_list_slice` established ("the type-metadata copy stays on the codegen side").
- **Three new generic primitives.** `ry_emit_create_switch` (`LLVMBuildSwitch` — returns the opaque `RySwitchRef`, not interned, the same handle shape as `create_basic_block`'s `RyBasicBlockRef`, because a switch is mutated after creation via `addCase`), `ry_emit_switch_add_case` (`LLVMAddCase`), and `ry_emit_array_gep` (a two-index `{i64 0, idx}` GEP into the `[N x ptr]` enum name-array global, distinct from the single-index `ry_emit_gep` and the field-index `ry_emit_struct_gep`; for constant operands it folds to a ConstantExpr, byte-matching the C++ `builder_.CreateGEP`). Engine methods: `build_switch` / `switch_add_case` in `crates/emit/src/primitive/control_flow.rs`, `build_array_gep` in `primitive/ops.rs` (all core-role `impl EmitCtx`, `core⇏abi`); `#[no_mangle]` shells in `crates/emit/src/abi/control_flow.rs` / `abi/primitive.rs`; CodeGen-side wrappers `createSwitch` / `switchAddCase` / `emitArrayGEP` in `src/codegen.cpp`. The `EnumInfo`-driven case values and name-array index stay C++-side; only the generic ops cross. `scripts/check-emit-abi-no-ir.sh` gains `LLVMAddCase` to its forbidden set (the `switch_add_case` engine method lives in `core`, so the abi shell stays IR-free).
- **Carve-out: the variadic sprint-printf.** The sprint-buffer writes (`emitSprintBegin` / `emitSprintEnd` + the **variadic** `__ry_sprint_printf`) stay C++ — `ry_emit_runtime_call` is non-variadic by contract, and varargs crossing is an orthogonal capability shared by every tostring path, deferred to a follow-on.
- **Settle ≠ unlock.** Single-level flat non-ADT enums only. Deep ADT tostring (`getOrCreateADTToStringFn` via `Function::Create`) is #2098's domain; the non-explicit-value direct-GEP enum branch is a separate sub-capability; Map / Set tostring and the other metadata-driven switch sites are the follow-on sweep. Pure refactor — byte-for-byte identical IR, verified by an ASLR-normalized `--emit-llvm-ir` diff over a `str(List<HttpStatus>)` probe with the switch path (`switch i64` / `vts.enum.merge` / per-variant case BBs) coverage-gated in the baseline first. ### New op migration (#2093 — collection copy-generation: keys / values / take / appended / concat)

### Collection linear-generation / linear-operation ops (#2095 — header-field single-sourcing + re-entrant retain trampoline)

The seven collection ops `emitListRemove` / `emitCollOp_distinct` / `emitCollOp_flatten` / `emitCollOp_items` / list `reverse` (the list branch of `emitStrOp_reverse`) / `enumerate` / `zip` all share the shape "source header/length read → optional malloc → 1–2 inline loops → new collection header set → optional ARC retain". #2095 migrates all seven onto the `crates/emit/` cdylib via seven new boundary entries (`ry_emit_list_remove` / `_distinct` / `_flatten` / `_reverse` / `_map_items` / `_list_enumerate` / `_list_zip`). The List header GEP positions LEN / CAP / DATA and the Map header positions LEN / CAP / KEYS / VALS / BUCKET_COUNT / BUCKETS are centralized as named `pub(crate) const` constants in `crates/emit/src/context.rs` and consumed by `header_fields` plus every migrated site; `tests/test_header_layout.cpp`'s `NamedFieldIndicesMatchCanonical` test asserts each constant indexes a field of the expected semantic type against C++'s canonical `listHeaderTy_` / `mapHeaderTy_`, so a future constant-value drift fails the build before any GEP-against-the-wrong-field defect can ship. Pure refactor — ASLR-normalized `--emit-llvm-ir` diff is empty over per-op probes; `ry_tests` (2659) and `ry test -p` (204 files) stay green.

- **Caller-side preserve order.** Each migrated entry preserves the C++ baseline's instruction order by having C++ pre-load whatever has to land before the boundary call: list / map header loads (`loadListHeader` / `loadMapHeader` — header-load capability stays C++-side, the #2093 / #2101 carve-out), the `emitArcAllocCollectionHeader` ARC header allocation (which also registers the new pointer in `arc_owned_values_`, a CodeGen-side set the boundary cannot reach), and any pre-loop computations whose IR position is fixed (zip's `zip_minlen` Select, reverse's `rev_dsize` Mul + `rev_data` malloc). The boundary then owns only the loop body + the named-StructGEP stores at `LIST_FIELD_LEN/CAP/DATA`. `flatten` is the exception: its inline ARC alloc lives inside the boundary because the loop computes `flat_total` before the alloc, and the boundary mirrors the C++ `arc_total` / `arc_hdr` / `arc_strong_ptr` / `arc_weak_ptr` / `arc_data` shape byte-for-byte (the C++-side `arcHeaderTy_` named struct crosses as a `RyTypeRef` parameter so the GEPs reference `%ArcHeader` rather than the anonymous `{i64,i64}` produced by `core::arc_header_type`).
- **Re-entrant retain callback via stack-struct trampoline.** `enumerate` / `zip` / `items` invoke `emitTupleComponentRetain` once per loop iteration to retain the tuple components. `emitTupleComponentRetain` re-enters the emitter recursively (nested tuple components), so it triggers the #2069 rule: the engine method MUST be a `core` free function (not `&mut self`) with `&mut dyn FnMut(ValueRef)` closure parameters, and the abi shell uses the two-step `let val_id = with_ctx(...); retain_fn(val_id, user_ctx);` pattern so the C callback runs strictly OUTSIDE any `&mut EmitCtx` borrow. The C++ callsite builds a tiny stack struct `{ CodeGen *cg; std::string sigName; }` and passes a capture-less lambda + the struct pointer as `user_ctx` — mirroring `ResultBranchTrampolineCtx` introduced in #2069 (the original C++ shim file `src/codegen_emission_result_branch.cpp` was removed in #2229; the trampoline pattern now lives at the caller site in `codegen_*.cpp` calling `ry_emit_result_branch` directly, backed by `crates/emit/src/composite/result.rs` + `crates/emit/src/abi/result.rs`). The struct's lifetime is the synchronous boundary call, so it stays alive without `thread_local`. The new typedef `RyRetainFn` (`void (*)(RyValueId val_id, void *user_ctx)`) lives in `include/ry/llvm_emit/api.h`; its Rust counterpart `pub type RyRetainFn = Option<unsafe extern "C" fn(...)>` is in `crates/emit/src/abi.rs`. NULL = no retain needed (primitive element path).
- **`reverse`'s post-loop retain stays C++-side.** The list branch of `emitStrOp_reverse` ends with a dispatch (tuple-element vs. ARC-managed-element vs. no-op) that calls `emitTupleElemRetainLoop` or `emitCowRetainArcElements` — both operate on `ValueMetadata` and emit their own retain loops downstream. Rather than crossing those decisions twice, the boundary returns control to C++ after the reverse copy + named-StructGEP stores, and C++ runs the dispatch as it did before — the simpler split (no callback) because the retain is a single post-loop call, not a per-iteration one.
- **Carve-outs.** The string branch of `emitStrOp_reverse` (`__ry_utf8_reverse`) is intentionally **not** migrated — it has no header field writes and is a thin runtime-call wrapper. `loadMapHeader`'s map-header field-index GEPs (KEYS/VALS field 2/3) inside the boundary are part of the same single-source mechanism as the List header constants. `arc_owned_values_` bookkeeping stays on the C++ side (a downstream codegen decision set, not an IR-emission state) — the flatten boundary returns the new collection header pointer and C++ explicitly inserts it to mirror what `emitArcGetDataPtr` did. The same split applies to `emitArcAlloc` / `emitArcAllocCollectionHeader`: their IR emission is already covered by existing primitives (`malloc` + `ry_emit_arc_counter_delta` + struct-GEP + store), but the `arc_owned_values_.insert(dataPtr)` side effect is consumed by C++-side ARC decision logic (`tryRetainArcSource` / `emitArcRelease` / `emitCowCheckSlot`) and cannot cross — the documented caller obligation, consistent with the same set's treatment in #1968 and #1970 (confirmed by the #2191 audit, area [5]).
- **Coverage gate per op.** Non-constant-operand probes (function args carrying `List<T>` / `Map<K, V>`) exercise every element-type cell of the dispatch — int / float / str for `remove` / `distinct` (the strcmp path), int / float / str for `flatten` (inner-list GEP via LIST_FIELD_LEN/DATA), primitive + str + nested-list for `enumerate` / `zip` / `items` / `reverse` — with each op's SSA markers (`lrem.*` / `dist.*` / `flat.*` / `lrev.*` / `items_*` / `enum_*` / `zip_*`) grep-confirmed in the baseline IR before the diff. Boundary input-validation guards (`ctx`-NULL, NULL-resolving ids, NULL type handles, NULL retain callback) are in `tests/test_emit_abi_guards.cpp` for each new entry. FileCheck fixtures (`tests/filecheck/list_remove_parity.ry` / `list_distinct_parity.ry` / `list_flatten_parity.ry` / `list_enumerate_parity.ry`) pin the BB scaffold + key markers as durable coverage probes.

### Checked FP→int conversion (#2097 — coarse op following the bounds-check pilot pattern)

`emitCheckedFPToInt` (`src/codegen_call_user.cpp`) is the shared helper that every `int(<float>)` / `<float> as <int>` cast in Ry emits — the 9 int-target cases in `src/codegen_expr_cast.cpp` plus the int branch of `coerceToLowLevelType` (10 callsites total) all delegate to it. The op shape is "BB scaffold + range check + runtime-error exit + happy-path cast" — the same shape as `ry_emit_bounds_check` (#1996) — so #2097 settles it as a **coarse op**, not a new generic-primitive batch: one boundary entry (`ry_emit_checked_fp_to_int`) emits the FPExt(f32→f64) + unordered FCmpULT/UGE range check + CondBr to fresh failBB / okBB + runtime-error exit + FPToSI / FPToUI on the original value. The 10 callsites are *implicitly migrated* the moment the C++ wrapper switches to the boundary call.

- **One new coarse op, zero new generic primitives.** `ry_emit_checked_fp_to_int(val_id, target_width, is_signed, bb_prefix, msg, global_name)` mirrors `ry_emit_bounds_check`'s shape. The C++ wrapper computes the message string (typeName + siteLabel), the `fptoi_err_counter_++`-stamped global-name hint, the bit width, and the signedness; the engine emits everything from FPExt through FPToSI / FPToUI. Carve-out: the integer-only / float-only / `f64 → f32` carve-out cases (~40 in `codegen_expr_cast.cpp`) are intentionally C++ — they are straight `sext` / `zext` / `trunc` / `sitofp` / `fptrunc` 1:1s with no checked path.
- **`emitRuntimeError` shape ≠ `bounds_error` shape (the trap).** `cachedGlobalString` (`src/codegen.cpp::buildArcGlobal`) builds a StringHeader-prefixed `{ i64 ARC_IMMORTAL, i64 0, i64 byte_len, [N+1 x i8] data }` global with a `.arc` suffix and passes a ConstantExpr in-bounds GEP `[0, 3, 0]` into the data payload to fprintf; `bounds_error` (`crates/emit/src/composite/bounds.rs`) instead builds a plain `[N+1 x i8]` global via `get_or_create_msg_global`. The two also order stderr/stdout loads differently (C++ `emitRuntimeError` interleaves stdout's load AFTER the fprintf call; Rust `bounds_error` loads stderr/stdout adjacently BEFORE fprintf). Reusing `bounds_error` for an `emitRuntimeError`-shaped exit would silently break bit-exact parity on both axes. #2097 therefore introduces a dedicated `get_or_create_arc_msg_global` (`crates/emit/src/composite/arc.rs`) mirroring `buildArcGlobal` byte-for-byte, plus a `composite/cast.rs`-local `runtime_error_with_value_arg` reproducing the C++ instruction order. Dedup caches stay independent: `bounds_msg_cache` for plain `[N x i8]` globals, `arc_msg_cache` for str-handle structs; both key on message bytes. The full lesson is captured in `.claude/rules/codegen-llvm-ir-conventions.md` so any future `emitRuntimeError`-flavored migration (e.g. `emitIntZeroDivGuard` / `emitIntDivOverflowGuard`) does not re-discover it.
- **Variadic fprintf carve-out.** The fprintf call uses an inline variadic FunctionType (`isVarArg=1`) built with `LLVMBuildCall2`, NOT routed through `ry_emit_runtime_call` (non-variadic — the #2100 carve-out). Same shape as `bounds_error`'s fprintf.
- **Settle ≠ unlock.** #2097 proves the pattern on `emitCheckedFPToInt` only. The sibling `emitRuntimeError` callers in `src/codegen_call_user.cpp` (`emitIntZeroDivGuard` / `emitIntDivOverflowGuard`) and the `?` operator / saturating-arithmetic exits stay C++-side, available to the follow-on sweep under the same discipline. The boundary input-validation guards (`ctx`-NULL, NULL-resolving val, `target_width <= 0`) are in `tests/test_emit_abi_guards.cpp`; coverage gating uses the signed / unsigned / f32-source classes pinned in `tests/filecheck/cast_fp_to_int.ry`.

### stdlib op follow-on sweep (#2192 — primitive sweep, 8 ops)

- **`CreateNeg` → `emitSub(zero, x, …)` (no new primitive).** `range()`'s `CreateNeg(step, "neg_step")` is definitionally `CreateSub(getNullValue, step)` per `llvm::BinaryOperator::CreateNeg`, so the textual IR `%neg_step = sub i64 0, %step` is byte-identical whether emitted via `CreateNeg` or `CreateSub(zero, x)`. The element-size constant (`dl.getTypeAllocSize(ptrTy_)` / `dl.getTypeAllocSize(i64Ty_)`) is materialized via `emitConstInt(i64Ty_, elemSize)` before the `emitMul`.
- **Constant operands materialize via `emitConstInt` / `emitConstNull`.** Every integer literal (zero, one, elemSize) and null pointer used as an operand to a boundary arithmetic / compare / select op must be a `RyValueId`-resolvable `llvm::Value*`; inline `ConstantInt::get` / `ConstantPointerNull::get` cannot be passed directly to `emitAdd` / `emitICmpEQ` / `emitSelect`. `range()`'s `zero` / `one` and `env()`'s null-pointer-comparison constant are all routed through the const-int / const-null helpers.

  - `emitResultBranch`, `wrapPtrAsOption`, `buildOkValue` / `buildErrValue`, `buildErrorFromRuntime` (`input`) — already boundary-migrated composite ops; the migration only changes the `CreateAlloca` / `CreateStore` / `CreateCall` / `CreateICmpSLT` / `CreateLoad` calls around them.

  - `arc_str_owned_values_.insert(r)` (`split` / `replace` / `substring` return values) — downstream ARC decision set, IR-free; must stay even after the `CreateCall` migrates to `emitRuntimeCallDirect`.
  - **Regex sub-paths of `split` / `replace` stay C++-side** — they end in `emitRuntimeError("error: %s\n", …, {msgPtr})` which routes through the variadic-fprintf `__ry_sprint_printf` carve-out (api.h L88, #2097 / #2100 discipline). Promoting these aborts to `Result<…, Error>` would require an API-shape change and is intentionally out of scope (boundary doc "Settle ≠ unlock" stance).
- **Pure refactor.** ASLR-normalized `--emit-llvm-ir` diff is empty over the eight per-op parity probes in `tests/filecheck/{args,range,input,env,isEmpty,str_split,str_replace,str_substring}_parity.ry`; per-op SSA markers (`argc64` for args; `step_pos` / `neg_step` / `count_pos_c` / `count_neg_c` / `range_count` / `range_data_size` / `range_offset` / `range_val` for range; `inp_iserr` / `inp_line` + both `__ry_io_input_prompt` (1-arg overload) and `__ry_io_read_line` (0-arg overload) call sites for input; `env_result` / `env_null` / `env_val` for env; `ie_len` / `isEmpty` for isEmpty list branch + `str_bytelen` for str branch; `split_empty_delim` / `split_chars` / `split_normal` / `split_result` for split; `replace_result` for replace; `substr_charlen` / `substr_cstart` / `substr_cend2` / `substring` for substring slow path + a separate `doSubstrFast` probe with literal `0 / 5` indices for the fast path's `__ry_utf8_substring(s, byteLen, 0, 5)` call) grep-confirmed in the baseline before diffing. Two distinct `emitRuntimeCallDirect` call sites with different arg lists per op (input's 1-arg vs 0-arg overload, substr's slow `clampedEnd` vs fast `end` 4th arg) each get their own probe so a per-site typo would not pass an empty diff with a single-cell probe. FileCheck fixtures pin the per-branch markers as durable coverage. `ry_tests` (2795) and `ry test -p` (207 spec files) stay green; `scripts/check-emit-abi-no-ir.sh` and `scripts/check-llvm-emit-abi-header.sh` stay clean.

### Composite / primitive sub-layer split (#2109)

After #2069 closed the `abi → core` story, the `core` umbrella still held three different kinds of responsibility: layer-neutral state and pure-data tables (`EmitCtx`, handle wrappers, enums, layout constants, `header_fields`), Ry-semantic combined emission (ARC counter delta, list-header load, inline ARC alloc, the StringHeader-prefixed `.arc` msg global), and LLVM-1:1 primitive emission (libc emitters, type constructors, name builders, `get_or_create_msg_global`). The boundary between the last two was a convention, not a structural invariant.

Issue #2109 captures that boundary as a directory split. `crates/emit/src/core.rs` is dissolved; the `core` umbrella becomes three sub-modules with their own CI gates:

- `context.rs` — `EmitCtx`, handle wrappers, enum selectors, layout constants, `HdrField` / `HeaderKind` / `header_fields`. IR-free (only `llvm_sys::prelude` for handle type aliases); the IR-gen lint script `scripts/check-emit-abi-no-ir.sh` covers it implicitly.
- `primitive/**.rs` — LLVM 1:1 emission with no Ry layout knowledge: scalar / memory ops, type constructors, name builders, module-symbol lookup, plain string globals, libc emitters, inline runtime-error, function creation, indirect call, intrinsic call, control flow, generic runtime calls.
- `composite/**.rs` — Ry-semantic combined emission: ARC, bounds, cast, collection, cow, any, option, result, reduce, and shared header struct construction.

`abi → composite → primitive → context` is the dependency direction; `abi → primitive` and `abi → context` are permitted as transitional shortcuts (the abi shell sometimes calls primitive entries directly). `context` sits below every sibling layer and imports from none of them. Two new lint gates back the layering:

| Gate | Enforces |
|---|---|
| `scripts/check-emit-composite-no-primitive.sh` | `primitive ⇏ composite` and `context ⇏ {abi, primitive, composite}` by grepping forbidden `use crate::...` paths. |
| `scripts/check-emit-llvm-ir-gen-concentration.sh` | composite files that call `llvm_sys::core` / `LLVMBuild*` directly are restricted to an explicit ALLOWLIST. The verbatim-move #2109 freezes the current ten files; new composite files must express their op via primitive methods (e.g. `self.build_load(...)`). |

Known **blind spot** of the first gate: both `composite` and `primitive` `impl` methods on the same `EmitCtx`, so `self.composite_method()` dispatch is invisible to import-path inspection. The future physical crate split (#2023) turns this into a Cargo-enforced constraint; until then, the gate covers the practical risk (accidental `use crate::composite::*` paths added during refactors).

The `crates/emit/src/abi/` layer is **unchanged** by #2109 — `abi.rs` and `abi/**.rs` only have their import paths rewritten from `crate::core::*` to `crate::context::*` (and from `crate::{any,cow,result}::*` to `crate::composite::{any,cow,result}::*` where applicable). The `check-emit-abi-no-ir.sh` regression bar continues to hold.

Composite files that still depend on `llvm_sys::core` are listed in the layering plan's transitional carve-out table (see [Codegen Layering Plan](codegen-layering-plan.md) §"Composite and primitive emission sub-layers (#2109)"). Each is a migration target for a follow-on issue; the gate fails closed for any new composite addition outside the allowlist.

## Distribution packaging (#2005)

The mandatory shared `libLLVM` (above) made the release binary non-self-contained: `release.yml` packages `build/ry` directly, so the shipped binary carried a build-machine-absolute reference to `libLLVM.dylib` / `libLLVM.so`. The first tag push after the #1993 cutover would therefore have published a binary that fails to start wherever that LLVM is absent (`dyld: Library not loaded` on macOS / `libLLVM.so: not found` on Linux). #2005 restores self-containment without changing the tarball-based distribution format:

- **Bundling + rpath rewrite.** `scripts/bundle-dist.sh` copies `libLLVM` (and on macOS its only non-system chain dep, `libzstd`) into `lib/` next to `ry`, alongside the `libemit` cdylib and the `libry_*` stdlib native libs. It rewrites install names / rpaths so the references are relocatable: on macOS via `install_name_tool` (absolute Mach-O install names → `@rpath` / `@loader_path`, then an ad-hoc `codesign` re-sign because the rewrite invalidates the signature); on Linux via CMake `BUILD_RPATH`/`INSTALL_RPATH` (`$ORIGIN`-relative, since the `ry-ci-glibc-old` image has no `patchelf` and the no-apt rule forbids adding one). `scripts/verify-bundle.sh` asserts the result (no build-absolute LLVM path survives) before packaging, and CI clean-room jobs hide the system libLLVM to prove `ry` starts from the bundle alone.
- **Two rpaths on `ry`.** `@loader_path/lib` / `$ORIGIN/lib` resolves the tarball-unpacked-in-place layout (`./ry` next to `./lib`); `@loader_path/../../.ry/lib` / `$ORIGIN/../../.ry/lib` resolves the installed layout (`~/.local/bin/ry` → `~/.ry/lib`, a fixed offset because both sit directly under `$HOME`). `install.sh` and `ry self-update` install the bundled libraries into `~/.ry/lib` alongside `libry_*`.
- **openssl is out of scope.** `ry_lib` links `OpenSSL::SSL/Crypto`, so `ry` also depends on `libssl`/`libcrypto` — but it did so identically before the cutover (v0.0.25 parity), the issue's AC targets only libLLVM's chain, and bundling crypto would block OS security updates. Clean-room tests therefore hide only libLLVM, leaving openssl resolvable.
- **License.** `LICENSE-LLVM.txt` (Apache-2.0 with LLVM exceptions) ships in every tarball per redistribution requirements; tarballs grow by roughly the size of libLLVM (~100 MB class).
