# LLVM IR Emission Boundary

This document identifies the candidate shared-library boundary inside the codegen layer. It is the design reference for issue #1949 (extract the LLVM IR emission layer as a separate shared library) and #1950 (reimplement that shared library in Rust). Issue #1820 (v0.0.26 stage 2) prepares the surface by extracting layer-independent helpers and documenting the access patterns described here.

## What this boundary is

The "LLVM IR emission layer" is the subset of `CodeGen` that owns LLVM types and the `IRBuilder<>`. Today this is intertwined with type registries, ARC bookkeeping, stdlib dispatch, and module-namespace state inside a single monolithic class (`include/ry/codegen.hpp`). The goal of #1949 is to extract the LLVM-touching surface into its own `.so`/`.dylib` exposing a stable `extern "C"` ABI, so that #1950 can reimplement it in Rust without rewriting the rest of the compiler.

## Constraint: LLVM types must not cross the boundary

In the final design, the following LLVM-owned types **must not appear** in the shared-library ABI:

- `llvm::Value*` / `llvm::Constant*` / any `llvm::*` derivative
- `llvm::Module&` and `llvm::LLVMContext&`
- `llvm::IRBuilder<>` and its template instantiations
- `llvm::Function*` / `llvm::BasicBlock*` / `llvm::Type*`

These types are LLVM-version-coupled and cannot be reasonably exposed through a stable ABI. The boundary instead exchanges opaque handles (or value IDs) that the LLVM side resolves internally. Concretely: anywhere the current C++ code passes an `llvm::Value*` between a custom stdlib emitter and a `CodeGen` helper, that exchange must be redesigned to use a plain integer handle, a small POD struct, or a callback that lives entirely on the LLVM side.

## Access categories observed in custom stdlib emitters

The 16 `src/codegen_call_*.cpp` dispatcher files are the primary consumers of `CodeGen` internals. Their access patterns fall into five categories:

1. **LLVM context handles**: `builder_`, `mod_`, `ctx_`, `fn_`. These are the raw LLVM state — they cannot cross the boundary as-is. Custom emitters that take a `CodeGen&` and read these directly must be reshaped to receive an `EmitterContext` wrapper instead.
2. **Primitive type accessors**: `i64Ty_`, `ptrTy_`, `anyTy_`, `errorTy_`, `i8Ty_`, `f64Ty_`, etc. These are `llvm::Type*` and share the same constraint as category 1 — wrap behind opaque type-id handles in the boundary.
3. **Runtime wrapper helpers**: `getRuntimeFn`, `wrapPtrAsResult`, `wrapStatusAsResult`, `emitResultBranch`, `buildErrorFromRuntime`. **This category is the most narrowed existing boundary candidate** — all five helpers are already centralized in `src/codegen_call_dispatch.cpp`, and they encapsulate the canonical "call a runtime symbol, wrap the result as `Result<T, Error>`" pattern. They are the natural starting point for the shared-library extraction in #1949: a thin wrapper layer that exchanges opaque value handles and dispatches to the LLVM-owning side.
4. **Metadata API**: `propagateTypeMeta`, `setTypeMeta`, `emitExpr`. These mutate or query the `ValueMetadata` keyed by `llvm::Value*`. Crossing the boundary requires the metadata store to live on the LLVM side and be addressed through the same opaque handles as category 1.
5. **Predicate and error helpers**: `isStringValue`, `isFile`, `codegenError`, `requireArgs`, `propagateTypeMeta`. These mix value inspection (LLVM-coupled) with diagnostic reporting (layer-independent). Diagnostics can move to the caller side; value-inspection predicates must stay LLVM-side.

## Narrowing direction (not implemented in #1820)

The concrete narrowing — replacing direct `CodeGen&` parameters in custom emitters with a smaller `EmitterContext` interface — is **not** in scope for issue #1820. The acceptance criterion is satisfied here by documentation: emitter access is currently broad, the narrowing plan is to introduce a context struct exposing only the surface above, and the implementation is left to a follow-up issue gated on #1949's ABI design.

The recommended sequence is:

1. (this issue, #1820) Document the surface; extract layer-independent string/type-name helpers out of `CodeGen` so they no longer cross the boundary.
2. (#1949) Define the shared-library ABI starting from category 3 (the most narrowed surface today) and progressively wrap the other categories. Extract the LLVM-owning side into `libry_codegen.so`/`.dylib`.
3. (#1950) Reimplement `libry_codegen` in Rust behind the same ABI.

## Stage 2-A landed (#1949 scaffolding)

The first #1949 PR is intentionally scaffolding-only — it stands up the shared-library boundary without migrating every category-3 helper:

- **Shared library target**: `ry_llvm_emit` is built as `add_library(SHARED ...)` in the root `CMakeLists.txt`. It produces `lib/libry_llvm_emit.{dylib,so}`; LLVM is not linked into it (its symbols resolve from the main process via `-undefined dynamic_lookup` on macOS and `-rdynamic` on Linux, mirroring the `add_ry_native_lib()` pattern). Unlike the JIT-loaded stdlib native libs the `ry` / `ry_tests` executables and the `add_ry_fuzz_target` harnesses link it explicitly because `ry_lib`'s shim layer references its symbols at compile time.
- **ABI header**: `include/ry/llvm_emit/api.h`. Defines `RyValueId` / `RyFuncId` / `RyTypeId` as `uint32_t` opaque handles, `RyEmitCtx` as an opaque struct, and a `RyEmitCallbacks` slot for the helpers that have not crossed the ABI yet. The header is the LLVM-type-exclusion contract: no `llvm::Value*` / `llvm::Module&` / `llvm::IRBuilder<>` / `llvm::Function*` / `llvm::BasicBlock*` / `llvm::Type*` appears in any public signature. Module / IRBuilder / context / function pointers are passed as transitional `void*` until categories 1 and 2 cross the ABI in a successor PR.
- **Helpers crossing the ABI in 2-A**: three entry points — two of the five category-3 helpers plus the BoundsCheck pilot.
  - `ry_emit_get_runtime_fn` — backs `CodeGen::getRuntimeFn` (category 3).
  - `ry_emit_build_error_from_runtime` — backs `CodeGen::buildErrorFromRuntime` (category 3). Takes `errorTy_` as a transitional `void*` parameter to preserve the named-`StructType` pointer identity that `isResultType` and friends rely on.
  - `ry_emit_bounds_check` — backs the BoundsCheck pilot from #1961. Not a category-3 helper; it is the first lowered-op surface that crosses the ABI. Calls into `CodeGen::emitNegativeIndexWrap` and `CodeGen::emitBoundsError` through the `RyEmitCallbacks` slot (this is replaced in Stage 2-B by proper ABI functions).
- **Category-3 helpers deferred** (still `CodeGen` methods, untouched call sites): `wrapPtrAsResult`, `wrapStatusAsResult`, and `emitResultBranch` — the remaining three of five. Their bodies pull in `getResultType` (a pointer-identity-sensitive `result_types_` cache) and `buildOkValue` / `buildErrValue` (which call `propagateMeta` + `tryRetainArcSource`). Migrating them via callbacks would widen the ABI surface beyond the scaffolding scope; they migrate together with the `ResultBranch` lowered op in Stage 2-B (#1964).
- **BoundsCheck shape**: the lowered op type in `include/ry/codegen/lowered_bounds_check.hpp` still holds `llvm::Value*` members, per the two-stage boundary policy — the lowering↔emission split is an internal C++ boundary where LLVM types are allowed; only the ABI surface is opaque. `src/codegen_emission_bounds_check.cpp` interns the op's `idx` / `len` into handles immediately before each ABI call.
- **EmitCtx lifecycle**: one ctx is created in `CodeGen::CodeGen` and destroyed in `CodeGen::~CodeGen`. `ry_emit_ctx_set_function` is called from `emitBoundsCheck` to sync the current `llvm::Function*` before the ABI creates new basic blocks. The handle table is a `std::vector<llvm::Value*>` indexed by `RyValueId`; handle 0 is the sentinel for "invalid / null".

## Stage 2-B landed (#1964 — category-3 migration complete)

The second #1949-track PR finishes the category-3 helper migration and removes the transitional `RyEmitCallbacks` slot:

- **Three new ABI entry points**: `ry_emit_result_branch`, `ry_emit_negative_index_wrap`, `ry_emit_bounds_error` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. All three are self-contained: `ry_emit_bounds_error` resolves its own `stdout` / `stderr` / `_Exit` / `fprintf` callees through `getOrInsertGlobal` / `getOrInsertFunction` on the LLVM `Module*`, and deduplicates format-string globals inside `RyEmitCtx::bounds_msg_cache` rather than calling back into CodeGen's `cachedGlobalString`.
- **ResultBranch lowered op**: `include/ry/codegen/lowered_result_branch.hpp` mirrors the BoundsCheck shape (`lowered::ResultBranchOp` struct + `lowering::lowerResultBranch` + `emission::emitResultBranch`). The lowering side has no constant-fold path today (ok/err builders are runtime lambdas), but the structure is kept symmetric so a future fold can be added without reshuffling callers. The emission side translates `llvm::function_ref<>` closures into the C-function-pointer + `user_ctx` ABI shape via a small trampoline in `src/codegen_emission_result_branch.cpp`.
- **`emitResultBranch` shim**: `CodeGen::emitResultBranch` survives as a thin shim that calls `codegen::lowering::lowerResultBranch` + `codegen::emission::emitResultBranch`. This keeps the ~14 existing `function_ref`-style call sites (including the three-level nest in `emitHttpRequest`, the `emitResultBranchWithMeta` in `codegen_call_io.cpp`, and Option/Result-monad helpers) working without per-caller edits. `wrapPtrAsResult` / `wrapStatusAsResult` likewise stay on the CodeGen side as thin convenience wrappers over `emitResultBranch`.
- **`getResultType` stays in CodeGen**: the `result_types_` cache and its `reverse_result_types_` reverse map are consumed by ARC release (`codegen_arc.cpp`) and Any wrapping (`codegen_any.cpp`) for type introspection. Migrating those reverse-direction consumers requires a category-2 (primitive type accessor) migration that is out of Stage 2-B scope. `resTy` crosses the ABI as `void*`, mirroring `errorTy_` in `ry_emit_build_error_from_runtime`.
- **`RyEmitCallbacks` removed**: `ry_emit_bounds_check` now invokes `ry_emit_negative_index_wrap` and `ry_emit_bounds_error` directly inside the shared library. The `RyEmitCallbacks` typedef, `ry_emit_ctx_set_callbacks`, and the corresponding registration in `CodeGen::CodeGen()` are all gone. The handle table inside `RyEmitCtx` is unchanged.

After Stage 2-B, the only remaining transitional shapes are the `void*` parameters for module / builder / context / function / `StructType*` — those become typed opaque handles when categories 1 and 2 cross the ABI in Stage 2-C.

Stage 2-C will: (1) migrate the remaining lowered IR ops (`RuntimeCall`, `AnyWrap` / `Unwrap`, `CollectionMutate`, `ArcRetain` / `Release`, `CowEnsureUnique`, `ControlFlow`), (2) start crossing category 1 / 2 so the transitional `void*` parameters can become typed opaque handles. The first 2-C step (#1967) migrated `OptionWrap` via two new ABI entry points (`ry_emit_option_wrap_some` / `ry_emit_option_wrap_none`); unlike BoundsCheck / ResultBranch, OptionWrap creates no basic blocks and therefore does not require `ry_emit_ctx_set_function`. The Ry-semantic side effects of the `Some` arm (`propagateMeta` + `tryRetainArcSource`, #999) stay on the CodeGen-side shim so the emission TU remains a pure `intern → ABI → resolve` transit. `getOptionType`'s `StructType` cache stays in CodeGen for the same reason as `getResultType` (`reverse_option_types_` is consumed by ARC release and Any wrapping); `optTy` crosses the ABI as `void*`. The codegen-layering graduation document remains unwritten until the remaining 2-C ops migrate and the boundary is observable end-to-end.

## Stage 2-C in progress (#1968 — ARC retain/release migrated; #1969 — RuntimeCall consolidated; #1970 — CowEnsureUnique migrated)

The first Stage 2-C op migration moves ARC retain/release across the ABI. ARC ops are the highest-fanout lowered op surface (`emitArcRetain` has 30+ call sites and `emitArcRelease` has 25+, reached indirectly through `@parallel for`, lambda capture, CoW clone, record/tuple field retain, and tagged-union release paths), so migrating them first establishes the ABI shape that the remaining Stage 2-C ops (`RuntimeCall`, `AnyWrap`, `CollectionMutate`, `CowEnsureUnique`, etc.) will reuse:

- **Two new ABI entry points**: `ry_emit_arc_retain` and `ry_emit_arc_release` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. Both are self-contained: the implementation rebuilds the anonymous `{i64 strong_count, i64 weak_count}` ARC header struct locally (no `void *arc_header_ty_ptr` parameter needs to cross the ABI because opaque pointers make the offset-0 GEP version-independent), resolves `__ry_gc_track` / `__ry_gc_untrack` / `free` callees through `getOrInsertFunction` on the `Module*`, and emits `__ry_arc_counter_address`-keyed `atomicrmw add` for the live-count balance counter — all without calling back into `CodeGen`.
- **Atomic flag crosses the ABI**: `ry_emit_arc_retain` / `ry_emit_arc_release` take an `int atomic` parameter (`RyArcAtomic` enum: `RY_ARC_NONATOMIC = 0`, `RY_ARC_ATOMIC = 1`). The `@parallel for` SeqCst contract (`parallel_for_depth_ > 0` → `atomicrmw SeqCst`) is preserved because the caller-side `isArcAtomic()` decision is made before the ABI call and propagated as a primitive.
- **Destructor crosses as a C function pointer**: `ry_emit_arc_release` takes `void *destructor_callee` rather than `llvm::FunctionCallee`. The lowering layer (`src/codegen_lowering_arc.cpp`) extracts `Value*` via `FunctionCallee::getCallee()` so the LLVM-typed `(FunctionType*, Value*)` pair does not need to cross the ABI; the emission side rebuilds the `void(*)(void*)` `FunctionType` locally. `gcVisitFn` likewise crosses as `void *gc_visit_fn` (nullable — null suppresses the `arc.gc_track` BB entirely).
- **ArcRetain / ArcRelease lowered ops**: `include/ry/codegen/lowered_arc.hpp` mirrors the BoundsCheck / ResultBranch shape (`lowered::ArcRetainOp` + `lowered::ArcReleaseOp` structs, `lowering::lowerArcRetain` / `lowerArcRelease` passthrough lowering, `emission::emitArcRetain` / `emitArcRelease` ABI dispatch). The lowering layer has no constant-fold path (ARC ops are always emitted at runtime), but the symmetric structure is kept so a future "skip retain when ref is already strong-immortal at compile time" fold can be added without reshuffling callers.
- **`CodeGen::emitArcRetain` / `emitArcRelease` shims**: both survive as thin shims that call `codegen::lowering::lowerArc*` + `codegen::emission::emitArc*`. The 55+ existing call sites (record field retain, tuple element CoW retain, `@parallel for` thunk teardown, lambda capture release, weak upgrade fast path, ARC tagged-union release, etc.) are not touched. `used_native_libraries_.insert("gc")` migrates from inline in `emitArcRelease` to once in `codegen_emission_arc.cpp` — the runtime requires `libry_gc` whenever `__ry_gc_track` / `__ry_gc_untrack` appear, and that decision is now driven by the emission layer.
- **`arc_owned_values_` side-effect intentionally not mirrored**: pre-migration `emitArcRelease` called `emitArcGetDataPtr` to compute the destructor argument, which had the side effect of inserting the resulting `Value*` into `arc_owned_values_`. The dataPtr is consumed only by the destructor call on the next IR line and is dead thereafter, so the side effect was benign at the release site. The ABI version uses a plain `GEP(i8, headerPtr, ARC_HEADER_SIZE)` with no side-table registration — verified semantically equivalent by the existing destructor-touching spec tests (List / Map / Set with str elements, `Result<List<int>, str>` Err binding, `@parallel for` worker ARC retain/release loops).
- **`arcHeaderTy_` named → anonymous**: pre-migration codegen used a named `%ArcHeader = type { i64, i64 }` struct. The ABI version creates an anonymous `StructType::get(*ctx, {i64, i64})` per call. Under opaque pointers all GEPs degenerate to `getelementptr i8, ptr ..., i64 N`, so the named-vs-anonymous difference is invisible in the emitted IR except for the absence of the `%ArcHeader = type {...}` declaration line. FileCheck CHECK patterns reference only BB labels (`arc.retain`, `arc.retain.done`, `arc.release.body`, `arc.release`, `arc.free`, `arc.skip_free`, `arc.gc_track`, `arc.done`) — not the named struct — so the goldens stay bit-exact.

## Stage 2-C in progress (#1969 — RuntimeCall consolidated, ResultBranch preemptive fix)

The third Stage 2-C op migration consolidates every `__ry_*` runtime symbol resolution across the ABI. RuntimeCall is the highest-volume Stage 2-C surface — ~130 `mod_->getOrInsertFunction("__ry_…", fnTy) + builder_.CreateCall(...)` pairs scattered across 17 codegen translation units (largest: `codegen_test.cpp` 46, `codegen_call_io.cpp` 39, `codegen_call_string.cpp` 12) — and its consolidation completes the "no direct `__ry_*` symbol resolution from codegen" invariant Stage 2-C is built around:

- **New ABI entry point**: `ry_emit_runtime_call` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. The implementation rebuilds the `FunctionType` from `ret_ty_ptr` + `arg_ty_ptrs[0..arg_ty_count]` (all transitional `void*` until categories 1/2 cross the ABI), resolves the symbol through `getOrInsertFunction`, and emits a single `CreateCall` against it with the supplied `RyValueId` argument handles. Void-returning calls get an empty SSA name automatically (LLVM forbids naming `void` results); non-void calls honour the `name_hint` parameter.
- **RuntimeCall lowered op**: `include/ry/codegen/lowered_runtime_call.hpp` mirrors the BoundsCheck / ResultBranch / OptionWrap / ARC shape (`lowered::RuntimeCallOp` struct + `lowering::lowerRuntimeCall` passthrough + `emission::emitRuntimeCall` ABI shim). The op type intentionally keeps `ret_ty` / `arg_tys` as bare `llvm::Type *` (category 2 not yet migrated, mirroring `errorTy_` / `resTy` on the ABI side). No constant-fold path: runtime calls are by definition runtime.
- **Bulk call-site migration via `getRuntimeFn`**: `CodeGen::getRuntimeFn` (`src/codegen.cpp:115`) is an ABI-aware thin wrapper over `ry_emit_get_runtime_fn` since Stage 2-A (#1949). The ~130 scattered call sites are uniformly rewritten from `auto fnTy = llvm::FunctionType::get(retTy, argTys, false); auto fn = mod_->getOrInsertFunction("__ry_…", fnTy);` to `auto fn = getRuntimeFn("__ry_…", retTy, {argTys});` — a one-line consolidation that routes every symbol resolution through the ABI without touching the subsequent `builder_.CreateCall(...)` (which stays on the caller side). The `emission::emitRuntimeCall` helper is available for future call-site migrations that want to route a full call (callee resolution + `CreateCall`) through the ABI in one shot.
- **`used_native_libraries_.insert("<mod>")` audit during migration**: where call-site migration touched stdlib dispatchers (`dispatchIO`, etc.), the library insert was verified to be at the dispatcher's top per the `.claude/rules/codegen-stdlib-dispatcher.md` rule (#1856). `dispatchIO` already conformed and was unchanged.
- **Variadic out of scope**: `__ry_print_printf` and `__ry_sprint_printf` in `codegen_call_user.cpp` use `isVarArg=true` and are incompatible with `getRuntimeFn`'s fixed `isVarArg=false`. A variadic-aware ABI variant or extension is deferred to a follow-up; the two sites remain on the legacy `getOrInsertFunction` path.
- **`ry_emit_result_branch` preemptive fix**: while in `src/llvm_emit/impl.cpp` for the RuntimeCall ABI implementation, `ry_emit_result_branch` was updated to derive the parent function for new basic blocks from `ctx->builder->GetInsertBlock()->getParent()` instead of `ctx->function`. This mirrors the `ry_emit_arc_retain` / `ry_emit_arc_release` fix in #1968 and forestalls the same cross-function reference hazard when result-branch helpers are invoked inside destructor / lambda / thunk bodies (where `cg.fn_` tracks the outer function while the IRBuilder has been retargeted to a nested function). Pre-existing call sites had not triggered the hazard because they happened to update `cg.fn_` before invoking, but RuntimeCall migration enlarges the caller surface.

## Stage 2-C in progress (#1970 — CowEnsureUnique migrated)

The fourth Stage 2-C op migration (#1970) moves CoW (Copy-on-Write) uniqueness check across the ABI. CoW is the most structurally complex op migrated so far — a single call expands into atomic strong-count load + ICmp + CondBr + per-kind (List / Map / Set) deep copy with malloc + memcpy of the data buffer + optional per-element retain loop + optional per-key retain loop (Map) + `arc_release` of the old data ptr + slot store + PHI joining the no-clone and clone branches:

- **One new ABI entry point**: `ry_emit_cow_ensure_unique` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. The function takes a single descriptor pointer (`RyCowEnsureUniqueDesc *`) carrying 12 primitive / opaque fields: `data_ptr_id` / `slot_ptr_id` (handles), `kind` (RyCowKind enum: `RY_COW_LIST=0` / `RY_COW_MAP=1` / `RY_COW_SET=2`), `atomic` (RyArcAtomic), `elem_size` / `key_size` / `val_size` (DataLayout-derived primitive sizes), `do_elem_retain` / `elem_is_str` / `do_key_retain` / `key_is_str` flags, and `destructor_callee` as a C `void *`. The single-descriptor shape keeps the C ABI extension surface narrow even though the op has many parameters; future ops with multiple kind-dependent fields are expected to adopt the same shape.
- **CowEnsureUnique lowered op**: `include/ry/codegen/lowered_cow.hpp` mirrors the ArcRetain / Release shape (`lowered::CowEnsureUniqueOp` struct, `lowering::lowerCowEnsureUnique` passthrough lowering, `emission::emitCowEnsureUnique` ABI dispatch with the LLVM `Value*` → `RyValueId` intern step). The lowering layer collects per-kind element / key / value sizes from `mod_->getDataLayout()` and the per-collection element type metadata before the descriptor is filled in by the CodeGen-side shim.
- **`CodeGen::emitCowCheckSlot` shim**: survives as a ~60-line shim that walks `arc_str_managed_vars_` / `arc_field_record_vars_` to set the `do_elem_retain` / `do_key_retain` flags, looks up element / key / value types via `getListElementType` / `getMapKeyType` / `getMapValueType` / `getSetElementType`, computes sizes via `dl.getTypeAllocSize`, resolves `getOrCreateCollectionDestructor`, calls the lower-then-emit pair, and runs `propagateMeta` / `propagateMetaWide` on the result. `CodeGen::emitCowCheck` (which wraps `emitCowCheckSlot` with the `arc_backed_vars_` / `arc_str_managed_vars_` guard) is untouched.
- **`emitCowDeepCopyList` / `emitCowDeepCopyMap` / `emitCowDeepCopySet` removed**: these three CodeGen-private helpers (one per collection kind) had no callers outside `emitCowCheckSlot`, so they dissolve into the ABI implementation's per-kind switch. The per-kind layout is reproduced as anonymous `StructType::get(*ctx, {...})` calls inside the ABI: List `{i64 strong, i64 weak, ptr data}`, Map `{i64 strong, i64 weak, ptr keys, ptr values, i64 cap, ptr present}`, Set `{i64 strong, i64 weak, ptr elems, i64 cap, ptr present}`. These mirror the named struct shapes still created in `src/codegen.cpp`'s collection constructors — a sync comment in `src/llvm_emit/impl.cpp` flags the dependency.
- **`emitCowRetainArcElements` stays in CodeGen**: this helper is called from 8 non-CoW sites (`codegen_expr.cpp`, `codegen_call.cpp`, `codegen_call_collection.cpp`) that retain ARC element buffers without going through the CoW path (`append!`, `insert!`, `concat`, `merge`, `slice`, …). Migrating it would either widen the ABI surface for a per-element retain loop or require those call sites to construct CoW descriptors they do not need. The ABI implementation re-derives the same loop shape internally by calling `ry_emit_arc_retain` per element.
- **Internal ABI cross-calls**: `ry_emit_cow_ensure_unique` invokes `ry_emit_arc_retain` (per element / per key in the retain loops) and `ry_emit_arc_release` (for the old data pointer before the slot store) directly inside the shared library. This is the first ABI helper that composes other ABI helpers — the pattern validates that the ABI surface is composable, not just leaf-level.
- **Atomic strong-count load preserves Acquire pairing**: the "is this the sole owner?" check at the top of the CoW path uses `emitAtomicI64Load(strongCountAddr, AtomicOrdering::Acquire)` when `desc->atomic == RY_ARC_ATOMIC`, preserving the pairing with the `atomicrmw SeqCst` updates emitted by `ry_emit_arc_retain` / `ry_emit_arc_release` so TSan stays clean on the `@parallel for` ARC path.
- **`arc_owned_values_` re-insert dropped**: the pre-migration `emitCowCheckSlot` called `arc_owned_values_.insert(newDataPtr)` after the clone branch. The set is rebuilt on every subsequent `emitArcGetDataPtr` call, and every downstream consumer goes through `emitArcGetDataPtr` before reading the data pointer, so the side-table insert was redundant. The ABI version omits it; the existing destructor-touching spec tests (List / Map / Set with str / nested-collection elements, `Result<List<int>, str>` Err binding, `@parallel for` worker ARC retain/release loops) confirm equivalence.

## Stage 2-C in progress (#1972 — AnyWrap/Unwrap migrated)

The fifth Stage 2-C op migration (#1972) moves the `Any` wrap/unwrap op group across the ABI. `Any` is the most semantically complex op group migrated so far — `wrapInAny` covers six payload kinds (primitive Int/Float/Bool, Str heap header, collection List/Map/Set headers, organic Record via per-type heap box, simple-enum i64 / ADT-enum / Option / Result via per-enum heap box, function-pointer/resource rejection), `unwrapFromAny` covers three target kinds (Standard scalar/Str/collection, F64Promote with int→float coercion, Record with runtime descriptor-chain subtype walk via `__ry_record_is_subtype_desc`), and `tryUnwrapFromAny` adds the typed `Option<…>` / `Record` / `List<T>` / `Set<T>` / `Map<str, V>` sub-emission paths that build `Result<T, Error>` outputs rather than trapping on mismatch:

- **Three new ABI entry points**: `ry_emit_any_wrap`, `ry_emit_any_unwrap`, `ry_emit_any_try_unwrap` — added to `include/ry/llvm_emit/api.h` and implemented in `src/llvm_emit/impl.cpp`. Three top-level entries (rather than a single dispatched op) match the public CodeGen surface and let each ABI helper keep its own `RyAnyWrapKind` (`NonBox=0` / `RecordBox=1` / `EnumBox=2`) / `RyAnyUnwrapKind` (`Standard=0` / `F64Promote=1` / `Record=2`) / `RyAnyTryUnwrapKind` (`Standard=0` / `F64Promote=1`) enum.
- **AnyWrap / AnyUnwrap / AnyTryUnwrap lowered ops**: `include/ry/codegen/lowered_any.hpp` mirrors the CollectionMutate shape (three `lowered::AnyWrapOp` / `AnyUnwrapOp` / `AnyTryUnwrapOp` structs, `lowering::lowerAnyWrap` / `lowerAnyUnwrap` / `lowerAnyTryUnwrap` passthrough lowering, `emission::emitAnyWrap` / `emitAnyUnwrap` / `emitAnyTryUnwrap` ABI dispatch). No constant-fold path: `Any` boxing always materializes a runtime tag + payload pair.
- **`CodeGen::wrapInAny` / `unwrapFromAny` / `tryUnwrapFromAny` shims**: all three survive as thin shims that retain the Ry-semantic side effects on the CodeGen side — type-name resolution (`findEnumLikeTypeNameForBoxing` / `findRecordInfoForType` / `findRecordTypeName` / `buildTypeNameFromMeta`), descriptor lookup (`getOrCreateRecordDescriptor` / `getOrCreateEnumDescriptor`), layout-type construction (`recordBoxLayoutType` / `enumBoxLayoutType`), tag computation (`getAnyTypeTagForValue` / `getAnyTypeTag`), typed-collection registration via `__ry_any_register_typed_coll`, field-wise ARC retain via `emitRecordArcFieldsRetain` / `emitEnumBoxArcFieldsRetain` gated by the `!isa<CallInst> && !isa<InvokeInst>` reassignment guard, generic-substitution rejection, sub-helper dispatch (`unwrapEnumFromAny` / `tryUnwrapRecordFromAny` / `tryUnwrapListFromAny` / `tryUnwrapMapFromAny` / `tryUnwrapOptionFromAny`), and the post-unwrap `emitRecordArcFieldsRetain` on the returned record value.
- **Path 1 narrower design — sub-emission helpers stay CodeGen-private**: the typed `Record` / `List<T>` / `Map<str, V>` / `Option` / simple-enum arms of `tryUnwrapFromAny` depend on per-record reconstruction, `reverse_option_types_`, and per-Map<str, V> rebuilding that the ABI cannot see. Migrating them would require crossing category-1 (`reverse_option_types_` is keyed by `StructType*`) and category-2 (every variant struct type) at the same time, expanding the ABI surface beyond the AnyWrap/Unwrap scope. The shim therefore dispatches to the CodeGen-private helpers before falling back to the ABI for the Standard / F64Promote arms; the ABI helper sees only the leaf "extract scalar / Str / collection header / record struct + chain walk" shapes.
- **ABI helpers derive parent function from the IRBuilder**: per the `.claude/rules/codegen-llvm-ir-conventions.md` rule, `ry_emit_any_wrap` / `ry_emit_any_unwrap` / `ry_emit_any_try_unwrap` derive the parent function via `ctx->builder->GetInsertBlock()->getParent()` instead of `ctx->function`. This keeps the helpers safe under ARC / lambda / thunk / destructor / iterator-next retargeting — the same fix that landed for `ry_emit_arc_retain` / `ry_emit_arc_release` (#1968) and `ry_emit_result_branch` (#1969).
- **Basic-block label preservation**: every label name from the pre-migration codegen is preserved bit-exact across the ABI surface — `any.bool.zext` / `any.rec.tag_ok` / `any.rec.tag_err` / `any.rec.desc_check` / `any.rec.desc_err` / `any.float` / `any.check_int` / `any.int2float` / `any.mismatch` / `any.merge` / `any.match` / `tryany.fp.tmp` / `tryany.fp.data` / `tryany.fp.fval` / `tryany.fp.ival` / `tryany.fp.i2f` / `tryany.fp.is_float` / `tryany.fp.is_int` / `tryany.fp.is_accept` / `tryany.fp.is_err` / `tryany.fp.val` / `res.ok` / `res.err` / `res.merge` / `tryany.tag` / `tryany.tag.eq` / `tryany.is_err` / `tryany.tmp` / `tryany.data` / `tryany.val`. The `load[<TargetType>]: …` error message prefixes used by the typed sub-helper arms are likewise preserved verbatim.
- **Heap-box layout unchanged**: per `.claude/rules/codegen-arc-cow.md`, the Record and Enum heap-box layout (`[ ArcHeader (16B) | descriptor ptr (8B) | payload ]`) is preserved bit-exact — `emitArcGetHeaderFromData` offset −16, `emitStrGetHeaderFromData` offset −24. The descriptor trampolines `__ry_arc_dtor_record_dispatch` / `__ry_arc_dtor_enum_dispatch` and the subtype walker `__ry_record_is_subtype_desc` continue to be invoked through the runtime symbol resolution path (already migrated via `RyRuntimeCallOp` in #1969). `canAnyHoldType` is not widened by this migration — the gating remains as-is.
